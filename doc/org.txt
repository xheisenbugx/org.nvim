1. INTRODUCTION                                             *org-introduction*

org.nvim implements Emacs Org mode in pure Lua. It reads and writes the same
plain-text format, so files can be shared with Emacs.

It covers the parts of Org you use every day:

  - Outlines with Emacs-style folding, cycling, motions and text objects.
  - TODO workflows with logging, repeaters, priorities, tags and properties.
  - An agenda with a time grid, habits, custom commands and bulk actions.
  - Capture templates that file notes from any buffer.
  - Clocking, effort estimates, clock tables and column view.
  - Spreadsheet tables with `#+TBLFM` formulas.
  - Source blocks that run asynchronously (Babel), and tangling.
  - Export to HTML, Markdown, text and LaTeX, plus more formats via pandoc.

There are no dependencies: no tree-sitter parser, external binary or
companion plugin.

Quick start:                                              *org-quickstart*

  1. Open `~/org/todo.org` and type `* TODO Buy milk`.
  2. Press `<prefix>s` to schedule it for today.
  3. Press `<prefix>a` then `a` to open the weekly agenda.
  4. Press `<prefix>c` then `t` in any buffer to capture a task.
  5. Press `g?` to list every keymap.

For a hands-on tour, open `examples/tutorial.org` from the plugin
directory. It has a section with exercises for every feature. To try it
with a throwaway config (agenda and capture included), run from the plugin
directory: >sh
    nvim -u examples/minimal_init.lua examples/tutorial.org
<

Conventions used in this manual:

  <prefix>    The value of `mappings.prefix` (default `<leader>o`).
  (ctx)       A context-sensitive key. When it does not apply at the cursor,
              the key falls back to its normal Vim behaviour (for example
              `>>` indents plain text and `<C-a>` increments numbers).
  target      Many Lua functions accept `{ bufnr = n, lnum = l }` to act on
              a headline other than the one at the cursor.

Press `g?` in an org or agenda buffer for a list of active keymaps.

2. INSTALLATION                                             *org-installation*

Requires Neovim 0.10 or later. Optional tools:

  pandoc               LaTeX, PDF, DOCX, ODT, EPUB, RST, ... export
  latexmk / pdflatex   native PDF export
  interpreters         whatever languages Babel should run

lazy.nvim / LazyVim: >lua
    {
      "xheisenbugx/org.nvim",       -- or: dir = "~/path/to/checkout", name = "org.nvim"
      main = "org",
      lazy = false,
      opts = {
        org_directory = "~/org",
        agenda_files = { "~/org/**/*.org" },
        default_notes_file = "~/org/refile.org",
      },
    }
<
Other plugin managers: add the plugin to 'runtimepath' and call: >lua
    require("org").setup({ ... })
<

Option defaults follow Emacs Org 9.8 (see |org-config|): with no
`agenda_files` the agenda and refile see only the current file until you
add some (`<C-c>[` adds the current file), `todo_keywords` is `TODO | DONE`,
nothing is logged on DONE and files open fully expanded. A common starting
point closer to many Emacs setups: >lua
    require("org").setup({
      agenda_files = { "~/org" },
      default_notes_file = "~/org/refile.org",
      todo_keywords = { "TODO(t) NEXT(n) | DONE(d)" },
      log_done = "time",
      log_into_drawer = true,
      startup_folded = "overview",
    })
<
If `setup()` is never called, the defaults are used the first time an org
buffer is opened or `:Org` is run.

Run |:checkhealth| `org` to check paths and external tools.

3. DOCUMENT STRUCTURE                                          *org-structure*

Headlines start with one or more stars followed by a space: >org
    * TODO [#A] Headline text                              :tag1:tag2:
      SCHEDULED: <2026-09-23 Wed> DEADLINE: <2026-09-30 Wed>
      :PROPERTIES:
      :ID:       0c7a...
      :END:
      Body text.
    ** Child headline
<
                                                          *org-meta-return*
<M-CR>          (ctx) Insert a new headline, list item or table row,
                depending on the cursor position, then enter Insert mode.
                On a headline: a new sibling after the subtree (or above,
                when the cursor is at column 0). In a list: a new item.
                In a table: a new row below.
<M-S-CR>        Like <M-CR>, but inserts a TODO headline or a checkbox item.
<prefix>ih      Insert headline after the current subtree.
<prefix>it      Insert TODO headline.
<prefix>is      Insert subheading (a child of the current headline).
<prefix>id      Insert a drawer (wraps the visual selection).
<prefix>ib      Insert a structure template (`#+begin_src`, quote, example,
                verse, center, comment, export ...). Wraps the visual
                selection.

                                                       *org-promote-demote*
<< / >>         (ctx) Promote / demote headline or list item. Count repeats.
<s / >s         (ctx) Promote / demote the whole subtree or item and its
                children.
<M-h> / <M-l>   (ctx) Promote / demote. In a table: move column.
<M-Left> / <M-Right>  Same as <M-h> / <M-l> (Alt + arrow keys).
<M-H> / <M-L>   (ctx) Promote / demote subtree. In a table: delete / insert
                column.
<M-h> / <M-l>   In Visual mode: promote / demote every headline of the
                selection (org-metaleft / org-metaright with a region).

                                                          *org-move-subtree*
<M-k> / <M-j>   (ctx) Move subtree, list item or table row up / down.
<M-Up> / <M-Down>  Same as <M-k> / <M-j> (Alt + arrow keys).
<prefix>K / J   Move subtree up / down.
<M-K> / <M-J>   (ctx) Outside tables: drag the line at the cursor up / down
                (org-drag-line-backward / forward). Count repeats.

                                                         *org-kill-subtree*
<prefix>hy      Copy subtree (count: that many siblings).
<prefix>hd      Cut subtree.
<prefix>hp      Paste subtree after the current one, adjusting levels.
                Subtrees are kept in a kill ring and also in the `"`
                register.
<prefix>hc      Clone subtree N times, shifting timestamps by a given offset
                (for example `+1w`).

                                                                 *org-sort*
<prefix>hs      Sort the children of the current headline (or top-level
                entries, or the list at the cursor). Menu keys: a alpha,
                n numeric, t time, s scheduled, d deadline, c created,
                p priority, o TODO order, r property, k clocking time
                (entries), x checkbox status (lists). Uppercase reverses.

                                                               *org-narrow*
<prefix>hn      Narrow to subtree: edit it in a separate buffer. `:w` writes
                back and <C-c>' saves and closes.

                                                        *org-cycle-level*
<Tab>           (Insert mode) On a new empty headline, cycle its level:
                child of the previous entry, then up the hierarchy, then
                back (org-cycle-level). On an empty list item, indent it
                under the previous item, then outdent it back
                (org-cycle-item-indentation). So `<M-CR><Tab>` makes a
                subheading. In a table: next field. Elsewhere: a tab.

<prefix>*       Toggle headline: line ↔ headline, item ↔ headline.
<prefix>-       Toggle list item: line ↔ item, headline ↔ item.
<prefix>hC      Toggle the COMMENT keyword.
<prefix>E       (Visual) Wrap the selection in an emphasis marker.

Motions and text objects:                           *org-motions* *org-textobj*
]] / [[         Next / previous visible headline.
][ / []         Next / previous sibling.
g{              Parent headline.
<prefix>.       Pick a headline of the buffer (|vim.ui.select()|).
ih / ah         Headline section without / with the headline line.
ir / ar         Subtree without / with the headline line.

4. VISIBILITY AND FOLDING                                        *org-folding*

Headlines fold by level. Drawers and `#+begin_`/`#+end_` blocks fold one level
deeper.

<Tab>           (ctx) Subtree cycling: FOLDED → CHILDREN → SUBTREE. On a
                drawer or block line, toggle that fold. In Insert mode
                inside a table, move to the next field.
                With a count (in place of C-u): `16<Tab>` restores the
                startup visibility, `64<Tab>` shows everything including
                drawers, and any other N shows the whole subtree of the
                ancestor at level N.
<S-Tab>         Global cycling: OVERVIEW → CONTENTS → SHOW ALL. With a
                count N, show headlines up to level N.
<C-c><C-Tab>    Cycle the subtree even when it is archived
                (`:Org force_cycle_archived`).

Startup visibility comes from `#+STARTUP:` (`overview`, `content`,
`showall`, `show2levels` … `show5levels`, `showeverything`, `nofold`),
falling back to the `startup_folded` option. Drawers are then folded
(`hidedrawers`, off with `nohidedrawers` or `hide_drawer_startup = false`)
and so are blocks with `hideblocks` (or `hide_block_startup = true`).
Except with `showeverything`, a `VISIBILITY` property (`folded`,
`children`, `content`, `all`) then sets the visibility of its subtree.

                                                        *org-archived-trees*
Subtrees tagged `:ARCHIVE:` stay folded when you cycle (TAB, S-TAB, the
startup visibility), like Emacs `org-cycle-open-archived-trees = nil`. Use
<C-c><C-Tab> to open one anyway, or set `cycle_open_archived_trees = true`.

`:Org overview`, `:Org content`, `:Org show_all`, `:Org show_everything`
and `:Org set_startup_visibility` set the visibility explicitly.

5. PLAIN LISTS AND CHECKBOXES                                      *org-lists*

Unordered bullets are `-`, `+` and indented `*`. Ordered bullets are `1.` and
`1)`. `[@N]` sets a counter. Description items look like `- term :: text`.
Checkboxes are `[ ]`, `[-]` (partial) and `[X]`.

<C-Space>       Toggle the checkbox. Parents get `[-]` or `[X]`, and
                statistics cookies are updated. Items without a checkbox
                get one. With a count of 4 (C-u), remove the checkbox; 16
                (C-u C-u) sets `[-]`. In Visual mode, toggle every item of
                the selection (all checked or all unchecked, following the
                first one; adds checkboxes when there are none).
<S-Up/Down>     (ctx) On an item: previous / next item of the same level
                (org-previous-item / org-next-item).
<C-c><C-c>      On an item: toggle its checkbox, or renumber the list.
<S-Right/Left>  (ctx) On an item: cycle the bullet style.
<prefix>hb      Cycle the bullet style.
<prefix>#       Update the statistics cookies `[1/3]` / `[33%]` at the cursor.

Statistics cookies on a headline count its checkboxes, or its child TODO
entries when it has no checkboxes. `:COOKIE_DATA: todo|checkbox recursive`
overrides this.

6. TODO ITEMS AND PRIORITIES                               *org-todo* *org-priority*

Keywords are defined with `todo_keywords` or per file with `#+TODO:` lines.
Each string is a sequence, and keywords after `|` are done states: >lua
    todo_keywords = {
      "TODO(t) NEXT(n) | DONE(d!)",
      "WAITING(w@/!) | CANCELLED(c@)",
    }
<
In `(x!/@)`, `x` is the fast-selection key, the first flag applies when
entering the state and the flag after `/` applies when leaving it: `!` logs a
timestamp and `@` asks for a note. Log entries go into the `log_into_drawer`
drawer (default none: under the headline, like Emacs; `true` = `LOGBOOK`), or
the drawer named by the inherited
`LOG_INTO_DRAWER` property (`nil` logs under the headline);
`#+STARTUP: logdrawer / nologdrawer` also switch it. The headings of the log
entries come from `log_note_headings` (org-log-note-headings). Notes are
typed in a small `*Org Note*` split, like Emacs: <C-c><C-c> stores the note
(lines starting with "# " are dropped), <C-c><C-k> cancels it
(`note_buffer = false` asks with a one-line prompt instead).

cit / ciT       Next / previous TODO state.
<S-Right/Left>  (ctx) Same, on a headline. Like Emacs, this walks every
                keyword of every sequence in order, with no keyword before
                the first and after the last one.
<prefix>T       Select a state (fast keys when defined).
<C-c><C-t>      Fast selection when the keywords have keys (turn it off
                with `use_fast_todo_selection = false`), otherwise cycle
                within the sequence: after its last keyword the headline
                has no keyword, and the next C-c C-t goes back to the
                first keyword of that same sequence. The count is the
                Emacs prefix argument:
                  4 (C-u)          take a note for this change
                  16 (C-u C-u)     switch to the next keyword set
                  64 (C-u C-u C-u) ignore blocking (dependencies)
                  N                switch to the Nth keyword
                In Visual mode every headline of the selection changes.
<C-S-Right/Left>  Next / previous keyword set (not logged, like Emacs).
:Org todo_without_note   Change the state, recording a time instead of
                asking for a note (C-0 C-c C-t).
:Org todo_cancel_repeaters   Set the repeaters of the entry to 0 and change
                the state, so a repeating task is done for good
                (C-- 1 C-c C-t, org-cancel-repeaters).

                                                     *org-loop-over-headlines*
In Visual mode, <C-c><C-t>, <C-c><C-s> and <C-c><C-d> act on every headline
of the selection, skipping headlines hidden in closed folds
(`loop_over_headlines_in_active_region`: true, false or "start-level" for
only the headlines at the level of the first one).

Entering a done state adds `CLOSED: [timestamp]` when `log_done` is set, and
going back to a TODO state removes it. Like Emacs, CLOSED is only touched
when some logging is set up (`log_done` or a keyword with `!`/`@`);
`closed_keep_when_no_todo` keeps it when the keyword is removed. With
`use_effective_time`, times recorded before `extend_today_until` o'clock
are 23:59 of the previous day.

                                                        *org-logging-property*
The inherited `LOGGING` property overrides the logging of a subtree, like
Emacs: `:LOGGING: nil` turns it off, `:LOGGING: lognotedone logrepeat`
selects done/repeat logging, and keyword specs such as `WAIT(@) DONE(!)`
replace the flags of the keyword definitions.

                                                      *org-todo-tags-triggers*
`todo_state_tags_triggers` adds or removes tags on state changes. Keys are
keywords, `todo` (any not-done state), `done` or `""` (no keyword): >lua
    todo_state_tags_triggers = {
      WAITING = { WAITING = true },
      done = { WAITING = false },
      [""] = { WAITING = false },
    }
<
                                                             *org-todo-events*
Every state change fires the User autocmd `OrgTodoStateChange` (Emacs
org-after-todo-state-change-hook and org-trigger-hook), and a repeating task
marked done also fires `OrgTodoRepeat` (org-todo-repeat-hook). `data` holds
`bufnr`, `lnum`, `from`, `to` (the final keyword), `state` (the keyword
chosen), `done` and `repeated`: >lua
    vim.api.nvim_create_autocmd("User", {
      pattern = "OrgTodoStateChange",
      callback = function(ev) print(ev.data.from, "->", ev.data.to) end,
    })
<
`todo_blockers` is a list of functions (org-blocker-hook); each receives
`{ type = "todo-state-change", from, to, bufnr, lnum }` and blocks the
change by returning `false`.

Repeated tasks                                            *org-repeat*
A SCHEDULED or DEADLINE timestamp with a repeater (`+1w`, `++1d`, `.+2d`)
is shifted when the task is marked done, and the task returns to the first
keyword of its sequence, like Emacs. The `REPEAT_TO_STATE` property or
`todo_repeat_to_state` (a keyword, or `true` for the previous state) choose
another state. A SCHEDULED date without a repeater is removed. The state
change is logged and `LAST_REPEAT` set when `log_repeat` is enabled
(`LAST_REPEAT` is also set when the entry has clock lines).
  +N   shift by N units once
  ++N  shift until the date is in the future, keeping the weekday
  .+N  shift to N units after today
Months keep the day of the month and roll over like Emacs: `<2026-01-31
+1m>` becomes `<2026-03-03>`.

Dependencies                                              *org-todo-dependencies*
With `enforce_todo_dependencies`, an entry cannot be marked done while its
children are unfinished, or while earlier siblings under an `:ORDERED: t`
parent are unfinished, or while an ancestor TODO is blocked that way. A
`NOBLOCKING` property disables blocking for the entry.
`enforce_todo_checkbox_dependencies` also blocks entries that have
unchecked or partial checkboxes (not the ones inside blocks).

Statistics                                               *org-todo-statistics*
A `[/]` or `[%]` cookie on a headline counts its children with a TODO
keyword. `provide_todo_statistics` chooses what counts (org-provide-todo-
statistics): `true`, `"all-headlines"`, a list of keywords, or
`{ todo_keywords, done_keywords }`; `false` stops updating cookies when a
state changes. `hierarchical_todo_statistics = false` counts the whole
subtree instead of the direct children (`:COOKIE_DATA: recursive` does it
for one entry).

Priorities
<S-Up> / <S-Down>   (ctx) Raise / lower priority on a headline. Past the
                    highest or lowest priority the cookie is removed; the
                    next shift in the same direction wraps around to the
                    other end, like Emacs.
<C-a> / <C-x>       (ctx) Same, with the cursor on the `[#A]` cookie.
<prefix>,           Set priority (press a letter, <Space> removes it). With
                    a count of 4 (C-u C-c ,), show the priority value.
:Org priority_show  Show the priority as Emacs computes it for sorting,
                    1000 × (lowest - priority) (org-priority-show).
Range and default come from `priority_highest/lowest/default` or
`#+PRIORITIES: A C B`. Numbers from 0 to 64 work too, like Emacs:
`#+PRIORITIES: 1 10 5` uses `[#1]` .. `[#10]` (typed as a number).
`ui.priority_faces` gives priorities their own highlight, like
`ui.todo_keyword_faces`.

7. TAGS                                                             *org-tags*

Tags sit at the end of the headline: `:work:urgent:`. They contain letters,
digits, `_`, `@`, `#` and `%` (org-tag-re); `:a-b:` is not a tag.

<prefix>t       Set tags. When some tag has a fast key (`#+TAGS: work(w)
                home(h)` or the `tags` option), a key menu is shown
                (org-fast-tag-selection); otherwise you type the tags with
                completion.
<C-c><C-c>      On a headline: set tags.
N<prefix>t      With a count (C-u C-c C-q): realign the tags of every
                headline. A count of 16 (C-u C-u) types the tags with
                completion even when they have keys.
{Visual}<prefix>t  Add or remove one tag on every headline of the selection
                (org-change-tag-in-region).
<C-c><C-x>q     Toggle tag groups in matches (org-toggle-tags-groups).

                                                      *org-fast-tag-selection*
In the fast selection menu, like Emacs:
  a key         toggle that tag (tags without a key get one: their first
                letter after a leading `@` when it is free, else the first
                free character of a-z A-Z { | } ~)
  <Tab>         add or remove one tag by completion
  <Space>       remove all tags
  <CR>          accept
  !             toggle the exclusivity of `{ }` groups
  <C-c>         toggle "exit after the next change"
  q <Esc> <C-g> cancel (`q` only when it is not a tag key)
The new tags are in the order of the tag table, followed by the other
tags. `fast_tag_selection_single_key` exits after one change (`true`) or
also hides the menu until <C-c> (`"expert"`);
`fast_tag_selection_include_todo` adds the TODO keywords with keys, which
change the state right away.

Completion offers the tags defined for the buffer (`#+TAGS` or the `tags`
option), or the tags used in the buffer when none are defined;
`complete_tags_always_offer_all_agenda_tags` adds every agenda file's tags.

Tags are aligned to `tags_column` (negative values right-align them, a
positive value starts them at that column). `:Org align_tags` realigns every
headline in the buffer. `ui.tag_faces` gives tags their own highlight.

In `#+TAGS`, `{ }` groups are mutually exclusive in the fast selection menu,
`[ ]` groups and `\n` start a new row, and `:` (as in `[ GTD : Control ]`)
separates a group tag from its members.
                                                              *org-tag-groups*
A group tag also matches its members in tag searches and sparse trees
(org-group-tags, `group_tags`): with `#+TAGS: [ GTD : Control Persp ]`, the
match `GTD` finds entries tagged GTD, Control or Persp, and `-GTD` excludes
all three. Groups nest, and `{regexp}` members match tags by regexp:
`[ Project : {P@.+} ]`. <C-c><C-x>q turns this off and on.

Inheritance: children inherit their parents' tags and `#+FILETAGS:`, except
the tags in `tags_exclude_from_inheritance`. Set `use_tag_inheritance =
false` to disable it, or to a list of tags or a regexp to inherit only those
tags (org-use-tag-inheritance).

8. PROPERTIES AND COLUMN VIEW                   *org-properties* *org-columns*

<prefix>p       Set a property. Names are completed, and values come from
                `PROP_ALL` properties when available. Before the first
                headline, the file-level property drawer at the top of the
                file is set (created after leading comments).
<C-c><C-x>P     Set a property from one `PROPERTY: value` answer
                (org-set-property-and-value); a count reuses the last one.
<prefix>P       Delete a property (and its `PROPERTY+` lines).
<S-Right/Left>  (ctx) On a property line: next / previous allowed value
                from `PROP_ALL` (org-property-next-allowed-value).
<C-c><C-c>      (ctx) On a property line: menu to set the value, delete it
                here or delete it from all entries (org-property-action).
`:Org delete_property_globally` removes a property from every entry of the
buffer.
<prefix>xe      Set the Effort property (stored as typed, e.g. `1h`).
<prefix>lI      Create an ID property (or show the existing one).

Property lines are written with `property_format` (org-property-format,
`"%-10s %s"`): `:Owner:    me`; an empty value leaves `:Owner:`.

Setting the special properties TODO, PRIORITY, SCHEDULED or DEADLINE
changes the headline instead (an empty value removes them), like Emacs
org-entry-put; the other special properties cannot be set. Every change
through <prefix>p fires the User autocmd `OrgPropertyChanged` with `data`
`{ bufnr, lnum, name, value }` (org-property-changed-functions).

Special properties available in matches and column view: ITEM, TODO,
PRIORITY, TAGS, ALLTAGS, CATEGORY, LEVEL, FILE, SCHEDULED, DEADLINE, CLOSED,
TIMESTAMP, TIMESTAMP_IA (first inactive timestamp), BLOCKED (`t` when the
entry cannot be marked done, else empty).

Inheritance is controlled by `use_property_inheritance` (true, false, a
list of property names, or a regexp matching them). `NAME+` lines append to the value, also to an
inherited one: `:Acc: 1` on a parent and `:Acc+: 2` on its child give
`1 2`. A property drawer at the top of the file, `#+PROPERTY: NAME value`
and `global_properties` set values for the whole file, in that order.

<prefix>C       Column view. The format comes from `#+COLUMNS`, the COLUMNS
                property or `columns_default_format`, for example
                `%25ITEM %TODO %3PRIORITY %TAGS %Effort{:}`. Summary
                operators (org-columns-summary-types-default): {+} (sum,
                printed like Emacs: `4.1`, `6`), {$} (2 decimals), {min}
                {max} {mean} (mean is always a float: `3.0`), {:} {:min}
                {:max} {:mean} (durations, in `duration_format` unless all
                values are H:MM), {X} {X/} {X%} (checkboxes), {@min} {@max}
                {@mean} (ages of timestamps), {est+} (low-high estimates).
                A format after `;`, `{+;%.1f}`, is applied to every value
                of the column, leaves included. `columns_summary_types`
                adds operators: `{ ["+|"] = function(values, fmt) ... end }`
                (or `{ summarize, collect }` where `collect(headline,
                prop)` gives a headline's value).
                Like Emacs (org-columns-compute-all), opening column view
                and updating a columnview block write each computed
                summary into the entry's property when the entry already
                has that property (even empty) and its value differs.
                SCHEDULED, DEADLINE and TIMESTAMP show as inactive
                timestamps; `columns_modify_value_for_display_function`
                (`function(title, value)`) can change any shown value.
                Keys in the view:
                  e               edit the value (TODO, tags, dates, ...)
                  n / p           next / previous allowed value (also
                                  <S-Right> / <S-Left>): `PROP_ALL`, TODO
                                  keywords, priorities, checkboxes
                                  (`columns_checkbox_allowed_values`), days
                  1 .. 9          select the Nth allowed value (digits are
                                  not counts in the view)
                  a               edit the allowed values (`PROP_ALL`)
                  < / >           narrow / widen the column
                  <M-h> <M-l>     move the column left / right (also
                                  <M-Left> / <M-Right>)
                  <M-L> / <M-H>   add a column / delete it (also
                                  <M-S-Right> / <M-S-Left>)
                  s               edit the column's attributes
                  <M-k> <M-j>     move the entry up / down (also <M-Up> /
                                  <M-Down>)

                  <C-c><C-t>      change the TODO state
                  <C-c><C-o>      open the link in the field
                  v view value, <CR> jump, r refresh, q quit.
                Format changes are saved to the COLUMNS property or the
                `#+COLUMNS:` line the view comes from.

9. DATES AND TIMES                                                 *org-dates*

Timestamps:
  <2026-09-23 Wed>                  active (shows in the agenda)
  [2026-09-23 Wed]                  inactive
  <2026-09-23 Wed 10:00-11:30>      time range
  <2026-09-23 Wed>--<2026-09-25 Fri> date range
  <2026-09-23 Wed +1w -2d>          repeater and warning period

<prefix>s       Schedule (SCHEDULED:). A new date removes CLOSED.
<prefix>d       Deadline (DEADLINE:).
<prefix>i.      Insert an active timestamp (count: include time; count
                16: the current time without a prompt). Right after an
                existing timestamp, this creates a range.
<prefix>i!      Insert an inactive timestamp.
<C-a> / <C-x>   (ctx) Increment / decrement the part under the cursor, like
                Emacs org-timestamp-change: year, month, day, hour, minute,
                end time, repeater or warning. The cursor on the character
                right after a part (a `-`, `:` or space) changes that part.
                On a repeater or warning, the number never goes below 1
                (warning: 0) and the unit letter cycles d, w, m, y. Only
                `+N` repeaters and `-N` warnings are changed, like Emacs.
<S-Up/Down>     (ctx) Same as <C-a> / <C-x>. On minutes, step by the
                second value of `time_stamp_rounding_minutes` (5) and
                round to it; a count steps by exactly that many minutes.
                The end minute of a time range moves by 1. On a bracket,
                switch the timestamp between active and inactive.
<S-Right/Left>  (ctx) Day +1 / -1.
:Org toggle_timestamp_type   Switch the timestamp at the cursor between
                active and inactive (in a range, only that end).
<C-c><C-y>      Show the length of the range at the cursor, e.g. "2 days
                3 hours 30 minutes"; with a count, insert it after the
                range as ` 2d 03:30` (` 2d` for dates, ` 00:20` under a
                day), replacing an earlier result (org-evaluate-time-range).
                `<d 10:00-12:30>` ranges work too (an extension).
<C-c><C-x><C-t> Toggle the custom display of timestamps
                (org-toggle-timestamp-overlays): each timestamp is shown as
                `time_stamp_custom_formats` (`09/25/26 Fri`) with conceal
                and inline virtual text. `display_custom_times = true` or
                `#+STARTUP: customtime` turn it on; the real text shows in
                Insert mode (see 'concealcursor').
<CR>            On a timestamp: open the agenda for that day.

The calendar                                                   *org-calendar*
Date prompts open a floating calendar:
  h l j k        day -1 / +1, week -1 / +1
  H L  < >       month -1 / +1
  J K  [ ]       year -1 / +1
  .              today
  i  t           type a date (see below); a date moved to in the calendar
                 is part of the answer, like Emacs
  T              set a time
  x  <Del>       remove the date (schedule/deadline)
  <CR>           select
  q  <Esc>       cancel
A count of 4 (`C-u`) before the schedule/deadline key removes the date; a
count of 16 (`C-u C-u`) instead asks for a date and sets the warning period
(DEADLINE) or delay (SCHEDULED) to the days between it and the entry's
date, e.g. `<2026-10-10 Sat -5d>`. Other counts are ignored, like Emacs.

Date input (like org-read-date)                                 *org-read-date*
The typed text is read like Emacs org-read-date-analyze:
  ""                   the default date (the date being changed, or today)
  "."  "+0"            today
  +3d  -2w  +1m  +4    relative to today (unit defaults to days)
  +2h                  two hours from now
  ++3d  --1w           relative to the default date
  fri  +2fri  -mon     next Friday (a weekday name is never today) / in two
                       weeks / last Monday
  2026-10-01  26-10-01  10-01  10/1  10/1/2026   absolute dates
  2026-10-01 Thu +1w   extra words (a pasted timestamp) are ignored
  15                   the 15th, this month or the next
  15.3.  15.3.2027     dotted day.month[.year]
  oct  sep 15  15 sep 2027  2027   month names, a year alone
  w39  2026-w39-5  w39 fri   ISO week (and weekday, default Monday)
  14:00  2pm  15h30  24:00   times (combine with any date); 24:00 is the
                       next day
  10:00-11:30  10am-11am  10:00+1:30   time ranges
  2026-10-01T10:00     ISO date and time
  today tomorrow yesterday now   (extensions; Emacs ignores these words)
Dates out of range roll over (`feb 30` is March 2nd). With
`read_date_prefer_future` (default), a day or month without a year is taken
in the future: `15` on the 20th is the 15th of next month; `"time"` also
moves a past time of today to tomorrow; `false` completes the date from the
default instead. Before `extend_today_until` o'clock the default is still
yesterday. Text that cannot be read at all is refused with a warning (Emacs
silently uses the default date).

Changes to SCHEDULED and DEADLINE are logged when `log_reschedule` or
`log_redeadline` is set (or via the `#+STARTUP` log keywords); setting the
same date again is not logged.

10. CLOCKING AND EFFORT                                            *org-clock*

<prefix>xi      Clock in on the current entry. Any running clock is
                stopped first, and `clock.in_switch_to_state` can change the
                TODO state. A count picks a task from the clock history
                (d default task, i the interrupted task, c the current one,
                1-9 A-Z recent tasks); 16 also marks the entry as the
                default task; 64 starts where the last clock stopped.
<prefix>xo      Clock out (global). `clock.out_switch_to_state` changes the
                TODO state; with a count, you are asked for the state.
<prefix>xq      Cancel the running clock (global).
<prefix>xj      Jump to the clocked entry (global), else to the last
                clocked one. With a count, pick from the history.
<prefix>xe      Set effort.
<prefix>xE      Set effort to the next value of `Effort_ALL`.
<prefix>xm      Change the effort of the clocked task (or the entry at the
                cursor); `+0:15` / `-10` add or subtract.
<prefix>xz      Resolve open clocks (with a count: only dangling ones, not
                the running clock). See |org-clock-resolve|.
<prefix>xd      Show the time clocked in each subtree next to its headline,
                for `clock.display_default_range` (this year). Count: 4 =
                today, 16 = ask for a range, 64 = only the total. Editing
                the buffer, <C-c><C-c> or calling it again hides the sums.
<prefix>xr      Insert a clock report (`#+BEGIN: clocktable`) for the entry
                at the cursor (:scope subtree), or the file before the
                first headline; update it when on one. With a count,
                update the first clock table of the buffer.
<C-c><C-c>      On a CLOCK line: recompute its duration.
<C-S-Up/Down>   On a CLOCK line: shift both timestamps by the part under
                the cursor, keeping the duration.
<S-M-Up/Down>   On a CLOCK timestamp: change it and move the touching
                timestamp of the previous (on a clock-in) or next (on a
                clock-out) task in the clock history by the same amount.
<S-arrows>      On a `#+BEGIN: clocktable` line: shift its :block
                (today -> today-1, 2026-W39 -> 2026-W40, ...).
:Org clock_in_last   Clock in the last clocked entry again (count: pick
                from the history; 16 = from the last clock-out; 64 = ask
                for the TODO state).
:Org clock_mark_default_task   Mark the entry as the default task.
:Org clock_toggle_auto_clockout  Turn auto clock-out on/off for this session.

Clock lines go into the LOGBOOK drawer: >org
    :LOGBOOK:
    CLOCK: [2026-09-23 Wed 10:00]--[2026-09-23 Wed 11:30] =>  1:30
    :END:
<
The drawer comes from the inherited `CLOCK_INTO_DRAWER` property (`nil`
for none, a number N for "once there are N clock lines"), then
`clock.into_drawer`, then the log drawer. With `log_note_clock_out` (or
`#+STARTUP: lognoteclock-out`), clocking out asks for a note that goes
below the CLOCK line. `clock.continuously` starts a new clock where the
last one stopped, `clock.rounding_minutes` rounds clock times and
`clock.in_resume` continues an entry's open CLOCK line.

Marking a clocked task done clocks it out (`clock.out_when_done`: true or a
list of states). A running clock is restored after restarting Neovim
(`clock.persist`: true, "clock" or "history"), after asking
(`clock.persist_query_resume`). Quitting with a running clock asks whether
to clock out and save first (`clock.ask_before_exiting`). Clocks of 0:00
are kept unless `clock.out_remove_zero_time` is set.

The statusline shows `[clocked/effort] (Task)`, where the clocked time
includes the task's earlier clocks (`clock.mode_line_total` or the
`CLOCK_MODELINE_TOTAL` property: current, today, repeat, all, auto =
since LAST_REPEAT for repeated tasks). Once it reaches the Effort you are
notified once (`clock.notify_effort`, `clock.sound`,
`clock.notification_handler`) and `clock.task_overrun_text` is prepended.

User autocmds: `OrgClockInPrepare` (before the CLOCK line is written, e.g.
to set an effort), `OrgClockIn`, `OrgClockOut`, `OrgClockCancel`,
`OrgClockGoto`.

Resolving clocks                                           *org-clock-resolve*
An open CLOCK line that isn't the running clock is dangling (e.g. after a
crash). Clocking in resolves them first (`clock.auto_clock_resolution`),
and after `clock.idle_time` idle minutes you are asked about the running
clock (the system idle time is used on macOS and with xprintidle). Keys:
  k / K   keep N of the minutes (default all) and stay clocked in / out
  t / T   keep the time until a given time
  g / G   you got back N minutes ago: clock out when you left, clock in
          again from then (G: stay out)
  s / S   subtract the idle time: clock in again now (S: stay out; the
          next clock in offers to start from the subtracted time)
  C       cancel the clock
  j / J   jump to the clock (J: clock it out first)
  i / q   ignore
`clock.auto_clockout_timer` clocks out after that many idle seconds.

Durations in clock tables, clock sums and effort changes use `1d 2:30` from
one day on, like Emacs `org-duration-format` (`duration_format = "h:mm"`
writes `26:30`).

Use |org-api| `require("org").statusline()` in your statusline.

14. CAPTURE                                                      *org-capture*

<prefix>c opens the template menu. `:Org capture KEY` selects a template
directly. A count works like Emacs's prefix argument: `4<prefix>c` (C-u)
jumps to a template's target, `16<prefix>c` (C-u C-u) to the last stored
entry and `1<prefix>c` (C-1) asks for the date of a date tree entry.
`:Org capture_here` (C-0 C-c c) inserts the template at the cursor: an
entry becomes a sibling of the headline there, other types go on the
cursor line (before it at column 0, else after it).

The target is resolved when the capture starts, like Emacs: missing
file+headline headlines and date tree nodes are created then, and the
location is remembered even if the file changes (or the clock moves to
another task) while you type. When the target is gone at the end (its
headline was deleted), nothing is lost: the capture buffer stays open.

                                                    *org-capture-templates*
>lua
    capture = {
      templates = {
        t = { description = "Task", template = "* TODO %?\n  %u", target = "~/org/refile.org" },
        w = "Work",   -- group label for keys starting with w
        wt = { description = "Work task", template = "* TODO %?", target = "~/org/work.org", headline = "Inbox" },
        j = { description = "Journal", template = "* %<%H:%M> %?", target = "~/org/journal.org", datetree = true },
      },
      window = "split",
    }
<
When `templates` is empty (the default), Emacs's fallback is used:
`t = { description = "Task", target = "", headline = "Tasks", template =
"* TODO %?\n  %u\n  %a" }`, which files under "Tasks" in
`default_notes_file`.

Template fields:
  description        menu label
  template           string, list of lines, `{ file = "path" }` (read from
                     that file, relative to `org_directory`) or a function
                     returning a string. When empty: "* %?\n  %a" for
                     entries, "- %?" for items, "- [ ] %?" for checkitems,
                     "| %? |" for table lines
  type               "entry" (default), "item", "checkitem", "table-line",
                     "plain"
  target             file (relative to `org_directory`, "" =
                     `default_notes_file`), "clock", or a function
                     returning either; defaults to `default_notes_file`
  headline           file+headline: under the first headline with this
                     title (TODO keyword, priority and tags ignored),
                     created at the end of the file when missing
  olp                file+olp: outline path, e.g. { "Projects", "Neovim" }
                     or "Projects/Neovim"; every node must exist
  datetree           file+olp+datetree: true or { tree_type = ... }, under
                     `olp`/`headline` when given. The date is the capture
                     date (agenda day, `time_prompt`, C-1) or today.
                     Existing nodes are recognized by their date
                     ("2026-09 Sept" is the September node)
  tree_type          "day" (default), "week", "month", a list of "year",
                     "quarter", "month", "week", "day", or a function(date)
                     returning { { title, compare } ... } (:tree-type)
  regexp             file+regexp: Vim regexp; the text goes where the
                     first match ends (starts, with `prepend`); an entry
                     becomes a child when the match is on a headline
  func / function    file+function: function(bufnr) returning the line
                     (and column) of the location, or moving the cursor
                     there; a headline line means "under this headline"
  location           the (function f) target: function() returning the
                     buffer, line and column, or nothing for the cursor
                     position in the current buffer
  id                 insert under the entry with this ID (file+id)
  target = "clock"   insert under the currently clocked task (clock)
  prepend            insert as the first child instead of the last
  empty_lines        blank lines around the text, replacing the blank
                     lines already there (also empty_lines_before /
                     empty_lines_after; items in an existing list get at
                     most one)
  table_line_pos     where a table line goes, e.g. "II-3" (3 lines before
                     the 2nd hline) or "I+1" (right after the 1st). A table
                     is created when there is none
  properties         table of properties added to the entry
  immediate_finish   finish without opening the capture window
  jump_to_captured   jump to the entry after finishing
  kill_buffer        unload the target file afterwards when the capture
                     loaded it
  refile_targets     `refile.targets` used when refiling from the capture
                     buffer
  clock_in           clock the entry while capturing (stops the running
                     clock); the time is logged when the capture ends
  clock_keep         with clock_in, keep the clock running afterwards
  clock_resume       with clock_in, clock the interrupted task in again
                     when the capture ends or is aborted
  time_prompt        ask for the date used by %t/%T/%u/%U and the datetree
  no_save            don't save the target file after capturing
  prepare_finalize   function(capture_bufnr), before the text is read
  before_finalize    function(bufnr, lnum) in the target, before saving
  after_finalize     function(bufnr, lnum) when the capture is done
  unnarrowed         not supported: see |org-differences|

An entry template without stars gets "* ", item templates get "- " (and
continuation lines are indented under the bullet); in an existing list the
item takes the list's indentation and bullet style. Items and table lines
go into the first list / table of the target entry (of the file for a
plain file target); "plain" text goes at the end of the entry's text,
before its children (after its planning, properties and drawers with
`prepend`), or at the end (top) of a file.

                                                    *org-capture-contexts*
`capture.templates_contexts` (org-capture-templates-contexts) makes
templates available only in some buffers. Each rule is `{ key, rules }`, or
`{ key, other_key, rules }` to use `other_key`'s template for `key` there
(the other key is then hidden). A template is shown when any of its rules
holds; rules are tables with one of `in_file`, `not_in_file`, `in_mode`
(filetype), `not_in_mode`, `in_buffer`, `not_in_buffer` (Vim regexps) or
functions:
>lua
    capture = { templates_contexts = {
      { "m", { { in_mode = "^mail$" } } },
      { "t", "p", { { in_file = "project" } } },
    } }
<
Template expansions:                               *org-capture-expansions*
  %?           cursor position
  %t %T        active date / date and time
  %u %U        inactive date / date and time
  %^t %^T %^u %^U  the same, asking with the calendar
  %<fmt>       strftime format, e.g. %<%Y-%m-%d>
  %a           annotation: a link to the location capture was started from
  %A           the same, asking for a description
  %l           the link without a description
  %L           the bare link target
  %i           initial content (the visual selection); the text before
               %i on its line is repeated on every line
  %x           clipboard (the `*` register, else `+`)
  %c           last yank
  %f %F        origin file name / full path
  %n           your full name (like Emacs's `user-full-name`)
  %k %K        the clocked task's title / a link to it
  %^{Prompt}   ask; `%^{Prompt|default|opt1|opt2}` offers opt1 and opt2
               and uses the default for an empty answer
  %^C %^L      ask for a clipboard value (%^L makes it a link)
  %\1 ...      the answer to the Nth %^{...} prompt
  %\*1 ...     the answer to the Nth prompt of any kind (%^t, %^g, ...)
  %^g %^G      tags prompt, completing the target file's / all agenda

  %^{PROP}p    property prompt (offers the PROP_ALL values of the target)
  %:keyword    link information: %:link, %:description, %:annotation,

expansion character (`\%t`). Leading blank lines and trailing whitespace of
the expanded text are removed.

Capture window: `<C-c><C-c>` or `:w` finalizes (with a count, C-u C-c C-c,
it then jumps to the entry), `<C-c><C-k>` aborts (the headlines created for
an unmodified target are dropped again) and `<C-c><C-w>` finalizes and
refiles the entry (entry templates only; also `<prefix>w`, `<prefix>k`,
`<prefix>r`). The window splits the screen like Emacs (`capture.window`:
"split", "float", "vsplit", "tab" or "current").

:Org capture_goto_target  choose a template and jump to its target
                          (C-u C-c c in Emacs)
:Org capture_goto_last    jump to the last captured (or refiled) entry
                          (C-u C-u C-c c)
From the agenda, `c` captures with the date at point as the default date.

org-protocol                                                  *org-protocol*
`org-protocol://` URLs from a browser or another program capture, store
links and open files in a running Neovim, like Emacs `org-protocol.el`:
  org-protocol://capture?template=KEY&url=URL&title=TITLE&body=TEXT
      capture with template KEY (`protocol.default_template_key`, else
      choose); `%:link`, `%:description`, `%a`, `%i` (body) and
      `%:<param>` come from the URL
  org-protocol://store-link?url=URL&title=TITLE
      store the link for |org-insert-link| and yank the URL
  org-protocol://open-source?url=URL
      open the local file behind a published URL (`protocol.projects`,
      like org-protocol-project-alist: base_url, working_directory,
      online_suffix, working_suffix, rewrites)
Old-style URLs (`capture://KEY/URL/TITLE/BODY`) work too, and
`protocol.handlers` adds sub-protocols. Call it from Lua with
`require("org.protocol").handle(url)` or `:Org protocol <url>`.

Neovim must listen on a socket (`nvim --listen ~/.cache/nvim/org.sock`, or
|v:servername|) and the OS must send `org-protocol:` URLs to a handler
that forwards them, e.g. on Linux a desktop file with
`MimeType=x-scheme-handler/org-protocol;` and: >sh
    Exec=nvim --server ~/.cache/nvim/org.sock --remote-expr "v:lua.require'org.protocol'.handle('%u')"
<
then `xdg-mime default org-protocol.desktop x-scheme-handler/org-protocol`.
On macOS register the scheme with a small app bundle (an AppleScript
`on open location` handler running the same command). A bookmarklet: >js
    javascript:location.href='org-protocol://capture?'+new URLSearchParams({
      template:'p', url:location.href, title:document.title,
      body:window.getSelection()});void(0)
<
Emacs's emacsclient integration (`server-visit-files` advice, `:kill-client`)
has no counterpart: the handler command above plays that role.

15. REFILE AND ARCHIVE                                *org-refile* *org-archive*

<prefix>r       Refile the subtree as the last child of another headline
                (org-refile, <C-c><C-w>). In Visual mode, refile the
                selected lines; they must start with a headline and form a
                sequence of subtrees. The subtree keeps its blank lines and
                goes after the target's own blank lines, like Emacs. A
                count works like Emacs's prefix argument: 4 (C-u) jumps to
                a target, 16 (C-u C-u) to the last refiled entry, 2 refiles

<prefix>R       Copy the subtree to a refile target, keeping the original
                (org-refile-copy, <C-c><M-w>).
:Org refile_goto       Jump to a refile target (C-u C-c C-w).
:Org refile_goto_last  Jump to where the last refile or capture went
                       (C-u C-u C-c C-w).

By default the targets are the level-1 headlines of the current buffer,
shown by their heading (Emacs's org-refile-targets nil). Refile options:
  targets             like org-refile-targets. A list of specs, each with
                      `files` ("agenda", "current" (the default), a path or
                      glob, a list, or a function) and any of `max_level`,
                      `level`, `tag`, `todo`, `regexp` (Vim regexp on the

                      plus the current file (unless `include_current_file
                      = false`) up to this level
  use_outline_path    how targets are shown (org-refile-use-outline-path):
                      false (default) the heading, followed by

                      "file" "file.org/Parent/Child/"; "full-file-path",
                      "title" (#+TITLE) and "buffer-name" likewise. The

  allow_creating_parent_nodes

  active_region_within_subtree
                      refile a Visual selection that does not start at a
                      headline by making its first line one
  verify              function(headline) -> boolean to drop targets

  reverse_note_order  refile as the first child (org-reverse-note-order)

<prefix>hA      Toggle the ARCHIVE tag. Archived subtrees stay folded and are

<C-c><C-x>A     Move the subtree under its "Archive" sibling

:Org archive_all_done

16. LINKS, IDS AND ATTACHMENTS                  *org-links* *org-id* *org-attach*

Syntax: `[[target][description]]`, `[[target]]`, plain links
(`https://en.wikipedia.org/wiki/Foo_(bar)`: balanced parentheses are part
of the link, trailing punctuation is not) and <angle> links. Bracket links
may span lines. With `ui.conceal_links` (org-link-descriptive), only the
description is shown.

Targets:
  https://… http://… ftp:… mailto:…   opened with |vim.ui.open()|
  doi:10.1000/x                       `links.doi_server_url` + path
  file:path  ./rel  ~/p  /abs          open a file; add a search option:
      ::42  ::*Heading  ::#custom-id  ::(coderef)  ::/regexp/  ::some text
  file+sys:path  file+emacs:path      system application / always Neovim
  id:UUID  id:UUID::search            headline with that ID (the search
                                      runs inside its subtree)
  #custom-id                          headline with that CUSTOM_ID
  *Heading                            headline in the current file
  (label)                             coderef in a src/example block
  <<target>>  text                    dedicated target, `#+NAME`, headline
  shell:cmd                           run in a terminal in the file's
                                      directory (asks first)
  help:topic                          Vim :help
  man:printf(3)  man:ls::-l           |:Man|, with an optional search
  info:emacs#Top                      the `info` program in a terminal
  attachment:name                     file in the entry's attachment dir
  abbrev:tag  abbrev::tag  abbrev     `#+LINK:` or `links.abbreviations`
                                      (`%s` = tag, `%h` = url-encoded)
  custom:path                         `links.types` (see below)

Searches (org-link-search) ignore case and runs of whitespace (a text
search also matches across line breaks), and headline searches ignore the
TODO keyword, priority, COMMENT, tags and statistics cookies. A fuzzy
link tries `<<target>>`, `#+NAME:` and headlines. When nothing matches in
an Org file, `links.search_must_match_exact_headline` decides: with
"query-to-create" (default) you are asked "No match - create this as a new
heading?" (the heading is added at the end of the file, or as the last
child of the entry for `id:ID::*Heading`); with true the failure is
reported; with false a plain text search follows, which never lands on the
link itself. `*Heading` searches never fall back to text. `::/regexp/`
takes an Emacs regexp: in Org files it shows a sparse tree
(|org-sparse-tree|), elsewhere a location list (like `occur`); common
Emacs syntax is translated to Vim regexps, see |org-differences|.

<CR>, gx, <prefix>o  Open the link, footnote or date at the cursor.
<C-c><C-o>      The same. On the tags of a headline, show a tags agenda for
                the tag under the cursor (a count: TODO entries only).
                Elsewhere on a headline, pick one of the entry's links, or
                "Open all links"; without links, open the attachment
                directory when there is one.
                With a count (C-u), files open in Neovim even when an
                external app applies, and internal links are shown in
                another window; with 16 (C-u C-u), files open with the
                system application.
                `file:` and `id:` links open in another window, splitting
                when there is none, like Emacs (`links.frame_setup`).
<prefix>ls      Store a link to the current location (works in any
                buffer, org-store-link). In org buffers this is, in order:
                the `store` function of a custom link type, an `id:` link
                (see `links.use_id`), the `<<target>>` under the cursor
                (`file:…::target`), the `#+NAME:` of the element at the
                cursor, the current line before the first heading, or the
                heading: `file:…::#custom-id` or `file:…::*Heading`. When
                the entry has a CUSTOM_ID, a `file:…::#custom-id` link is
                stored too. In Visual mode the selection is the search
                string (`links.context_for_files` may limit its lines).
                In other files, the current line is the search string (an
                empty line gives a plain `file:` link). Search strings
                collapse whitespace and drop statistics cookies. In the
                agenda, the link points to the item's entry; in a src
                block edit buffer (|org-babel|), it stores a coderef link
                `file:…::(label)` and adds a `(ref:label)` to the line when
                it has none. Help buffers give `help:tag`, man pages
                `man:page`, netrw/oil listings a link to the file under the
                cursor.
                A count of 4 (C-u) toggles `links.context_for_files`, 16
                (C-u C-u) skips custom `store` functions, 64 stores one link
                per selected line.
<prefix>li      Insert a link (org-insert-link). Stored links, their
                descriptions, link types and file paths (relative to the
                file's directory) are completed; an empty answer inserts
                the last stored link. Entering a type alone (`file`,
                `id:`, a custom type) completes it. On a link, edit it (a
                plain or angle link becomes a bracket link). In Visual
                mode, the selection becomes the description. Links to the
                current file become their search option, and file paths
                follow `links.file_path_type`. An inserted stored link is
                removed from the list (`links.keep_stored_after_insertion`).
                With a count of 4 (C-u), pick a file; 16 (C-u C-u) uses an
                absolute path; 64 inverts `keep_stored_after_insertion`.
<prefix>lL      Insert the last stored link and a newline, and forget it
                (C-c M-l). A count inserts that many. Links without a
                description get `<no description>`, like Emacs.
<prefix>lA      Insert every stored link as a `- ` line and forget them
                (C-c C-M-l); a count of 4 keeps them.
<prefix>lt      Toggle concealed link display (org-toggle-link-display):
                only links change, not emphasis markers.
<prefix>ln/lp   Next / previous link (takes a count). Links in src and
                example blocks, comments and verbatim are skipped;
                repeating a failed search wraps around the buffer.
<C-c>&          Jump back to where you followed a link from (<C-o> works
                too).
<C-c>'          On `#+INCLUDE:`, `#+SETUPFILE:` or `#+BIBLIOGRAPHY:`, visit
                the file.

Radio targets `<<<text>>>` make every occurrence of "text" a link to them
(also in export): case is ignored, the words must stand alone and may be
split over lines. Radio links are highlighted; after adding a radio
target, <C-c><C-c> on it refreshes the highlighting. Coderefs: a
`(ref:name)` label at the end of a src or example block line (or the
block's `-l "fmt"` format) can be reached with `[[(name)]]`.

Custom link types (org-link-set-parameters) go in `links.types`, either a
function (follow) or a table: >lua
    links = { types = { jira = {
      follow = function(path, link, count) vim.ui.open("https://jira/" .. path) end,
      complete = function() return "jira:" .. vim.fn.input("Issue: ") end,
      store = function(interactive) end,   -- { link = ..., desc = ... } or nil
      export = function(path, desc, backend) end,  -- "html", "md", "latex", "ascii"
      face = "DiagnosticWarn",
      insert_description = function(link, desc) return link:sub(6) end,
    } } }
<
`links.make_description(link, desc)` gives other links a default
description. `links.search_functions` run first on search options and
`links.translation_function(type, path)` rewrites links before they open.

IDs are stored in `id.locations_file`. `:Org id_update_locations` rebuilds
it from the agenda files, their archive files (`id.search_archives`,
default true), `id.extra_files`, the loaded org buffers and the files
already known; an ID that is not where the database says triggers the same
scan. Refiled and archived entries are recorded at their new place.
New IDs follow `id.method` (org-id-method): "uuid" (default), "ts" (a time
stamp in `id.ts_format`) or "org" (a compact time based ID), with
`id.prefix` and a colon in front when set (org-id-prefix).
Links to headings are `file:` links unless
`links.use_id` asks for `id:` links (IDs are then created in your files).
`id:` links get a search string for a named element or a selection below
the heading (`id:ID::tbl1`, `id.link_use_context`); with
`id.link_consider_parent_id`, a heading without an ID is linked through
its ancestor's ID (`id:ID::*Child`).
<prefix>lI      Get or create the entry's ID; with a count (C-u), replace
                it by a new one.
<prefix>lg      Go to an entry by ID (org-id-goto, IDs are completed).
<prefix>ly      Copy the entry's ID, creating it if needed (org-id-copy).
`:Org id_store_link` stores an `id:` link whatever `links.use_id` says.

<prefix>A opens the attachment menu (org-attach):
  a  attach a file (method from `attach.method`: cp/mv/ln/lns)
  c m l y  attach by copy / move / hard link / symbolic link
  u  download a URL (curl)   b  attach the contents of a buffer
  n  create a new file       z  sync the ATTACH tag with the directory
  o  open an attachment (system app or `links.file_apps`)
  O  open it in Neovim
  f  open the directory with the system app
  F  open the directory in Neovim
  d  delete one              D  delete all
  s  set the DIR property    S  remove the DIR property
Directories can be attached too (copied recursively with "cp").

The directory is the DIR property (or the older ATTACH_DIR), else it
comes from the ID: `attach.dir` + a folder from `attach.id_to_path`
(org-attach-id-to-path-function-list: "uuid" gives `ab/cdef...`, "ts"
gives `202609/25T...`, "fallback" gives `__/a/abcdef...`, or your own
functions); an existing folder wins, also under the default "data/".
Parents' DIR / ID count only as `attach.use_inheritance` says
("selective", the default, follows `use_property_inheritance`). An entry
without either gets an ID (`attach.preferred_new_method`: "id", "dir"
asks for a DIR, "ask", or false). Attaching adds the `attach.auto_tag`
tag (ATTACH) and stores a link (`attach.store_link`: "attached" an
`attachment:` link, "file" a `file:` link to the attachment, true to the
source, false none). Other options: `dir_relative` (store DIR relative to
the file), `sync_delete_empty_dir` ("query", true, false) and
`archive_delete` (delete the attachments of archived entries: false, true,
"query").

18. TABLES AND FORMULAS                                *org-tables* *org-tblfm*

Start a row with `|`. `|-` becomes a separator line (hline) when the table is
aligned.

Insert mode:  <Tab>/<S-Tab>  next / previous field (realigns; creates rows)
              <CR>           same column in the next row
              <S-CR>         copy the field down (see below)
Normal mode:
  <C-c><C-c>      realign; in a row marked `#` recalculate that row; with a
                  count recalculate the table (4) or iterate it (16); on
                  a `#+TBLFM` line apply that line (see below); on
                  `#+PLOT:` plot; on `#+ORGTBL:` recalculate and send
  <C-c>*          recalculate the current row (column formulas of the row
                  and every field formula); count 4: the whole table;
                  count 16: until it no longer changes (org-table-iterate)
  <M-h/l>         move column left / right (also <M-Left/Right>)
  <M-k/j>         move row up / down (also <M-Up/Down>)
  <M-H>/<M-L>     delete / insert column
  <M-K>/<M-J>     delete row / insert row above
  <M-CR>          insert row below
  <S-Up/Down/Left/Right>  swap the field with its neighbour
  <S-CR>          copy the field one row down and move there; in an empty
                  field, copy the nearest non-empty field above (count: the
                  Nth). Numbers, text starting or ending with a number and
                  dates are incremented (`table_copy_increment`)
                  In tmux, <S-CR> arrives as <CR> unless extended keys
                  are on: `set -s extended-keys on` and
                  `set -as terminal-features 'xterm*:extkeys'`
  <C-c>+          sum the column (or the Visual selection) into the
                  unnamed register: every row, header included; as soon as
                  one field is H:MM[:SS], plain numbers count as hours and
                  the sum is H:MM:SS (org-table-sum)
  <C-c><Tab>      shrink / expand the column (see |org-table-shrink|)
  <C-c>`          edit the field in a prompt; count 4: show a shrunk
                  column in full; count 16: follow-field mode
  <C-c>{          toggle the formula debugger (|org-table-debugger|)
  <C-c>"a <C-c>"g ASCII bar plot / gnuplot plot (|org-plot|)
  <prefix>Tc      create a table ("5x3"), or convert CSV/TSV/whitespace
                  (Visual mode; count 4: comma, 16: tab, N: N+ spaces)
  <prefix>T-      insert a hline (<C-c>- with a count: above)
  <prefix>Tf      recalculate the whole table
  <prefix>Ts      sort rows (<C-c>^, see below)
  <prefix>Tr/TR   insert / delete row
  <prefix>Ti/TI   insert / delete column
  <prefix>Tt      transpose the table (hlines are dropped)
  <prefix>T#      rotate the recalculation mark ` # * ! $ _ ^` of the row
                  (Visual mode: set a mark on every selected row); a
                  marker column is added when needed
  <prefix>'       the formula editor (|org-table-formula-editor|)
  :Org table_import   insert a CSV/TSV/whitespace file as a table
  :Org table_export   write the table with a translator: the file and
                      format come from the TABLE_EXPORT_FILE and
                      TABLE_EXPORT_FORMAT (`orgtbl-to-latex :splice t`)
                      properties when set, else from prompts (the format
                      offered matches the file extension, else
                      `table_export_default_format`)
  :Org table_iterate  :Org table_recalc_buffer (all tables, iterated)

Inserting, deleting and moving rows and columns rewrites the references of
every `#+TBLFM` line below the table like Emacs org-table-fix-formulas:
`$3=$1+$2` becomes `$2=$INVALID+$1` when column 1 is deleted, formulas that
assign to a deleted row or column are removed, references inside remote()
are left alone. Set `table_fix_formulas_confirm` to be asked first. A new
row copies a `#`, `*` or `$` mark of the current row.

Sorting (<C-c>^, org-table-sort-lines) sorts the rows between the hlines
around the cursor, or the rows of the Visual selection: `a` text (emphasis
markers and link brackets ignored; case-insensitive, case-sensitive with a
count), `n` numbers, `t` timestamps, durations and H:MM, `f` a key function
typed as Lua (`function(s) return #s end`) with an optional comparison
function; the uppercase letters sort in reverse.

Alignment: a column is right-aligned when at least `table_number_fraction`
(0.5) of its fields are numbers. `<l>`, `<r>` and `<c>` cookies (`<r10>`
with a width) fix the alignment; cookie cells are aligned like the column.

Type `=formula` in a field and press <Tab>, <CR> or <C-c><C-c>: it becomes
the column formula of that column (`:=formula` a field formula for that
field), is stored in `#+TBLFM` and the field is computed (<C-c>* updates
the rest). `table_formula_evaluate_inline` turns this off.

<C-c>= reads the formula of the current column (count: of the current field,
or its `^`/`_` name; count 16: put the active formula into the field as
`=...` for editing), stores it and computes the field. An empty formula
removes it. A1-style references (`B3`, `C&`) are accepted when typed
(`table_use_standard_references`).

                                                        *org-table-formulas*
Formulas go in `#+TBLFM:` lines below the table: >org
    | Item  | Qty | Price | Total |
    |-------+-----+-------+-------|
    | Apple |   3 |  0.50 |  1.50 |
    | Pear  |   2 |  0.75 |  1.50 |
    |-------+-----+-------+-------|
    | Sum   |     |       |  3.00 |
    #+TBLFM: $4=$2*$3;%.2f::@>$4=vsum(@I..@II);%.2f
<
Only the first `#+TBLFM:` line is used. Keep alternatives in more lines
below it and press <C-c><C-c> on one of them to apply it once
(org-table-calc-current-TBLFM). Storing formulas (<C-c>=, inline formulas,
the formula editor) rewrites only the first line (or the edited one), with
the formulas sorted like Emacs.
References:
  $2  $>  $<  $>> $+1 $-1    columns
  @3  @>  @<  @<< @-1 @I @II rows / hlines
  @2$3                       a single field
  @2$1..@4$3  $1..$3         ranges
  @# $#                      the current row / column number
  remote(name, @2$1)         a field of a named table (#+NAME:)
  $name                      a named column, field, parameter or constant
Names, looked up in this order:
  `!` row           `| ! | | qty | price |` names the columns below it
  `^` / `_` rows    name the field in the row above / below (a formula
                    sees the value it had before the recalculation, like
                    Emacs, so iterate to use a fresh one)
  `$` row           `| $ | max=50 |` defines a parameter
  constants         `#+CONSTANTS: tax=0.16 rate=18.5`, then the
                    `table_formula_constants` option
  $PROP_Name        the Name property of the entry (inherited)
  header row        (extension) `$Total=$Qty*$Price` uses the header above
                    the first hline when there is no `!` row
Column formulas run on the rows below the first hline (all rows without
one); when the first column holds marks (`! $ ^ _ # *`), only on rows
marked `#` or `*`. Rows marked `! ^ _ $ /` are never changed. Formulas run
row by row in the order of their sorted left sides, column formulas first,
then field formulas. A column formula beyond the last column adds the
column; a field formula does so only with `table_formula_create_columns`
(true, "warn" or "prompt"; false: an error).

                                                           *org-table-calc*
Formulas are GNU Calc expressions, evaluated by a Lua reimplementation of
the parts Org tables use. As in Emacs, each reference is replaced by the
field text (`(3)`; ranges `[1,2,3]`, empty fields dropped) before the
formula is evaluated, so:
- Calc precedence: `/` binds looser than `*`, `a/b*c` is `a/(b*c)`; `^`
  binds tighter than unary minus (`-2^2` is -4); `2 3` and `2(3+1)`
  multiply; `a ? b : c`; `!` factorial, `%` percent (`10%`) or modulo.
- Numbers: exact integers of any size (`2^100`), floats with 12 digits and
  Calc's display with 8 (`3.`, `0.33333333`, `1e-3`, `1.2345679e12`),
  fractions `3:4` (`F` flag), vectors `[1, 2]` (`|` concatenates, `*` of
  two vectors is the dot product).
- Dates: `<2024-01-10 Wed>` (also `[...]` fields) is a date; subtracting
  two gives days (`$2-$1`), adding a number gives a date (written as an
  inactive timestamp), `date(<...>)` gives the day number.
- Text stays symbolic: `$1*2` on `x` gives `2 x`, `sqrt(x)` stays,
  `if($1>3, big, small)` returns `big`/`small`; `pi` and `e` stay
  symbols. With `N` a non-numeric result is #ERROR.
- Functions: vsum vmean vmin vmax vcount vprod vmedian vsdev vpsdev vvar
  vpvar vlen rev sort, abs sqrt exp ln log log10 exp10 floor ceil round
  trunc frac idiv mod `\` gcd lcm fact choose perm sign min max hypot, sin
  cos tan arcsin arccos arctan arctan2 sinh cosh tanh deg rad (degrees
  unless `R`), if lnot, date year month day hour minute second weekday
  now. Unknown functions stay symbolic, e.g. `foo(x)`.
Flags after `;` (org-table-eval-formula): Calc modes `p20` (precision),
`n3` (significant digits), `f2` (fixed), `s3` / `e3` (scientific /
engineering), `N` (fields as numbers), `E` (keep empty fields, as `nan` in
Calc), `R` / `D` (radians / degrees), `F` (fractions), `T` / `t` / `U`
(fields and results as durations: H:MM:SS, hours (see
`table_duration_custom_format`) and H:MM; `table_duration_hour_zero_padding`),
`L` (Lisp literal). Like Emacs, these letters are removed from the rest,
which is a printf format applied to the result: `%.2f`, `%.1f%%`, `%d`.
Lisp formulas: `'(+ $1 $2);N`, `'(concat $1 "-" $2)`: fields become Lisp
strings, numbers with `N`, verbatim text with `L`; ranges become several
arguments; a list result is #ERROR. See |org-differences| for the Lisp
subset. Lua formulas (extension): `$3='(string.upper($1))` (a `'(...)`
that is not Lisp).
Errors show as #ERROR.

                                                  *org-table-formula-editor*
<C-c>' (or <prefix>') in a table, or on a `#+TBLFM` line, opens the
formula editor in a split below (org-table-edit-formulas): one `lhs = rhs`
per line under "# Column Formulas", "# Field and Range Formulas" and
"# Named Field Formulas". Lines starting with a blank continue the formula
above. As the cursor moves, the fields the formula uses are highlighted in
the table (OrgTableFormulaRef, OrgTableFormulaRefCursor for the reference
at the cursor, OrgTableFormulaTarget for the target), for column formulas
on the row of the table window's cursor.
  <C-c><C-c> <C-c>' <C-c><C-s> <C-x><C-s> :w   store (a count: also
                                              recalculate the table)
  <C-c><C-q>          abort
  <C-c>?              show the references, move the table cursor there
  <S-Up/Down/Left/Right>  shift the reference at the cursor
  <M-S-Up> <M-S-Down> change the table row used for column formulas
  <M-Up> <M-Down>     scroll the table window

  <C-c>}              toggle the table coordinates

                                                       *org-table-debugger*
<C-c>{ toggles the formula debugger: each evaluation then shows the
original formula, the formula with the references replaced, the result, the
format and the final text in a `*Substitution History*` window and asks

                                                         *org-table-shrink*
<C-c><Tab> in a table shrinks the current column, or shows it again
(org-table-toggle-column-width): a shrunk column shows the first W
characters of each field (W from a `<W>`/`<lW>` cookie in the column, one
character without one) followed by `table_shrunk_column_indicator` (`…`).
Before the first or after the last column it asks for column ranges
(`2-4 6-`). Count 4 shrinks the columns with a width cookie and expands the
others (org-table-shrink), count 16 expands all (org-table-expand).
`#+STARTUP: shrink` (or `startup_shrink_all_tables`) shrinks every table
with cookies when a file is opened; columnview blocks with widths are
shrunk after an update. Neovim has no overlays that hide text, so shrunk
fields are concealed ('conceallevel' is set to 2) and drawn as inline
virtual text; the text itself is unchanged. In Insert mode the table is
shown in full, and it shrinks again when you leave Insert mode.

                                                  *org-table-follow-field*
Follow-field mode (<C-c>` with count 16): a small window below shows the
full text of the current field and follows the cursor. Edit the text there
and write it back with <C-c><C-c> or :w (moving to another field writes it
too). Leaving the table ends the mode
(`table_exit_follow_field_mode_when_leaving_table`).
Header-line mode (`:Org table_header_line_mode`, or `table_header_line_p`
for every buffer): while the first row of the table at the top of the window
is scrolled out of view, it is shown in the 'winbar' (Emacs draws it over
the first visible line).

                                            *org-table-translators* *orgtbl*
Translators turn a table into another format (Emacs orgtbl-to-*):
`orgtbl-to-tsv`, `-csv`, `-latex` (:booktabs, :environment), `-html`
(:attributes), `-texinfo` (:columns), `-orgtbl` and `-generic`. Parameters
of orgtbl-to-generic: :splice, :skip N (rows, hlines included), :skipcols
(2 3), :hline, :sep, :hsep, :tstart :tend, :lstart :lend, :llstart :llend,
:hlstart :hlend :hllstart :hllend, :lfmt :llfmt :hlfmt :hllfmt, :fmt :hfmt
(a format or `(2 "$%s$" 4 "%s")`), :efmt (`"%s\\times10^{%s}"`), :raw. As in
Emacs export, a column of recalculation marks, the `! ^ _ $ /` rows and
cookie rows are dropped. From Lua, the format parameters may be functions:
`require("org.table.orgtbl").translate("orgtbl-to-generic", rows, {...})`;
a global Lua function can be used as a translator by name.

                                              *org-radio-tables* *orgtbl-mode*
Radio tables: a table below `#+ORGTBL: SEND name translator :params` is
sent, translated, between the lines containing `BEGIN RECEIVE ORGTBL name`
and `END RECEIVE ORGTBL name` (anywhere in the buffer) whenever <C-c><C-c>
recalculates or realigns it. `:Org orgtbl_mode` turns on the table editor in
buffers of any filetype (Emacs orgtbl-mode): on table lines <Tab>, <S-Tab>,
<CR> (Insert mode), <S-CR>, <C-c><C-c>, <C-c>|, <C-c>-, <C-c><CR>, <C-c>=,
<C-c>', <C-c>`, <C-c>*, <C-c>^, <C-c>?, <C-c><Space>, <C-c>+, <C-c>},
<C-c>{, <C-c><Tab>, <C-#>, <C-c><C-x><M-w>/<C-w>/<C-y>, <M-arrows>,
<M-S-arrows>, <M-hjkl>, <M-HJKL>, <C-c>"a and <C-c>"g work like in org
buffers; elsewhere the keys keep their meaning. `:Org
orgtbl_insert_radio_table` inserts a template for the filetype
(`orgtbl_radio_table_templates`: tex, texinfo, html, org),
`:Org orgtbl_toggle_comment` comments or uncomments the table with
'commentstring', `:Org orgtbl_send_table` sends it.

                                                                  *org-plot*
<C-c>"a (orgtbl-ascii-plot) adds a column after the current one with a bar
plot of its numbers, drawn by `'(orgtbl-ascii-draw $2 MIN MAX 12)` (a
count sets the width, count 4 asks); it follows the table on
recalculation. `orgtbl-uc-draw-grid` and `orgtbl-uc-draw-cont` draw with
Unicode blocks. <C-c>"g (or <C-c><C-c> on a `#+PLOT:` line) plots the

`plot_gnuplot_term_extra`), using the `#+PLOT:` options above it: >org
    #+PLOT: title:"Sales" ind:1 deps:(2 3) type:2d with:lines
    #+PLOT: file:"sales.png" set:"yrange [0:]" labels:("x" "a" "b")
<
Options: type (2d, 3d, grid), title, ind, deps, with, file, labels, line,
set, map, script (a gnuplot script; `$datafile` is replaced), timefmt,
transpose. The header row gives the labels; an independent column of
timestamps is plotted as time. The radar type is not supported.

19. SOURCE BLOCKS (BABEL)                                          *org-babel*
>org

    #+begin_src python :results output :var n=3
    for i in range(n): print("hi", i)

<C-c><C-c> or <prefix>be   Execute the block (asynchronously). With
                           `babel.confirm_evaluate`, you are asked first

<prefix>bk         Remove the result. With a count (C-u), remove every
                   result in the buffer.
<prefix>bn / bp    Next / previous block.
<prefix>'          Edit the block in a buffer with the language's filetype.

<prefix>bt         Tangle the file (`:Org tangle`). With a count of 1

                   `#+NAME:` above a call names its results.
src_lua{return 1}  Inline block: C-c C-c on it inserts or replaces
                   ` {{{results(=1=)}}}` after it (single-line results).
call_name(n=5)     Inline call, same as above.

Sessions ~
`:session [name]` runs the block in a long-lived interpreter shared by every
block with the same language and name (no name = `default`), so variables,
imports, functions and the working directory persist between blocks.
Supported: shells (sh, bash, zsh, fish), python, js/node, ruby and lua (lua
sessions keep their globals inside Neovim). Other languages ignore
`:session` with a warning.
  - `:results value` is the value of the last expression (python, ruby,
    js) or the returned value (lua); shells use their output unless
    `:results value` is explicit, which gives the exit status.
  - stderr is merged into the output, like an Emacs REPL buffer.
  - Each session has a transcript buffer (`org-babel-session://lang/name`)
    showing what ran; type at its prompt to evaluate a line in the session.
    Wiping that buffer kills the session.
  - The session starts in the block's `:dir`. A top-level `let`/`const` in
    a js session becomes `var`, so blocks can be evaluated again.

Languages: `babel.languages` maps a language name to `{ cmd = "...", ext =
"..." }`. Lua runs inside Neovim. sqlite uses `:db file`.

Header arguments merge in this order: `babel.default_header_args`, then
`#+PROPERTY: header-args[:lang]`, then HEADER-ARGS properties, then
`#+HEADER:` lines, then the `#+begin_src` line.
  :results   output|value; replace|append|prepend|silent;
             verbatim|raw|org|drawer|html|latex|code|list|table|file
  :var       name=value, name="string", name=named-table, name=list,
             name=table[1,2], name=table[1:3,-1] (0-based, ranges,
             negative indices from the end, `[,1]` = a column).
             Like Emacs, a reference to a src block or `#+CALL` evaluates
             it: name=block, name=block(x=1), name=block[:results output]
             (x=1), name=block(x=1)[0]; `name=block[]` is its body text.
             Other forms: file.org:name (another file), an ID or CUSTOM_ID
             (the headline's text), Emacs Lisp literals `'(1 2 3)` and
             simple forms `(+ 1 2)`. Bash gets tables as associative
             arrays and lists as arrays; sqlite replaces `$name` in the
             body (a table becomes a CSV file path). An unknown reference
             is an error.
  :hlines    yes: keep the horizontal lines of table variables (None /
             nil / null in python, ruby, js; "hline" in lua and shells)
  :separator cell separator of tables given to shells (default: tab)
  :stdin     ref: feed a value to the stdin of a shell block
  :session   [name]: see Sessions above
  :colnames  (default) a table variable whose 2nd row is a hline passes
             its first row as column names; they are put back on a table
             result of the same width. `yes` / `no` / `'(a b)` like Emacs
  :rownames  yes: the same for the first column
  :wrap      [type [params]] wrap the result in #+begin_type (default
             `results`), e.g. `:wrap src python`, `:wrap export html`
  :cache     yes: store a hash in `#+RESULTS[hash]:` and skip evaluation
             when the body and arguments did not change
  :file      write the result to the file and insert a link to it (not
             with `:results link` / `graphics`); :output-dir, :file-ext
             (with #+NAME), :file-mode, :sep (for tables)
  :dir :cmdline :prologue :epilogue :noweb-ref  (`:dir` is created
             with `:mkdirp yes`)
  :noweb     yes|no|tangle|eval|no-export|strip-export|strip-tangle|
             tangle-eval. Every <<ref>> of a line is expanded; blocks
             sharing a :noweb-ref are joined with :noweb-sep (default a
             newline); :noweb-prefix no stops repeating the text before
             the reference. `<<name(x=1)>>` inserts the result of
             evaluating the block. Blocks in COMMENT subtrees are skipped.
  :exports   code|results|both|none (for export)
  :results   file without :file: the value is a file name to link
  :tangle    yes|no|path  :mkdirp yes  :shebang "#!/bin/sh"
  :comments  link|org|both  :padline  :tangle-mode  :no-expand
  :post      name(arg=*this*): run the named block on the result; its
             result is inserted instead
Switches: `-i` keeps the indentation of the lines (edit buffer and
tangling), `-n` / `+n` number lines and `-r` / `-l "fmt"` handle coderefs
in export.
Tangled files contain the :var assignments, :prologue and :epilogue, like
Emacs; `-r` removes coderef labels and COMMENT subtrees are skipped.

Results of 10 or more lines (`babel.min_lines_for_block_output`) use an
example block; shorter results use `: ` lines. Value results that look like a
list of lists become a table.

Export: with `babel.evaluate_on_export = true` (Emacs
`org-export-use-babel`) exporting first evaluates, in a copy of the buffer,
the blocks and #+CALL lines with `:exports results|both`, inline src blocks
and calls, and `:exports code|none` blocks that use a session. `:eval
never-export|no-export` blocks keep their existing results. Otherwise export
uses the `#+RESULTS` already in the buffer.

:Org timer_start        Start a relative timer. A count asks for an offset
                        `H:MM:SS` (default: the timer value on the line; a
                        bare number is seconds, `M:SS` minutes); 16 shifts
                        the timer values of the selection instead.
:Org timer_insert       Insert the timer value after the cursor, written
                        with `timer.format` ("%s "). Starts the timer if
                        needed; a count restarts it; 16 shifts the timer
                        values of the selection. During a countdown, the
                        remaining time.
:Org timer_item         Insert a `- 0:01:23 :: ` item: below the current
                        item in a timer list, turning the current line into
                        one elsewhere (an error in other lists).
:Org timer_pause        Pause or continue the timer or countdown.
:Org timer_stop         Stop the timer or countdown.
:Org timer_countdown N  Countdown of N minutes (or `H:MM:SS`, `M:SS`). Without

                        Effort, else a prompt suggesting `timer.default_timer`.

23. ENCRYPTION (ORG CRYPT)                                         *org-crypt*

Encrypt the text of an entry with GnuPG, like Emacs' org-crypt. The `gpg`
command (`crypt.gpg_program`) must be installed and set up. The headline,
planning line, property drawer, clock lines, LOGBOOK drawer and the blank
lines after them stay in clear; the rest of the entry, subtree included, is
replaced by an ASCII-armored message (trailing blank lines stay outside):
>
    * Totally secret                                              :crypt:
    :PROPERTIES:
    :CRYPTKEY: 0x0123456789012345678901234567890123456789
    :END:
    -----BEGIN PGP MESSAGE-----

    jA0ECQMIkNjbrRrbvfn80mABVGV15nu5Iag/HgOzdDr3dtq1HTkNqHu2MN2nc6ow
    ...
    -----END PGP MESSAGE-----
<
The format is the one Emacs writes: files encrypted in either editor
decrypt in the other.

:Org crypt_encrypt_entry     Encrypt the entry at the cursor
                             (org-encrypt-entry). Encrypted entries are
                             left alone.
:Org crypt_decrypt_entry     Decrypt the entry at the cursor
                             (org-decrypt-entry).
:Org crypt_encrypt_entries   Encrypt every entry matching
                             `crypt.tag_matcher` (org-encrypt-entries).
:Org crypt_decrypt_entries   Decrypt every matching entry
                             (org-decrypt-entries).
There are no default keys, as in Emacs; bind the actions in `mappings.org`.
`:Org reveal` (<C-c><C-r>) decrypts the entry at the cursor first, as
org-crypt does through `org-fold-reveal-start-hook`. `*_entries` skip
archived and commented trees, like org-scan-tags.

Keys: `crypt.key = false` encrypts symmetrically, always (Emacs
`org-crypt-key` nil). Otherwise the `CRYPTKEY` property (inherited only
through `use_property_inheritance`; the value `nil` means no key), or else
`crypt.key`, is looked up in the public keyring and every key it matches
becomes a recipient. When nothing matches (`""`, the default, never does)
the entry is encrypted symmetrically. Unchanged decrypted text gets its old
message back when encrypted again, so saving doesn't rewrite it.

Passphrases are read with |inputsecret()| (twice when encrypting) and
passed to gpg on stdin with `--pinentry-mode loopback`; for secret keys
they are asked only when gpg-agent has none cached. During one
`*_entries` run or save the symmetric passphrase is asked once.

Encrypting on save: with `crypt.encrypt_on_save = true`, matching entries
are encrypted before the buffer is written (Emacs
`(org-crypt-use-before-save-magic)`). As in Emacs the buffer stays
encrypted after writing; decrypt again to keep working. When an entry
can't be encrypted the write is aborted.

                                                           *org-crypt-leaks*
Emacs' auto-save files leak decrypted text to disk; in Neovim the swap
file ('swapfile') and a persistent undo file ('undofile') do. Before
decrypting in a buffer that has either, `crypt.disable_auto_save` decides
(org-crypt-disable-auto-save): `"ask"` (default) asks whether to turn both
off for the buffer, `true` turns them off, `false` keeps them with a
warning. `"encrypt"` (re-encrypt before auto-saving) is not possible, as
Neovim has no hook before writing the swap file: it acts like `true`.
Text you yank goes to registers, which 'shada' may save; for files you
always keep encrypted consider an autocmd such as: >lua

    vim.api.nvim_create_autocmd("BufReadPre", {
      pattern = "*/secret/*.org",
      command = "setlocal noswapfile noundofile shada=",
    })
<
Tag inheritance: children inherit `crypt`, so `crypt_encrypt_entries` and
`crypt_decrypt_entries` also visit them (harmless: they are encrypted with
their parent). Emacs recommends `tags_exclude_from_inheritance = { "crypt"
}` to keep the tag on the entries that carry it; like Emacs it is not the
default.

Config (`crypt`): `tag_matcher` "crypt" (a |org-match-syntax| expression),
`key` "" (string or false), `encrypt_on_save` false, `disable_auto_save`
"ask", `gpg_program` "gpg".

32. DIFFERENCES FROM EMACS                                   *org-differences*

- Agenda notes (`z`), clock-out and refile notes are single-line prompts;
  state change and schedule notes use a `*Org Note*` split like Emacs
  (`note_buffer`).
- Table formulas are evaluated as Lua arithmetic instead of Emacs Calc: there
  is no symbolic math. Elisp formulas `'(...)` support common Lisp functions,
  anything else is a Lua expression.
- Tables: width cookies (`<10>`) don't shrink columns, there is no formula
  debugger (C-c {), no orgtbl-mode / radio tables, no table.el tables, and
  <M-CR> inserts a row instead of splitting the field. Table export writes
  TSV or CSV only.
=======
- Notes (state changes with `@`, agenda `z`) are single-line prompts rather
  than a separate note buffer.
- Table formulas: GNU Calc is reimplemented in Lua for what tables use
  (|org-table-calc|); its symbolic algebra (simplification, solving,
  derivatives), units, complex numbers (`sqrt(-4)` stays `sqrt(-4)`
  instead of `(0, 2)`), HMS forms, intervals, error forms and its ~1000
  other functions are not: Calc is a large Emacs package, and results
  here are exact integers, fractions, 12-digit floats, dates or symbolic
  text with only a few simplifications (`x + x` is `2 x`; Emacs's
  `vmean` of symbols is left as `(1 + x + 3) / 3`). Quoted strings
  (`"big"`) are kept as text; Calc makes them vectors of character codes.
  Emacs Lisp formulas `'(...)` run on a small Lisp interpreter (the
  functions listed in `lua/org/table/elisp.lua`): arbitrary Emacs Lisp
  cannot run without Emacs. Any other `'(...)` is a Lua expression.
- Table formula errors: Emacs stops the whole recalculation on some errors
  (a reference outside the table, `$2=` defined twice, unknown remote
  tables); here the field shows #ERROR (the last definition wins) and the
  other fields are still computed. Left sides Emacs rejects are accepted:
  `$name=` for a named column, `$2..$3=` and `@I$2..@>$2=` ranges.
- Tables in the table.el format (`+---+` grids, C-c ~, C-c ' on them) are
  not supported: table.el is a separate large Emacs package; such tables
  are left alone. <M-CR> inserts a row instead of splitting the field.
  Shrunk columns use conceal and virtual text (|org-table-shrink|), the
  header line is drawn in the 'winbar', <C-c>` edits a field in a prompt
  (follow-field mode uses a window) and plots use gnuplot directly (Emacs
  needs gnuplot.el; the radar plot type is missing). The orgtbl-to-unicode
  and orgtbl-to-table.el translators are missing, and translators convert
  Org markup in cells with a simplified exporter.
- Column view in the agenda (org-agenda-columns, C-c C-x C-c in the

- Capture `%(...)`, bulk action `f` and agenda skip functions take Lua
  instead of Elisp.
- Capture edits the text in a separate buffer that is stored at the target
  (resolved when the capture starts) on finalize, instead of an indirect
  buffer narrowed to the text already inserted in the target. So
  `:unnarrowed` (showing the rest of the target file while capturing) is
  not supported, and the target file does not show the new text until the
  capture is finished. Mail and news `%:keyword` values (`%:from`,
  `%:subject`, ...) come from Emacs link sources (Gnus, mu4e, ...) that
  have no Neovim counterpart; only `%:link`, `%:description`,
  `%:annotation`, `%:initial` and `%:type` exist. The last stored location
  (`org-capture-bookmark`, obsolete in Emacs) lasts for the session only.
  `org-extend-today-until` is not applied to capture dates. With C-0
  (`:Org capture_here`) Emacs splits the line at point; the Neovim cursor
  sits on a character, so the text goes before the cursor line at column
  0 and after it otherwise.
- The ID database is JSON, not Emacs's `org-id-locations-file` format, so
  it can't be shared with Emacs. The org-attach git/annex extensions and
  the refile cache (not needed) are not implemented; archiving does not
  loop over a Visual selection (Emacs does only with
  `org-loop-over-headlines-in-active-region`, off by default). Agenda archives-mode and view toggles (`va`, `v[`, ...)
  stay on until toggled off.
- Babel sessions exist for shells, python, js, ruby and lua only, and
  are not full REPLs: each block runs as one request. Export runs code only
  with `babel.evaluate_on_export` (Emacs evaluates by default). `elisp:`
  links and emacs-lisp blocks are not supported; `:var` Lisp forms are
  limited to what the table formula Lisp evaluator implements.
- Export is lenient: broken internal links are rendered in italics instead
  of stopping the export.
- Links (|org-links|):
  - `elisp:` links are not supported: they need an Emacs Lisp interpreter.
    Abbreviations using `%(my-function)` cannot call Elisp either; give
    `links.abbreviations` a Lua function instead.
  - `help:` opens Vim's |:help|: Emacs `help:` links name Elisp functions
    and variables (describe-function), which do not exist here. `info:`
    runs the `info` program in a terminal, `man:` uses |:Man|.
  - Links to Emacs applications (gnus, rmail, mhe, bbdb, irc/erc, eww,
    w3m, bibtex, calendar) can't be followed or stored: there is no such
    application in Neovim. `docview:` opens the file.
  - `shell:` runs in a terminal window instead of collecting the output in
    an `*Org Shell Output*` buffer; `links.confirm_shell` asks with a y/n
    prompt.
  - `::/regexp/` searches translate the common Emacs regexp syntax to Vim
    regexps; Emacs-only constructs (syntax classes other than whitespace
    and words, categories, backward references to point) are approximated
    or unsupported.
  - Internal links followed with a count open in another window on the same
    buffer; there are no indirect buffers
    (org-link-use-indirect-buffer-for-internals), and Vim folds are per
    window anyway.
  - Files Neovim cannot display (images, media, office documents, PDF,
    HTML) open with the system application, where Emacs opens images and
    office documents itself (org-file-apps); `links.file_apps` overrides it.
  - Storing an `id:` link before the first heading stores a `file:` link:
    no file-level ID property drawer is created.
  - Emacs wildcard file links (`file:*.org`) do not open a directory
    listing of the matches.

  - diary sexps `<%%(...)>`
  - MobileOrg (org-mobile): the MobileOrg apps are unmaintained and the
    staging/sync protocol is tied to Emacs; sync the files with any file
    sync tool instead.
  - inline image and LaTeX previews: core Neovim has no image protocol
    (org-link-preview, org-toggle-inline-images, org-image-max-width,

- <M-CR> never splits the current line.
