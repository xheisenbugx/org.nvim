1. INTRODUCTION                                             *org-introduction*

org.nvim implements Emacs Org mode in pure Lua. It reads and writes the same
plain-text format, so files can be shared with Emacs.

It covers the parts of Org you use every day:

  - Outlines with Emacs-style folding, cycling, motions and text objects.
  - TODO workflows with logging, repeaters, priorities, tags and properties.
  - An agenda with a time grid, habits, custom commands and bulk actions.
  - Capture templates that file notes from any buffer.
  - Clocking, effort estimates, clock tables and column view.
  - Spreadsheet tables with `#+TBLFM` formulas.
  - Source blocks that run asynchronously (Babel), and tangling.
  - Export to HTML, LaTeX/PDF, Beamer, Markdown, ASCII, Org and iCalendar,
    publishing projects, plus more formats via pandoc.

There are no dependencies: no tree-sitter parser, external binary or
companion plugin.

Quick start:                                              *org-quickstart*

  1. Open `~/org/todo.org` and type `* TODO Buy milk`.
  2. Press `<prefix>s` to schedule it for today.
  3. Press `<prefix>a` then `a` to open the weekly agenda.
  4. Press `<prefix>c` then `t` in any buffer to capture a task.
  5. Press `g?` to list every keymap.

For a hands-on tour, open `examples/tutorial.org` from the plugin
directory. It has a section with exercises for every feature. To try it
with a throwaway config (agenda and capture included), run from the plugin
directory: >sh
    nvim -u examples/minimal_init.lua examples/tutorial.org
<

Conventions used in this manual:

  <prefix>    The value of `mappings.prefix` (default `<leader>o`).
  (ctx)       A context-sensitive key. When it does not apply at the cursor,
              the key falls back to its normal Vim behaviour (for example
              `>>` indents plain text and `<C-a>` increments numbers).
  target      Many Lua functions accept `{ bufnr = n, lnum = l }` to act on
              a headline other than the one at the cursor.

Press `g?` in an org or agenda buffer for a list of active keymaps.

2. INSTALLATION                                             *org-installation*

Requires Neovim 0.10 or later. Optional tools:

  pandoc               LaTeX, PDF, DOCX, ODT, EPUB, RST, ... export
  latexmk / pdflatex   native PDF export
  interpreters         whatever languages Babel should run

lazy.nvim / LazyVim: >lua
    {
      "xheisenbugx/org.nvim",       -- or: dir = "~/path/to/checkout", name = "org.nvim"
      main = "org",
      lazy = false,
      opts = {
        org_directory = "~/org",
        agenda_files = { "~/org/**/*.org" },
        default_notes_file = "~/org/refile.org",
      },
    }
<
Other plugin managers: add the plugin to 'runtimepath' and call: >lua
    require("org").setup({ ... })
<

Option defaults follow Emacs Org 9.8 (see |org-config|): with no
`agenda_files` the agenda and refile see only the current file until you
add some (`<C-c>[` adds the current file), `todo_keywords` is `TODO | DONE`,
nothing is logged on DONE and files open fully expanded. A common starting
point closer to many Emacs setups: >lua
    require("org").setup({
      agenda_files = { "~/org" },
      default_notes_file = "~/org/refile.org",
      todo_keywords = { "TODO(t) NEXT(n) | DONE(d)" },
      log_done = "time",
      log_into_drawer = true,
      startup_folded = "overview",
    })
<
If `setup()` is never called, the defaults are used the first time an org
buffer is opened or `:Org` is run.

Run |:checkhealth| `org` to check paths and external tools. Inside tmux or
Ghostty it also checks that the terminal can send the keys org maps: <C-CR>,
<S-CR>, <C-,> and the like need extended keys (CSI u), which tmux passes on
only with `set -s extended-keys on` and a `terminal-features` entry with
`extkeys` for the outer terminal (read when a client attaches). In Ghostty it
also looks for keybinds that take a mapped key (e.g. the default
`ctrl+tab=next_tab`) and, on macOS, for `macos-option-as-alt` (needed by the
<M-...> keys).

3. DOCUMENT STRUCTURE                                          *org-structure*

Headlines start with one or more stars followed by a space (a line of
stars alone is text, like in Emacs): >org
    * TODO [#A] Headline text                              :tag1:tag2:
      SCHEDULED: <2026-09-23 Wed> DEADLINE: <2026-09-30 Wed>
      :PROPERTIES:
      :ID:       0c7a...
      :END:
      Body text.
    ** Child headline
<
                                                          *org-meta-return*
<M-CR>          (ctx) Insert a new headline, list item or table row, then
                enter Insert mode, like org-meta-return:
                - In Insert mode it acts at the cursor: at the start of a
                  headline the new one goes above it; in the title the
                  rest of the title moves to the new headline (the tags
                  stay); at the start of a text line that line becomes a
                  headline; elsewhere in a line the line is split. In a
                  list, at or before the item text the new item goes
                  before it; elsewhere the rest of the item (and its
                  sub-items) moves to the new item.
                  `meta_return_split_line` (org-M-RET-may-split-line)
                  turns splitting off: `false`, or per context
                  `{ headline = false, item = true }`.
                - In Normal mode it acts at the end of the line without
                  splitting it (in column 0 of a headline or text line:
                  at its start). So on a headline the new one goes right
                  below the headline line, in a list after the item and
                  its sub-items (also in column 0; use `i<M-CR>` there
                  for an item before it).
                - A folded headline gets the new one after its subtree.
                - With a count (C-u, `4<M-CR>`): always a headline, after
                  the current subtree; `16<M-CR>` (C-u C-u): at the end of
                  the parent's subtree.
                New headlines get a blank line before them when the
                current one has one (`blank_before_new_entry.heading =
                "auto"`); new items when the items of the list are
                separated by blank lines (`plain_list_item = "auto"`).
<M-S-CR>        Like <M-CR>, but a TODO headline (with the keyword of the
                current entry, or the first one when it is done or with
                a count) or an item with an empty checkbox. M-RET never
                copies a checkbox.
<prefix>ih      Insert headline after the current subtree
<C-CR>          (org-insert-heading-respect-content). Before the first
                headline, after the text.
<prefix>it      Insert TODO headline after the subtree
<C-S-CR>        (org-insert-todo-heading-respect-content).
<C-c><CR>       (ctx) Outside tables: insert a headline like <M-CR>.
<prefix>is      Insert a subheading: a headline below the current line,
                demoted (org-insert-subheading). In a list: an item,
                indented.
<prefix>id      Insert a drawer at the cursor (Insert mode splits the line,
<C-c><C-x>d     like Emacs), or around the Visual selection. With a count
                (C-u), a property drawer.
<prefix>ib      Insert a structure template (org-insert-structure-template):
<C-c><C-,>      `#+begin_TYPE` / `#+end_TYPE` around the selection, or an
                empty block at the cursor; the cursor goes inside, or
                after `#+begin_src ` to type the language. Types come from
                `structure_template_alist` (a export ascii, c center,
                C comment, e example, E export, h export html, l export
                latex, q quote, s src, v verse); TAB asks for any type,
                written in upper case for #+BEGIN_/#+END_.
                                                              *org-tempo*
<s<Tab>         With `tempo = true` (the org-tempo module), `<` plus a key
                of `structure_template_alist` then <Tab> in Insert mode
                expands to that block; `<L`, `<H`, `<A`, `<i`
                (`tempo_keywords`) to `#+latex: `, `#+html: `, `#+ascii: `,
                `#+index: `, and `<I` asks for a file to `#+include:`.

                                                       *org-promote-demote*
<< / >>         (ctx) Promote / demote headline or list item. Count repeats.
<s / >s         (ctx) Promote / demote the whole subtree or item and its
                children.
<M-h> / <M-l>   (ctx) Promote / demote. In a table: move column.
<M-Left> / <M-Right>  Same as <M-h> / <M-l> (Alt + arrow keys).
<M-H> / <M-L>   (ctx) Promote / demote subtree. In a table: delete / insert
                column. Elsewhere an error, like Emacs.
<M-h> / <M-l>   In Visual mode: promote / demote every headline of the
                selection, or outdent / indent every item.
Promotion keeps the spacing of the headline and realigns its tags. With
`odd_levels_only` (`#+STARTUP: odd`, org-odd-levels-only) the level changes
by two.

List items follow org-list rules: an item with children cannot be outdented
alone (use <M-H>), the first item of a list cannot be indented alone, and
<M-L> / <M-H> on the first item move the whole list. A `*` bullet that
reaches column 0 becomes `-`. After each change the list is repaired:
numbers, bullets of siblings, sub-list indentation, parent checkboxes.

                                                          *org-move-subtree*
<M-k> / <M-j>   (ctx) Move subtree, list item or table row up / down; a
<M-Up> / <M-Down>  count moves past that many siblings. Elsewhere, drag the
                element (paragraph, block, drawer, table...) past the
                previous / next one, keeping blank lines in place
                (org-drag-element-backward / forward). In Visual mode:
                move the selected subtrees past the previous / next sibling
                when the selection starts at a headline, else move the
                selected lines.
<prefix>K / J   Move subtree up / down.
<M-K> / <M-J>   (ctx) Outside tables: drag the line at the cursor up / down
                (org-drag-line-backward / forward). Count repeats.

                                                         *org-kill-subtree*
<prefix>hy      Copy subtree (count: that many siblings).
<prefix>hd      Cut subtree.
<prefix>hp      Paste subtree like org-paste-subtree: in column 0 of a
<C-c><C-x><C-y> headline, before it with its level; elsewhere before the
                next visible headline, at the deeper level of the visible
                headlines before and after. On an empty headline (`***`)
                its stars give the level. Count 4 (C-u): after the current
                subtree at its level; 16 (C-u C-u): as the first child;
                other counts: that level. A subtree that was folded when
                copied is pasted folded. Subtrees are kept in a kill ring
                and also in the `"` register.
<prefix>hc      Clone subtree N times (org-clone-subtree-with-time-shift),
<C-c><C-x>c     shifting its timestamps by an offset per clone (`+1w`,
                `-2d`, `+3h`; asked only when it has timestamps, and not
                with a count). Clones lose CLOCK lines and get a new ID, or
                none with `clone_delete_id`. With a repeating timestamp,
                the copies lose the repeater and one more copy after them
                keeps it.

                                                                 *org-sort*
<prefix>hs      Sort the children of the current headline, the top-level
<C-c>^          entries before the first headline, the entries of the
                Visual selection, or the list at the cursor. Entry keys:
                a alpha, n numeric (a missing number is 0), p priority,
                r property (compared as text), o TODO order (open
                keywords, then none, then done), f function, t time
                (first active timestamp, else inactive), s scheduled,
                d deadline, c created (first inactive timestamp at the
                start of a line), k clocking time; missing dates count as
                now. List keys: a, n, t, f, x (checkbox). Uppercase
                reverses; a count (C-u) makes it case-sensitive. For `f`,
                give a name from `sort_functions` or a Lua expression
                returning a function(entry, lines), then optionally a
                compare function.

                                                               *org-narrow*
<prefix>hn      Narrow to subtree: edit it in a separate buffer. `:w` writes
                back and <C-c>' saves and closes.
<prefix>nb      Narrow to the block at the cursor (org-narrow-to-block).
<prefix>ne      Narrow to the element at the cursor (org-narrow-to-element).

                                                        *org-cycle-level*
<Tab>           (Insert mode) On a new empty headline, cycle its level:
                child of the previous entry, then up the hierarchy, then
                back (org-cycle-level). On an empty list item, indent it
                under the previous item, then outdent it level by level,
                then back to where it started (org-cycle-item-indentation).
                So `<M-CR><Tab>` makes a subheading. In a table: next field.
                Elsewhere: a tab.

<prefix>*       Toggle headline (org-toggle-heading): headline → text,
<C-c>*          item → headline one level below the entry (checkboxes
                become TODO / DONE), text line → headline. In Visual mode,
                every line; with a count on text, only the first line.
<prefix>-       Toggle list item (org-toggle-item): item → text (the
<C-c>-          checkbox stays), headline → item (TODO → checkbox, tags,
                planning and properties dropped, and in Visual mode the
                text of each entry moves into its item), text → item. With
                a count, the selection becomes one item.
<C-c><C-*>      Turn the list at the cursor into a subtree
                (org-list-make-subtree).
<prefix>hC      Toggle the COMMENT keyword.
<prefix>E       Emphasize (org-emphasize): wrap the Visual selection in a
<C-c><C-x><C-f> marker, replacing one already there (a space removes it);
                without a selection, insert a pair and type between them.
<C-c>:          Toggle fixed-width markup `: ` (org-toggle-fixed-width) on
                the line or the Visual selection.

Motions and text objects:                           *org-motions* *org-textobj*
]] / [[         Next / previous visible headline.
][ / []         Next / previous sibling.
g{              Parent headline.
<prefix>.       Pick a headline of the buffer (|vim.ui.select()|).
ih / ah         Headline section without / with the headline line.
ir / ar         Subtree without / with the headline line.

Elements                                                    *org-elements*
Paragraphs, lists and items, blocks, drawers, tables, fixed-width areas,
keywords and comments are elements; blank lines after one belong to it.
Commands work on whole lines: on the first line of a list item they act on
the item.
<M-}> / <M-{>   Next / previous element at the same level
                (org-forward-element / org-backward-element); on a
                headline, the next / previous sibling.
<C-c><C-^>      Up to the parent element, or the headline (org-up-element).
<C-c><C-_>      Down to the first element inside (org-down-element).
<prefix>v       Select the element (org-mark-element); again in Visual
                mode to add the next one. Emacs binds it to M-h, which is
                <M-h> (promote) here.
<C-M-t>         Swap the element with the previous one and move after both
                (org-transpose-element).
<C-c><M-f>      Next / previous `#+begin_` block (org-next-block /
<C-c><M-b>      org-previous-block); a count skips blocks.

                                                        *org-inlinetask*
Inline tasks (the org-inlinetask module, off like in Emacs): with
`inlinetask_min_level = 15`, headlines of that level or deeper are TODO
items inside the text of an entry, optionally closed by an END line: >org
    * Entry
    *************** TODO Call Bob
    Details.
    *************** END
<
They are not entries of their own (the text around them belongs to the
entry), fold up to END with <Tab>, promote / demote together with their END
line (never below the minimum level) and show only their last two stars.
<C-c><C-x>t     Insert an inline task (`inlinetask_default_state` as its
                keyword unless a count is given), around the Visual
                selection if any.

                                                      *org-speed-commands*
Speed commands (org-use-speed-commands, off by default): with
`use_speed_commands = true`, a letter typed in Insert mode at the very start
of a headline (before the stars) runs a command instead of being inserted:
n p f b u next / previous / next sibling / previous sibling / parent
headline, F B next / previous block, j go to heading, g refile goto, c C
cycle / global cycle, SPC outline path, s narrow, k cut subtree, = column
view, U D move subtree, r l R L demote / promote (subtree), i insert heading,
^ sort, w refile, a archive, @ select subtree, # COMMENT, I O clock in / out,
t TODO, , priority (0 remove, 1 2 3 highest, default, lowest), : tags,
e E effort, W APPT_WARNTIME, v agenda, / sparse tree, o open link,
< > agenda restriction lock, ? help. `speed_commands` adds or changes keys:
`{ x = "archive_subtree", n = false }`. `use_speed_commands` may also be a
function deciding where they apply.

4. VISIBILITY AND FOLDING                                        *org-folding*

Headlines fold by level. Plain list items with sub-items or more lines fold
one level deeper (`cycle_include_plain_lists`, org-cycle-include-plain-lists),
and drawers and `#+begin_`/`#+end_` blocks one level deeper than what
contains them. When the text before a headline ends with at least
`cycle_separator_lines` (2) blank lines, the last one stays visible when the
subtree above is folded (org-cycle-separator-lines).

<Tab>           (ctx) Subtree cycling like org-cycle: a folded subtree
                shows its text and its children (CHILDREN); right after
                that, <Tab> shows the whole subtree (SUBTREE); otherwise it
                folds it (FOLDED). A subtree without children goes from
                FOLDED to SUBTREE. On a list item, the same with its
                sub-items. On a drawer, block or inline task line, toggle
                that fold. On text, indent the line like org-indent-line
                (`cycle_emulate_tab`, org-cycle-emulate-tab: `true`,
                `"white"`, `"whitestart"`, `"exc-hl-bol"`; `false` cycles
                the entry instead). In Insert mode inside a table, move to
                the next field.
                With a count (in place of C-u): `16<Tab>` restores the
                startup visibility, `64<Tab>` shows everything including
                drawers, and any other N shows the whole subtree of the
                ancestor at level N.
<S-Tab>         Global cycling: OVERVIEW → CONTENTS (headlines only) →
                SHOW ALL. With a count N, show headlines up to level N.
<C-c><Tab>      Show the children of the entry (a count: that many levels)
                without showing its text (org-show-children).
<C-c><C-k>      Show every headline of the subtree, without their text
                (show_branches).
<C-c><C-r>      Show the context of the cursor (org-reveal): the headlines
                above it, their children and the current entry. A count 4
                (C-u) also shows the text of the headlines above; 16 the
                parent's whole subtree.
<C-c><C-Tab>    Cycle the subtree even when it is archived
                (`:Org force_cycle_archived`).
<C-c><C-x>v     Copy the visible text (org-copy-visible).

                                                        *org-hidden-lines*
Vim folds nest, so a fold that is open shows every line in it: they cannot
show the child headlines of an entry while hiding its own text, as the Emacs
CONTENTS view, <C-c><Tab>, <C-c><C-k>, `#+STARTUP: content` and
`show2levels`, and a `VISIBILITY: content` property do, nor hide the
siblings of a sparse-tree match. Those lines are hidden with `conceal_lines`
extmarks (Neovim 0.11 or later, 'conceallevel' 2, set by the plugin), and
the headline gets the ellipsis. Hidden lines are never under the cursor:
<j> / <k> skip them and other jumps show them (like Emacs, which never
leaves point in invisible text). Typing on a hidden line follows
`catch_invisible_edits` (org-fold-catch-invisible-edits): `"smart"` (the
default) and `"show-and-error"` show the line and refuse the character,
`"show"` shows it and types, `"error"` refuses, `false` types into it.
Hidden lines are shared by the windows showing the buffer (like Emacs
invisible text), while folds are per window. Vim's own fold commands (zo,
zR, ...) don't show hidden lines; the org commands above do. Neovim 0.10
cannot hide lines: the text of those entries stays visible and sparse trees
also show the siblings of the matches.

Startup visibility comes from `#+STARTUP:` (`overview`, `content`,
`showall`, `show2levels` … `show5levels`, `showeverything`, `nofold`),
falling back to the `startup_folded` option. Drawers are then folded
(`hidedrawers`, off with `nohidedrawers` or `hide_drawer_startup = false`)
and so are blocks with `hideblocks` (or `hide_block_startup = true`).
Except with `showeverything`, a `VISIBILITY` property (`folded`,
`children`, `content`, `all`) then sets the visibility of its subtree.

                                                        *org-archived-trees*
Subtrees tagged `:ARCHIVE:` stay folded when you cycle (TAB, S-TAB, the
startup visibility), like Emacs `org-cycle-open-archived-trees = nil`. Use
<C-c><C-Tab> to open one anyway, or set `cycle_open_archived_trees = true`.

`:Org overview`, `:Org content`, `:Org show_all`, `:Org show_everything`
and `:Org set_startup_visibility` set the visibility explicitly.

Vim's linewise commands act on a closed fold as a whole (`dd` on a folded
headline deletes the subtree, `>>` indents all of it); Emacs edits only the
visible headline. That is Vim's fold semantics and is not caught.

5. PLAIN LISTS AND CHECKBOXES                                      *org-lists*

Unordered bullets are `-`, `+` and indented `*`. Ordered bullets are `1.` and
`1)`. `[@N]` sets a counter. Description items look like `- term :: text`.
Checkboxes are `[ ]`, `[-]` (partial) and `[X]`. Lines inside example,
src, export and verse blocks are never items (org-list-forbidden-blocks).

<C-c><C-c>      On the first line of an item: toggle its checkbox and repair
                the list (numbers, bullets, sub-list indentation, parent
                checkboxes). A parent checkbox follows its children, so
                toggling it is refused ("Cannot toggle this checkbox"). A
                count 4 (C-u) adds or removes the checkbox, 16 (C-u C-u)
                sets `[-]`. Without a checkbox, it only repairs the list.
                With `ORDERED: t`, boxes after an unchecked one stay
                unchecked. On other lines of an item: nothing.
<C-Space>       Toggle checkboxes (org-toggle-checkbox): the item at the
<C-c><C-x><C-b> cursor, every item of the Visual selection (following the
                first one), or on a headline every item of its text. Items
                without a checkbox are left alone; with a count of 4
                (C-u) checkboxes are added or removed, 16 (C-u C-u) sets
                `[-]`.
                                                          *org-radio-list*
<C-c><C-x><C-r> Toggle a radio button: check this item, uncheck its
                siblings (org-toggle-radio-button). In a list preceded by
                `#+attr_org: :radio t`, <C-c><C-c> and <C-Space> do this.
<S-Up/Down>     (ctx) On an item: previous / next item of the same level
                (org-previous-item / org-next-item).
<S-Right/Left>  (ctx) On an item: cycle the bullet style.
<C-c>-          (ctx) On an item: cycle the bullet style; elsewhere toggle
                items (|org-structure|).
<prefix>hb      Cycle the bullet style.
<prefix>#       Update the statistics cookies of the current entry
<C-c>#          (org-update-statistics-cookies): on a headline with child
                entries, its TODO cookie; with a count (C-u), every cookie
                of the buffer.

Statistics cookies on a headline count its checkboxes, or its child TODO
entries when it has no checkboxes. `:COOKIE_DATA: todo|checkbox recursive`
overrides this.

6. TODO ITEMS AND PRIORITIES                               *org-todo* *org-priority*

Keywords are defined with `todo_keywords` or per file with `#+TODO:` lines.
Each string is a sequence, and keywords after `|` are done states: >lua
    todo_keywords = {
      "TODO(t) NEXT(n) | DONE(d!)",
      "WAITING(w@/!) | CANCELLED(c@)",
    }
<
In `(x!/@)`, `x` is the fast-selection key, the first flag applies when
entering the state and the flag after `/` applies when leaving it: `!` logs a
timestamp and `@` asks for a note. Log entries go into the `log_into_drawer`
drawer (default none: under the headline, like Emacs; `true` = `LOGBOOK`), or
the drawer named by the inherited
`LOG_INTO_DRAWER` property (`nil` logs under the headline);
`#+STARTUP: logdrawer / nologdrawer` also switch it. The headings of the log
entries come from `log_note_headings` (org-log-note-headings). Notes are
typed in a small `*Org Note*` split, like Emacs: <C-c><C-c> stores the note
(lines starting with "# " are dropped), <C-c><C-k> cancels it
(`note_buffer = false` asks with a one-line prompt instead).

cit / ciT       Next / previous TODO state.
<S-Right/Left>  (ctx) Same, on a headline. Like Emacs, this walks every
                keyword of every sequence in order, with no keyword before
                the first and after the last one.
<prefix>T       Select a state (fast keys when defined).
<C-c><C-t>      Fast selection when the keywords have keys (turn it off
                with `use_fast_todo_selection = false`), otherwise cycle
                within the sequence: after its last keyword the headline
                has no keyword, and the next C-c C-t goes back to the
                first keyword of that same sequence. The count is the
                Emacs prefix argument:
                  4 (C-u)          take a note for this change
                  16 (C-u C-u)     switch to the next keyword set
                  64 (C-u C-u C-u) ignore blocking (dependencies)
                  N                switch to the Nth keyword
                In Visual mode every headline of the selection changes.
<C-S-Right/Left>  Next / previous keyword set (not logged, like Emacs).
:Org todo_without_note   Change the state, recording a time instead of
                asking for a note (C-0 C-c C-t).
:Org todo_cancel_repeaters   Set the repeaters of the entry to 0 and change
                the state, so a repeating task is done for good
                (C-- 1 C-c C-t, org-cancel-repeaters).

                                                     *org-loop-over-headlines*
In Visual mode, <C-c><C-t>, <C-c><C-s> and <C-c><C-d> act on every headline
of the selection, skipping headlines hidden in closed folds
(`loop_over_headlines_in_active_region`: true, false or "start-level" for
only the headlines at the level of the first one).

Entering a done state adds `CLOSED: [timestamp]` when `log_done` is set, and
going back to a TODO state removes it. Like Emacs, CLOSED is only touched
when some logging is set up (`log_done` or a keyword with `!`/`@`);
`closed_keep_when_no_todo` keeps it when the keyword is removed. With
`use_effective_time`, times recorded before `extend_today_until` o'clock
are 23:59 of the previous day.

                                                        *org-logging-property*
The inherited `LOGGING` property overrides the logging of a subtree, like
Emacs: `:LOGGING: nil` turns it off, `:LOGGING: lognotedone logrepeat`
selects done/repeat logging, and keyword specs such as `WAIT(@) DONE(!)`
replace the flags of the keyword definitions.

                                                      *org-todo-tags-triggers*
`todo_state_tags_triggers` adds or removes tags on state changes. Keys are
keywords, `todo` (any not-done state), `done` or `""` (no keyword): >lua
    todo_state_tags_triggers = {
      WAITING = { WAITING = true },
      done = { WAITING = false },
      [""] = { WAITING = false },
    }
<
                                                             *org-todo-events*
Every state change fires the User autocmd `OrgTodoStateChange` (Emacs
org-after-todo-state-change-hook and org-trigger-hook), and a repeating task
marked done also fires `OrgTodoRepeat` (org-todo-repeat-hook). `data` holds
`bufnr`, `lnum`, `from`, `to` (the final keyword), `state` (the keyword
chosen), `done` and `repeated`: >lua
    vim.api.nvim_create_autocmd("User", {
      pattern = "OrgTodoStateChange",
      callback = function(ev) print(ev.data.from, "->", ev.data.to) end,
    })
<
`todo_blockers` is a list of functions (org-blocker-hook); each receives
`{ type = "todo-state-change", from, to, bufnr, lnum }` and blocks the
change by returning `false`.

Repeated tasks                                            *org-repeat*
A SCHEDULED or DEADLINE timestamp with a repeater (`+1w`, `++1d`, `.+2d`)
is shifted when the task is marked done, and the task returns to the first
keyword of its sequence, like Emacs. The `REPEAT_TO_STATE` property or
`todo_repeat_to_state` (a keyword, or `true` for the previous state) choose
another state. A SCHEDULED date without a repeater is removed. The state
change is logged and `LAST_REPEAT` set when `log_repeat` is enabled
(`LAST_REPEAT` is also set when the entry has clock lines).
  +N   shift by N units once
  ++N  shift until the date is in the future, keeping the weekday
  .+N  shift to N units after today
Months keep the day of the month and roll over like Emacs: `<2026-01-31
+1m>` becomes `<2026-03-03>`.

Dependencies                                              *org-todo-dependencies*
With `enforce_todo_dependencies`, an entry cannot be marked done while its
children are unfinished, or while earlier siblings under an `:ORDERED: t`
parent are unfinished, or while an ancestor TODO is blocked that way. A
`NOBLOCKING` property disables blocking for the entry.
`enforce_todo_checkbox_dependencies` also blocks entries that have
unchecked or partial checkboxes (not the ones inside blocks).

Statistics                                               *org-todo-statistics*
A `[/]` or `[%]` cookie on a headline counts its children with a TODO
keyword. `provide_todo_statistics` chooses what counts (org-provide-todo-
statistics): `true`, `"all-headlines"`, a list of keywords, or
`{ todo_keywords, done_keywords }`; `false` stops updating cookies when a
state changes. `hierarchical_todo_statistics = false` counts the whole
subtree instead of the direct children (`:COOKIE_DATA: recursive` does it
for one entry).

Priorities
<S-Up> / <S-Down>   (ctx) Raise / lower priority on a headline. Past the
                    highest or lowest priority the cookie is removed; the
                    next shift in the same direction wraps around to the
                    other end, like Emacs.
<C-a> / <C-x>       (ctx) Same, with the cursor on the `[#A]` cookie.
<prefix>,           Set priority (press a letter, <Space> removes it). With
                    a count of 4 (C-u C-c ,), show the priority value.
:Org priority_show  Show the priority as Emacs computes it for sorting,
                    1000 × (lowest - priority) (org-priority-show).
Range and default come from `priority_highest/lowest/default` or
`#+PRIORITIES: A C B`. Numbers from 0 to 64 work too, like Emacs:
`#+PRIORITIES: 1 10 5` uses `[#1]` .. `[#10]` (typed as a number).
`ui.priority_faces` gives priorities their own highlight, like
`ui.todo_keyword_faces`.

7. TAGS                                                             *org-tags*

Tags sit at the end of the headline: `:work:urgent:`. They contain letters,
digits, `_`, `@`, `#` and `%` (org-tag-re); `:a-b:` is not a tag.

<prefix>t       Set tags. When some tag has a fast key (`#+TAGS: work(w)
                home(h)` or the `tags` option), a key menu is shown
                (org-fast-tag-selection); otherwise you type the tags with
                completion.
<C-c><C-c>      On a headline: set tags.
N<prefix>t      With a count (C-u C-c C-q): realign the tags of every
                headline. A count of 16 (C-u C-u) types the tags with
                completion even when they have keys.
{Visual}<prefix>t  Add or remove one tag on every headline of the selection
                (org-change-tag-in-region).
<C-c><C-x>q     Toggle tag groups in matches (org-toggle-tags-groups).

                                                      *org-fast-tag-selection*
In the fast selection menu, like Emacs:
  a key         toggle that tag (tags without a key get one: their first
                letter after a leading `@` when it is free, else the first
                free character of a-z A-Z { | } ~)
  <Tab>         add or remove one tag by completion
  <Space>       remove all tags
  <CR>          accept
  !             toggle the exclusivity of `{ }` groups
  <C-c>         toggle "exit after the next change"
  q <Esc> <C-g> cancel (`q` only when it is not a tag key)
The new tags are in the order of the tag table, followed by the other
tags. `fast_tag_selection_single_key` exits after one change (`true`) or
also hides the menu until <C-c> (`"expert"`);
`fast_tag_selection_include_todo` adds the TODO keywords with keys, which
change the state right away.

Completion offers the tags defined for the buffer (`#+TAGS` or the `tags`
option), or the tags used in the buffer when none are defined;
`complete_tags_always_offer_all_agenda_tags` adds every agenda file's tags.

Tags are aligned to `tags_column` (negative values right-align them, a
positive value starts them at that column). `:Org align_tags` realigns every
headline in the buffer. `ui.tag_faces` gives tags their own highlight.

In `#+TAGS`, `{ }` groups are mutually exclusive in the fast selection menu,
`[ ]` groups and `\n` start a new row, and `:` (as in `[ GTD : Control ]`)
separates a group tag from its members.
                                                              *org-tag-groups*
A group tag also matches its members in tag searches and sparse trees
(org-group-tags, `group_tags`): with `#+TAGS: [ GTD : Control Persp ]`, the
match `GTD` finds entries tagged GTD, Control or Persp, and `-GTD` excludes
all three. Groups nest, and `{regexp}` members match tags by regexp:
`[ Project : {P@.+} ]`. <C-c><C-x>q turns this off and on.

Inheritance: children inherit their parents' tags and `#+FILETAGS:`, except
the tags in `tags_exclude_from_inheritance`. Set `use_tag_inheritance =
false` to disable it, or to a list of tags or a regexp to inherit only those
tags (org-use-tag-inheritance).

8. PROPERTIES AND COLUMN VIEW                   *org-properties* *org-columns*

<prefix>p       Set a property. Names are completed, and values come from
                `PROP_ALL` properties when available. Before the first
                headline, the file-level property drawer at the top of the
                file is set (created after leading comments).
<C-c><C-x>P     Set a property from one `PROPERTY: value` answer
                (org-set-property-and-value); a count reuses the last one.
<prefix>P       Delete a property (and its `PROPERTY+` lines).
<S-Right/Left>  (ctx) On a property line: next / previous allowed value
                from `PROP_ALL` (org-property-next-allowed-value).
<C-c><C-c>      (ctx) On a property line: menu to set the value, delete it
                here or delete it from all entries (org-property-action).
`:Org delete_property_globally` removes a property from every entry of the
buffer.
<prefix>xe      Set the Effort property (stored as typed, e.g. `1h`).
<prefix>lI      Create an ID property (or show the existing one).

Property lines are written with `property_format` (org-property-format,
`"%-10s %s"`): `:Owner:    me`; an empty value leaves `:Owner:`.

Setting the special properties TODO, PRIORITY, SCHEDULED or DEADLINE
changes the headline instead (an empty value removes them), like Emacs
org-entry-put; the other special properties cannot be set. Every change
through <prefix>p fires the User autocmd `OrgPropertyChanged` with `data`
`{ bufnr, lnum, name, value }` (org-property-changed-functions).

Special properties available in matches and column view: ITEM, TODO,
PRIORITY, TAGS, ALLTAGS, CATEGORY, LEVEL, FILE, SCHEDULED, DEADLINE, CLOSED,
TIMESTAMP, TIMESTAMP_IA (first inactive timestamp), BLOCKED (`t` when the
entry cannot be marked done, else empty).

Inheritance is controlled by `use_property_inheritance` (true, false, a
list of property names, or a regexp matching them). `NAME+` lines append to the value, also to an
inherited one: `:Acc: 1` on a parent and `:Acc+: 2` on its child give
`1 2`. A property drawer at the top of the file, `#+PROPERTY: NAME value`
and `global_properties` set values for the whole file, in that order.

<prefix>C       Column view. The format comes from `#+COLUMNS`, the COLUMNS
                property or `columns_default_format`, for example
                `%25ITEM %TODO %3PRIORITY %TAGS %Effort{:}`. Summary
                operators (org-columns-summary-types-default): {+} (sum,
                printed like Emacs: `4.1`, `6`), {$} (2 decimals), {min}
                {max} {mean} (mean is always a float: `3.0`), {:} {:min}
                {:max} {:mean} (durations, in `duration_format` unless all
                values are H:MM), {X} {X/} {X%} (checkboxes), {@min} {@max}
                {@mean} (ages of timestamps), {est+} (low-high estimates).
                A format after `;`, `{+;%.1f}`, is applied to every value
                of the column, leaves included. `columns_summary_types`
                adds operators: `{ ["+|"] = function(values, fmt) ... end }`
                (or `{ summarize, collect }` where `collect(headline,
                prop)` gives a headline's value).
                Like Emacs (org-columns-compute-all), opening column view
                and updating a columnview block write each computed
                summary into the entry's property when the entry already
                has that property (even empty) and its value differs.
                SCHEDULED, DEADLINE and TIMESTAMP show as inactive
                timestamps; `columns_modify_value_for_display_function`
                (`function(title, value)`) can change any shown value.
                Keys in the view:
                  e               edit the value (TODO, tags, dates, ...)
                  n / p           next / previous allowed value (also
                                  <S-Right> / <S-Left>): `PROP_ALL`, TODO
                                  keywords, priorities, checkboxes
                                  (`columns_checkbox_allowed_values`), days
                  1 .. 9          select the Nth allowed value (digits are
                                  not counts in the view)
                  a               edit the allowed values (`PROP_ALL`)
                  < / >           narrow / widen the column
                  <M-h> <M-l>     move the column left / right (also
                                  <M-Left> / <M-Right>)
                  <M-L> / <M-H>   add a column / delete it (also
                                  <M-S-Right> / <M-S-Left>)
                  s               edit the column's attributes
                  <M-k> <M-j>     move the entry up / down (also <M-Up> /
                                  <M-Down>)
                  <C-c><C-c>      toggle a checkbox value, else quit
                  <C-c><C-t>      change the TODO state
                  <C-c><C-o>      open the link in the field
                  v view value, <CR> jump, r refresh, q quit.
                Format changes are saved to the COLUMNS property or the
                `#+COLUMNS:` line the view comes from.

9. DATES AND TIMES                                                 *org-dates*

Timestamps:
  <2026-09-23 Wed>                  active (shows in the agenda)
  [2026-09-23 Wed]                  inactive
  <2026-09-23 Wed 10:00-11:30>      time range
  <2026-09-23 Wed>--<2026-09-25 Fri> date range
  <2026-09-23 Wed +1w -2d>          repeater and warning period

<prefix>s       Schedule (SCHEDULED:). A new date removes CLOSED.
<prefix>d       Deadline (DEADLINE:).
<prefix>i.      Insert an active timestamp (count: include time; count
                16: the current time without a prompt). Right after an
                existing timestamp, this creates a range.
<prefix>i!      Insert an inactive timestamp.
<C-a> / <C-x>   (ctx) Increment / decrement the part under the cursor, like
                Emacs org-timestamp-change: year, month, day, hour, minute,
                end time, repeater or warning. The cursor on the character
                right after a part (a `-`, `:` or space) changes that part.
                On a repeater or warning, the number never goes below 1
                (warning: 0) and the unit letter cycles d, w, m, y. Only
                `+N` repeaters and `-N` warnings are changed, like Emacs.
<S-Up/Down>     (ctx) Same as <C-a> / <C-x>. On minutes, step by the
                second value of `time_stamp_rounding_minutes` (5) and
                round to it; a count steps by exactly that many minutes.
                The end minute of a time range moves by 1. On a bracket,
                switch the timestamp between active and inactive.
<S-Right/Left>  (ctx) Day +1 / -1.
:Org toggle_timestamp_type   Switch the timestamp at the cursor between
                active and inactive (in a range, only that end).
<C-c><C-y>      Show the length of the range at the cursor, e.g. "2 days
                3 hours 30 minutes"; with a count, insert it after the
                range as ` 2d 03:30` (` 2d` for dates, ` 00:20` under a
                day), replacing an earlier result (org-evaluate-time-range).
                `<d 10:00-12:30>` ranges work too (an extension).
<C-c><C-x><C-t> Toggle the custom display of timestamps
                (org-toggle-timestamp-overlays): each timestamp is shown as
                `time_stamp_custom_formats` (`09/25/26 Fri`) with conceal
                and inline virtual text. `display_custom_times = true` or
                `#+STARTUP: customtime` turn it on; the real text shows in
                Insert mode (see 'concealcursor').
<CR>            On a timestamp: open the agenda for that day.

The calendar                                                   *org-calendar*
Date prompts open a floating calendar:
  h l j k        day -1 / +1, week -1 / +1
  H L  < >       month -1 / +1
  J K  [ ]       year -1 / +1
  .              today
  i  t           type a date (see below); a date moved to in the calendar
                 is part of the answer, like Emacs
  T              set a time
  x  <Del>       remove the date (schedule/deadline)
  <CR>           select
  q  <Esc>       cancel
A count of 4 (`C-u`) before the schedule/deadline key removes the date; a
count of 16 (`C-u C-u`) instead asks for a date and sets the warning period
(DEADLINE) or delay (SCHEDULED) to the days between it and the entry's
date, e.g. `<2026-10-10 Sat -5d>`. Other counts are ignored, like Emacs.

Date input (like org-read-date)                                 *org-read-date*
The typed text is read like Emacs org-read-date-analyze:
  ""                   the default date (the date being changed, or today)
  "."  "+0"            today
  +3d  -2w  +1m  +4    relative to today (unit defaults to days)
  +2h                  two hours from now
  ++3d  --1w           relative to the default date
  fri  +2fri  -mon     next Friday (a weekday name is never today) / in two
                       weeks / last Monday
  2026-10-01  26-10-01  10-01  10/1  10/1/2026   absolute dates
  2026-10-01 Thu +1w   extra words (a pasted timestamp) are ignored
  15                   the 15th, this month or the next
  15.3.  15.3.2027     dotted day.month[.year]
  oct  sep 15  15 sep 2027  2027   month names, a year alone
  w39  2026-w39-5  w39 fri   ISO week (and weekday, default Monday)
  14:00  2pm  15h30  24:00   times (combine with any date); 24:00 is the
                       next day
  10:00-11:30  10am-11am  10:00+1:30   time ranges
  2026-10-01T10:00     ISO date and time
  today tomorrow yesterday now   (extensions; Emacs ignores these words)
Dates out of range roll over (`feb 30` is March 2nd). With
`read_date_prefer_future` (default), a day or month without a year is taken
in the future: `15` on the 20th is the 15th of next month; `"time"` also
moves a past time of today to tomorrow; `false` completes the date from the
default instead. Before `extend_today_until` o'clock the default is still
yesterday. Text that cannot be read at all is refused with a warning (Emacs
silently uses the default date).

Changes to SCHEDULED and DEADLINE are logged when `log_reschedule` or
`log_redeadline` is set (or via the `#+STARTUP` log keywords); setting the
same date again is not logged.

10. CLOCKING AND EFFORT                                            *org-clock*

<prefix>xi      Clock in on the current entry. Any running clock is
                stopped first, and `clock.in_switch_to_state` can change the
                TODO state. A count picks a task from the clock history
                (d default task, i the interrupted task, c the current one,
                1-9 A-Z recent tasks); 16 also marks the entry as the
                default task; 64 starts where the last clock stopped.
<prefix>xo      Clock out (global). `clock.out_switch_to_state` changes the
                TODO state; with a count, you are asked for the state.
<prefix>xq      Cancel the running clock (global).
<prefix>xj      Jump to the clocked entry (global), else to the last
                clocked one. With a count, pick from the history.
<prefix>xe      Set effort.
<prefix>xE      Set effort to the next value of `Effort_ALL`.
<prefix>xm      Change the effort of the clocked task (or the entry at the
                cursor); `+0:15` / `-10` add or subtract.
<prefix>xz      Resolve open clocks (with a count: only dangling ones, not
                the running clock). See |org-clock-resolve|.
<prefix>xd      Show the time clocked in each subtree next to its headline,
                for `clock.display_default_range` (this year). Count: 4 =
                today, 16 = ask for a range, 64 = only the total. Editing
                the buffer, <C-c><C-c> or calling it again hides the sums.
<prefix>xr      Insert a clock report (`#+BEGIN: clocktable`) for the entry
                at the cursor (:scope subtree), or the file before the
                first headline; update it when on one. With a count,
                update the first clock table of the buffer.
<C-c><C-c>      On a CLOCK line: recompute its duration.
<C-S-Up/Down>   On a CLOCK line: shift both timestamps by the part under
                the cursor, keeping the duration.
<S-M-Up/Down>   On a CLOCK timestamp: change it and move the touching
                timestamp of the previous (on a clock-in) or next (on a
                clock-out) task in the clock history by the same amount.
<S-arrows>      On a `#+BEGIN: clocktable` line: shift its :block
                (today -> today-1, 2026-W39 -> 2026-W40, ...).
:Org clock_in_last   Clock in the last clocked entry again (count: pick
                from the history; 16 = from the last clock-out; 64 = ask
                for the TODO state).
:Org clock_mark_default_task   Mark the entry as the default task.
:Org clock_toggle_auto_clockout  Turn auto clock-out on/off for this session.

Clock lines go into the LOGBOOK drawer: >org
    :LOGBOOK:
    CLOCK: [2026-09-23 Wed 10:00]--[2026-09-23 Wed 11:30] =>  1:30
    :END:
<
The drawer comes from the inherited `CLOCK_INTO_DRAWER` property (`nil`
for none, a number N for "once there are N clock lines"), then
`clock.into_drawer`, then the log drawer. With `log_note_clock_out` (or
`#+STARTUP: lognoteclock-out`), clocking out asks for a note that goes
below the CLOCK line. `clock.continuously` starts a new clock where the
last one stopped, `clock.rounding_minutes` rounds clock times and
`clock.in_resume` continues an entry's open CLOCK line.

Marking a clocked task done clocks it out (`clock.out_when_done`: true or a
list of states). A running clock is restored after restarting Neovim
(`clock.persist`: true, "clock" or "history"), after asking
(`clock.persist_query_resume`). Quitting with a running clock asks whether
to clock out and save first (`clock.ask_before_exiting`). Clocks of 0:00
are kept unless `clock.out_remove_zero_time` is set.

The statusline shows `[clocked/effort] (Task)`, where the clocked time
includes the task's earlier clocks (`clock.mode_line_total` or the
`CLOCK_MODELINE_TOTAL` property: current, today, repeat, all, auto =
since LAST_REPEAT for repeated tasks). Once it reaches the Effort you are
notified once (`clock.notify_effort`, `clock.sound`,
`clock.notification_handler`) and `clock.task_overrun_text` is prepended.

User autocmds: `OrgClockInPrepare` (before the CLOCK line is written, e.g.
to set an effort), `OrgClockIn`, `OrgClockOut`, `OrgClockCancel`,
`OrgClockGoto`.

Resolving clocks                                           *org-clock-resolve*
An open CLOCK line that isn't the running clock is dangling (e.g. after a
crash). Clocking in resolves them first (`clock.auto_clock_resolution`),
and after `clock.idle_time` idle minutes you are asked about the running
clock (the system idle time is used on macOS and with xprintidle). Keys:
  k / K   keep N of the minutes (default all) and stay clocked in / out
  t / T   keep the time until a given time
  g / G   you got back N minutes ago: clock out when you left, clock in
          again from then (G: stay out)
  s / S   subtract the idle time: clock in again now (S: stay out; the
          next clock in offers to start from the subtracted time)
  C       cancel the clock
  j / J   jump to the clock (J: clock it out first)
  i / q   ignore
`clock.auto_clockout_timer` clocks out after that many idle seconds.

Durations in clock tables, clock sums and effort changes use `1d 2:30` from
one day on, like Emacs `org-duration-format` (`duration_format = "h:mm"`
writes `26:30`).

Use |org-api| `require("org").statusline()` in your statusline.

11. AGENDA                                                        *org-agenda*

The agenda follows Emacs Org 9.8: the same entries, line layout, sorting
and default options (the Emacs variable is named next to each option in
`lua/org/config.lua` and |org-config|).

<prefix>a opens the dispatcher (org-agenda):

  a   agenda for the current week (or `agenda.span`)
  t   global TODO list        T   TODO list for one keyword
  m   tags/property match     M   match, TODO entries only
  s   search for words or a regexp
  S   like s, TODO entries only
  n   agenda and all TODOs    #   stuck projects
  /   multi-occur: a regexp in all agenda files, into the quickfix list
  <   restrict to the current file / subtree (press again to cycle)
  >   remove the restriction and the restriction lock
  e   export the agenda views of custom commands (|org-agenda-export|)
  *   toggle sticky agenda buffers (`agenda.sticky`)
  ... custom commands from `agenda.custom_commands`

:Org agenda a|t [KW|KW]|T KW|m MATCH|M MATCH|s TEXT|S TEXT|n|#|/ REGEXP|
            *|>|e|export FILE|day|week|fortnight|month|year|N|<key>|DATE

Restriction lock (org-agenda-set-restriction-lock):
  <C-c><C-x><    lock every agenda command to the current subtree (to the
                 file when not under a headline, or with a count); also
                 in the agenda, from the entry at point
  <C-c><C-x>>    remove the lock
Other keys in org buffers:
  <C-c>[ <C-c>]  add the current file to / remove it from the agenda files
  <C-'> <C-,>    visit the next agenda file (org-cycle-agenda-files)

With the default `agenda_files = {}` (Emacs org-agenda-files nil) the
agenda is empty, like in Emacs, until files are added with <C-c>[ or the
option is set.

Agenda contents                                          *org-agenda-contents*

For each day, per file, in this order (org-agenda-get-day-entries):
- Deadlines, on their day (`Deadline:`) and in today's agenda from
  `deadline_warning_days` (or the `-Nd` warning) before (`In N d.:`) and
  after (`N d. ago:`, for `agenda.deadline_past_days`). Done entries show
  on their day only.
- Scheduled entries on their day (`Scheduled:`) and, while not done, in
  today's agenda (`Sched.Nx:`, for `agenda.scheduled_past_days`). A delay
  (`-2d`) hides the entry until it is over.
- Date ranges on each of their days (`(2/3):`), with the start time on
  the first day and the end time on the last.
- Active timestamps. Repeaters show on every repeat up to today and, after
  today, per `agenda.show_future_repeats` (true, false, "next");
  `agenda.prefer_last_repeat` shows the last repeat instead of the base
  date.
- Diary sexps, `<%%(...)>` timestamps and `%%(...)` lines
  (|org-agenda-diary-sexp|), including holidays (|org-agenda-holidays|).
- Habits (`:STYLE: habit` and a repeater) in today's agenda, without a
  leader, with a consistency graph from column
  `agenda.habits.graph_column` (40) that overwrites the end of the line
  (org-habit).
- A time grid (`agenda.time_grid`, org-agenda-time-grid) with the current
  time; the `remove-match` flag hides grid lines at the time of an entry.
- Entries under ARCHIVE-tagged or COMMENT headlines are excluded.
`agenda.entry_types` selects the kinds ("deadline", "scheduled",
"timestamp", "sexp"; "deadline*" / "scheduled*" keep only timed ones).
Skipping: `skip_scheduled_if_done`, `skip_deadline_if_done`,
`skip_timestamp_if_done`, `skip_scheduled_if_deadline_is_shown` (true or
"not-today"), `skip_timestamp_if_deadline_is_shown`,
`skip_scheduled_repeats_after_deadline`,
`skip_additional_timestamps_same_entry`,
`skip_deadline_prewarning_if_scheduled` (true: no pre-warning when the
entry is scheduled; N: warn N days before; "pre-scheduled": not before the
scheduled date), `skip_scheduled_delay_if_deadline`. `show_all_dates =
false` hides days without entries.

Line format                                                *org-agenda-prefix*

Each line is `agenda.prefix_format` (org-agenda-prefix-format) followed
by the headline and its tags:
  agenda  " %i %-12:c%?-12t% s"      todo, tags, search  " %i %-12:c"
  %c  category          %i  icon (`agenda.category_icons`)
  %t  time of day       %s  leader (Scheduled:, In 3 d., ...)
  %e  effort            %l  level (spaces)
  %b  breadcrumbs (outline path + `breadcrumbs_separator`)
  %T  last tag          %(expr)  a Lua expression, with `item` and `hl`
A width like `%-12` pads (no truncation), `%-12.10` also truncates, `%?`
omits an empty field with its padding, and a character after the width
(`:` in `%-12:c`) is added after a non-empty value. The leaders are
`scheduled_leaders`, `deadline_leaders`, `timerange_leaders` and
`inactive_leader`. A time of day in the headline ("Call Bob 10:00",
"8pm") is used when the timestamp has none (`search_headline_for_time`)
and removed from the text (`remove_times_when_in_prefix`, true or "beg").
Times: `time_leading_zero`, `timegrid_use_ampm`,
`default_appointment_duration` (minutes). The grid separator
(`time_grid.separator`) follows the time of timed entries without an end.
Tags show inherited tags first, then "::" and the entry's own tags
(":ft::work:"); `hide_tags_regexp` (a Vim regexp) hides some,
`remove_tags` removes them (true, or "prefix" when %T is used),
`tags_column` places them ("auto" = right edge of the window). Day headers
use `format_date` (a strftime format or a function) and show the ISO week
on Mondays; `weekend_days` (0 = Sunday) get the weekend highlight.

Sorting                                                   *org-agenda-sorting*

`agenda.sorting` (org-agenda-sorting-strategy) per view:
  agenda  { "habit-down", "time-up", "urgency-down", "category-keep" }
  todo, tags  { "urgency-down", "category-keep" }
  search  { "category-keep" }
Strategies: time-, urgency-, priority-, category-, todo-state-, alpha-,
habit-, tag-, effort-, stats-, deadline-, scheduled-, timestamp-, ts-,
tsia-, user-defined- (each -up or -down), and category-keep. Urgency is
Emacs's: 99 + days late + priority for scheduled entries, priority + days
overdue (minus days left) for deadlines in today's agenda, the priority
for other entries (A = 2000, B = 1000, C = 0 with the default range) and
org-habit-get-urgency for habits. "user-defined-*" call
`agenda.cmp_user_defined(a, b)`, which returns -1, 1 or nil. An unknown
strategy is an error. `sort_notime_is_late` and `sort_noeffort_is_high`
place entries without a time or an effort.

Windows and buffers                                        *org-agenda-window*

`agenda.window` (org-agenda-window-setup): "split" (default, Emacs
reorganize-frame: the current window and the agenda below it), "only"
(only-window), "other" (other-window), "current", "vsplit", "tab"
(other-tab), "float". `restore_windows_after_quit` restores the previous

Filtering                                                  *org-agenda-filter*

Filters hide lines without rebuilding the view; they show in the window
bar (Emacs shows them in the mode line).
  /     org-agenda-filter: a combined filter such as `+work-John<0:10-/plot/`:
        +/- a tag or category (tags win), an effort comparison (< means
        at most, > at least), a /regexp/ (Emacs syntax). An empty answer
        removes the filters; a leading `+` (`++work`) or a count of 2
        adds to the current ones; a count of 1 negates the whole filter;
        a count of 3 runs `agenda.auto_exclude_function`
  \     filter by one tag: its selection key (#+TAGS / `tags` `(k)`
        keys), <Tab> to type a tag, <Space> any tag, `?` untagged, `.` the
        tags of the entry at point, `-` / `+` exclude / include the next
        tag, <CR> `auto_exclude_function`, `\` removes the tag filter
  <     keep the category of the entry at point (again to clear); with a
        count, hide that category
  =     keep entries matching an Emacs regexp; with a count 1, hide them;
        again to clear
  _     effort: `<`, `>` or `=`, then a digit selecting a value of
        `global_properties.Effort_ALL` (default "0 0:10 0:30 1:00 2:00
        3:00 4:00 5:00 6:00 7:00"); `_` again clears. Entries without
        an effort count as infinitely long (`sort_noeffort_is_high`)
  ^     keep the entries under the top headline of the entry at point
  |     remove all filters
`agenda.auto_exclude_function(tag)` returns "+tag", "-tag" or nil
(org-agenda-auto-exclude-function). Custom commands may preset filters
that stay on: `tag_filter_preset`, `category_filter_preset`,
`regexp_filter_preset`, `effort_filter_preset` (lists like { "+work" }).
`agenda.persistent_filter` keeps the filters when another agenda is
built.

Limits                                                     *org-agenda-limits*

`agenda.max_entries`, `max_todos`, `max_tags` and `max_effort` (minutes)
limit each day or list, as a number or per view type
({ agenda = 5, todo = 10 }); a negative number keeps the entries without
the property. `~` sets one interactively (e entries, t TODOs, T tags, E
effort); with a count it removes them. Like Emacs, lines without the
property (time grid lines too) are dropped while a limit is on.

Bulk actions                                                 *org-agenda-bulk*

B acts on the marked entries, or on the entry at point without marks
(org-agenda-bulk-action):
  $ archive     A archive to the Archive sibling    t TODO state
  + / - add / remove a tag       r refile
  s / d   (re)schedule / set the deadline: a date, or `++2d` to shift each
          entry's own date; an empty answer opens the calendar
  S       scatter: schedule each entry on a random day of the next N days
          (with a count, weekend days are skipped)
  f       apply a Lua function (`function(target, item) ... end`)
  p       toggle persistent marks (`agenda.persistent_marks`: keep the
          marks after the action), then choose the action
  custom  keys of `agenda.bulk_custom_functions`:
          { x = { fn = function(target, item, ...) end, desc = "...",
          args = function() return { ... } end } }

Column view                                               *org-agenda-columns*

<C-c><C-x><C-c> in the agenda shows each entry as columns, like column
view in an org buffer. The format is `agenda.overriding_columns_format`,
else the COLUMNS property or #+COLUMNS of the entry at point (or of the
first entry), else `columns_default_format`. Date lines and block headers
show the summaries of the entries below them
(`agenda.columns_show_summaries`). While it is on: `q` turns it off, `e`
edits the value under the cursor, `n`/`p` (<S-Right>/<S-Left>) switch to
the next/previous allowed value, `v` shows the full value. Other agenda
commands keep working on the entry at point.
`agenda.view_columns_initially` turns it on for every new agenda.

Exporting agenda views                                     *org-agenda-export*

<C-x><C-w> in the agenda, or `:Org agenda export FILE`, writes the current
view (org-agenda-write). The extension picks the format:
  .txt        the agenda text
  .html .htm  the agenda with its colours, as a <pre> block
  .org        the subtrees of the entries in the view, as level-1 trees
  .ics        iCalendar: an event per timestamp (deadlines of non-TODO
              entries too), a VTODO per TODO entry
Custom commands with `export_files = { "~/today.html", "~/today.txt" }`
are written all at once by `e` in the dispatcher or `:Org agenda e`
(org-store-agenda-views). From the shell (org-batch-agenda and
org-batch-agenda-csv):
  nvim --headless -c "lua require('org.agenda.export').batch('a',
    { span = 'day' })" -c q
  nvim --headless -c "lua require('org.agenda.export').batch_csv('t')" -c q
The first argument is a custom command key, a dispatcher key, or a match
string; the second one sets agenda options for the run. CSV records have
Emacs's fields: category,head,type,todo,tags,date,time,extra,priority-l,
priority-n,agenda-day.

Custom commands                                   *org-agenda-custom-commands*
>lua
    agenda = {
      custom_commands = {
        w = {
          description = "Work overview",
          types = {
            { type = "agenda", span = "day", header = "Today" },
            { type = "tags_todo", match = "+work/!", header = "Work" },
            { type = "todo", match = "WAITING" },
          },
          settings = { prefix_format = " %-12:c %s" },
          export_files = { "~/work.html" },
        },
        u = { description = "Urgent", type = "tags", match = "+urgent" },
        p = { description = "Projects", type = "tags-tree",
              match = "project" },
      },
    }
<
Block types: `agenda`, `todo`, `tags`, `tags_todo`, `search`, `stuck`.
`tags-tree`, `todo-tree` and `occur-tree` make a sparse tree of the current
org buffer instead (tags match, TODO keyword, Emacs regexp); they cannot
be blocks of a composite command. A composite command (`types` /
`blocks`) shows its blocks one after the other, separated by a blank line
and `agenda.block_separator` (none with `compact_blocks`, which also drops
the date agenda header). `settings` (Emacs's options list) applies to
every block unless the block sets the option itself.
Block options:
  match         match string (see |org-match-syntax|), TODO keywords for
                `todo`, or text for `search`
  header        heading shown above the block; "" for none; a function
                returning it (also `org_agenda_overriding_header`)
  span          span for `agenda` blocks
  start_day     first day for `agenda` blocks
  files         files to use instead of `agenda_files`
  skip          function(headline) that returns true to skip an entry
                (also `org_agenda_skip_function`). Helpers like Emacs'
                org-agenda-skip-entry-if / -subtree-if:
                  local agenda = require("org.agenda")
                  skip = agenda.skip_entry_if("scheduled", "deadline")
                  skip = agenda.skip_subtree_if("regexp", ":someday:")
                Conditions: scheduled, notscheduled, deadline,
                notdeadline, timestamp, nottimestamp, regexp RE,
                notregexp RE, todo KWS, nottodo KWS (KWS: a list of
                keywords, or "todo", "done", "any")
  sorting       sorting strategies of this block
  *_filter_preset  filters that stay on (|org-agenda-filter|)
  any other `agenda` option (`prefix_format`, `entry_types`,
  `todo_ignore_*`, `show_future_repeats`, `max_entries`, ...), also with
  Emacs names: `org_agenda_entry_types`, `org_agenda_prefix_format`, ...
Keys may be several characters long; a string entry (`w = "Work"`) only
labels the group.

TODO lists: `todo_ignore_scheduled` ("all", "future", "past" or days),
`todo_ignore_deadlines` (true = "near": within the warning period, "far",
"all", "future", "past" or days), `todo_ignore_timestamp`,
`todo_ignore_with_date` hide dated entries (org-agenda-todo-ignore-*);
tags-todo (M) views honour them only with
`tags_todo_honor_ignore_options`. `todo_list_sublevels = false` skips the
children of a listed TODO; `tags_match_list_sublevels = false` those of a
match.

Stuck projects                                         *org-stuck-projects*

`agenda.stuck_projects` (org-stuck-projects): projects matching `match`
("+LEVEL=2/-DONE") are stuck unless a heading of their subtree, the
project heading included, has one of `todo_keywords` ({ "TODO", "NEXT",
"NEXTACTION" }; "*" = any not-done keyword) or `tags` ("*" = any tag), or
the subtree text matches the Vim regexp `text`.

Search view                                            *org-agenda-search*

A plain query is a phrase whose spaces match any whitespace, newlines
included ("banana split" finds "banana\n  split"). A query starting with
`+`, `-` or `{` is boolean: `+word` must and `-word` must not occur, "a
phrase" in double quotes counts as one word, `{regexp}` is an Emacs
regexp, and `word\ word` joins two words. A leading `*` searches
headlines only, `!` TODO entries only, `:` makes words match whole words.
Matching ignores case.
  agenda.search_view_always_boolean    treat every query as boolean
  agenda.search_view_force_full_words  words match whole words only
  agenda.search_view_max_outline_level entries below this level are
                                       searched as part of their ancestor
                                       (0 = no limit)
  agenda.text_search_extra_files       more files to search; include
                                       "agenda-archives" for the archive
                                       files

Diary sexp entries                                  *org-agenda-diary-sexp*

Emacs lets you put diary s-expressions in timestamps, `<%%(diary-float t 4
2)>`, and on lines of their own at the start of a line, `%%(org-anniversary
1990 5 17) Birthday of Joe (%d)`. Emacs evaluates them as Emacs Lisp.
Neovim has no Lisp interpreter, so they are read with a small, safe
s-expression reader and the common calendar functions are emulated,
with the same results as Emacs:

  org-anniversary Y M D          diary-anniversary M D [Y]
  org-cyclic N Y M D             diary-cyclic N M D Y
  org-block Y1 M1 D1 Y2 M2 D2    diary-block M1 D1 Y1 M2 D2 Y2
  org-date Y M D                 diary-date M D Y
  diary-float MONTH DAYNAME N [DAY]
  org-class Y1 M1 D1 Y2 M2 D2 DAYNAME [ISO-WEEKS...]
  and  or  not  list  quote

The `diary-*` functions take their arguments in Emacs's default
`calendar-date-style` order (american: month day year). The `org-*`
variants use ISO order (year month day). In `diary-date`/`org-date`, `t`
matches any value and a list `'(1 2)` matches any of its elements. In
`diary-float`, MONTH may be `t` or a list, DAYNAME is 0 (Sunday) to 6,
and a negative N counts from the end of the month. The entry text of
anniversaries and cycles may contain `%d` (years or repetitions) and `%s`
(its ordinal suffix, "st", "nd", ...); a result with "; " gives several
agenda lines.

Holidays                                              *org-agenda-holidays*

A `%%(org-calendar-holiday)` line shows the day's holidays, like Emacs's
`calendar-check-holidays`: several on one day give several agenda lines.
>org
    * Holidays
      :PROPERTIES:
      :CATEGORY: Holiday
      :END:
    %%(org-calendar-holiday)
<
The holidays come from `agenda.holidays` (calendar-holidays), with the
Emacs defaults: one list per `holiday-*-holidays` variable (`general`
(the United States), `local`, `other`, `christian`, `hebrew`, `islamic`,
`bahai`, `oriental` and `solar`), and the flags `christian_all`,
`hebrew_all`, `islamic_all`, `bahai_all` and `chinese_all`
(calendar-*-all-holidays-flag, false). Set a group to `{}` to drop it;
list replaces the default. Items are Emacs's holiday forms written as Lua
lists, or Lua functions:
>lua
    agenda = {
      holidays = {
        general = {},  -- no US holidays
        christian = {  -- only Christmas and Easter Sunday
          { "holiday-fixed", 12, 25, "Christmas" },
          { "holiday-easter-etc", 0, "Easter Sunday" },
        },
        ["local"] = {
          { "holiday-fixed", 9, 16, "Independence Day" },
          { "holiday-float", 11, 1, 3, "Revolution Day" },  -- 3rd Monday
          function(year)  -- holiday-sexp: { MONTH, DAY, NAME } per year
            return { { 2, 5, "Constitution Day " .. (year - 1917) } }
          end,
        },
      },
    }
<
    `{ "holiday-fixed", MONTH, DAY, NAME }`
    `{ "holiday-float", MONTH, DAYNAME, N, NAME [, DAY] }` (the Nth
      DAYNAME, 0 = Sunday, from DAY; negative N counts backwards)
    `{ "holiday-easter-etc" [, N, NAME] }`, `{ "holiday-advent" [, N, NAME] }`,
    `{ "holiday-greek-orthodox-easter" [, N, NAME] }` (N days from Easter,
      Advent Sunday or Pascha; without arguments the default holidays)
    `{ "holiday-julian" | "holiday-hebrew" | "holiday-islamic" |
      "holiday-bahai" | "holiday-chinese", MONTH, DAY, NAME }` (a date
      of that calendar)
    `{ "holiday-hebrew-passover" }`, `-rosh-hashanah`, `-hanukkah`,
    `-tisha-b-av`, `-misc`, `{ "holiday-islamic-new-year" }`,
    `{ "holiday-bahai-new-year" }`, `-ridvan`, `-twin-holy-birthdays`,
    `{ "holiday-chinese-new-year" }`, `-qingming`, `-winter-solstice`,
    `{ "solar-equinoxes-solstices" }` and `{ "holiday-daylight-saving" }`
      (the Emacs functions of the same names)
    `{ "if", FLAG, ITEM... }` (the items when `holidays[FLAG]` is true)

Equinox, solstice and daylight saving times use the system time zone,
like Emacs's calendar-time-zone. A bad item is reported once and skipped.
Differences: Emacs evaluates each item as Lisp (`holiday-sexp` and other
Lisp forms become Lua functions here).

Not supported in the agenda                        *org-agenda-unsupported*

- Arbitrary Emacs Lisp in sexps, `diary-remind`, `diary-offset`, the
  diary functions of other calendars (`diary-hebrew-date`, ...) and the
  `holidays` argument of `org-class`: they need Emacs's Lisp evaluator
  and diary library. An unsupported sexp is skipped with a message (once
  per session). Holidays are supported (|org-agenda-holidays|).
- The Emacs diary file (org-agenda-include-diary) and the agenda keys
  that use it (`i` insert a diary entry, `D` toggle the diary): the diary
  is an Emacs file format and machinery with no Neovim counterpart.
- Calendar conversions (`C`), moon phases (`M`), sunrise and sunset
  (`S`) and holidays (`H`): they rely on Emacs's calendar, astronomy
  and holiday code.
- `C-c C-x b` (show the subtree in an indirect buffer): Neovim has no
  indirect buffers or narrowing; <Tab> opens the entry instead.
- PDF and PostScript agenda export (.pdf/.ps): Emacs prints them with
  ps-print; export .html and print it from a browser instead.
  org-agenda-exporter-settings is not used; pass options as the second
  argument of batch()/batch_csv().
- `%%(...)` sexp lines before the first heading of a file: agenda
  entries belong to a heading here, so write them under one.
- `?` (show the FLAGGED note of MobileOrg) and the Customize keys (`C`,
  `!` in the dispatcher): there is no MobileOrg or Customize.
- Group tags (`#+TAGS: [ Work : Lab ]`) are expanded in match strings
  (|org-tag-groups|) but not by the agenda tag filter (`\`, `/`).
- Keys that differ on purpose, to keep Vim motions: `n`/`p` move by item
  (Emacs: by line; N/P by item), `j` and `k` are motions (go to date is
  `gd`, capture `K`), `g` is a Vim prefix (redo all is `gr`), `s`/`d`
  schedule and set deadlines (Emacs: save and day view; views are `vd`,
  `vw`, `vt`, `vm`, `vy`), `R` refiles (the clock report is `C` / `vR`).

12. MATCH SYNTAX                                            *org-match-syntax*

Used by the agenda (m, M, custom commands), sparse trees and clocktables.
The syntax is Emacs's `org-make-tags-matcher':

  +work-boss            has `work` and not `boss`
  work:boss             both tags (`:` and `&` are synonyms of `+`)
  work|home             either tag
  {^proj}               a tag matching a regexp
  LEVEL>1               property comparison: = == <> != /= < <= > >=
  PRIORITY="A"          string comparison; a missing property is ""
  Effort<2              numbers compare like `string-to-number': "1:30"
                        is 1, a missing property is 0
  Effort<*2             starred operators (<* <=* =* >=* >* <>* !=* /=*)
                        only match entries that have the property
  CATEGORY={^work}      regexp match on a property (<>, != and /= negate)
  SCHEDULED<="<+2d>"    date comparison: "<now>", "<today>", "<tomorrow>",
                        "<+2d>", "<-1w>", "<+1m>", "<2026-01-01>"
  +proj/NEXT|TODO       TODO keyword part after `/`
  +proj/!               only entries that aren't done
  /-DONE                exclude a keyword
  work/{^W}             a regexp in the TODO part

Regexps in `{...}' are written in Emacs syntax (`\(...\)', `\|', `+',
`?', `\{m,n\}', `[[:alpha:]]', `\<', `\s-', ...), translated to Vim
regexps, and ignore case, like Emacs. Text that does not start a new term
ends the match, as in Emacs: "work -boss" is the same as "work" (write
"work-boss").

13. SPARSE TREES                                             *org-sparse-tree*

<prefix>/ shows a menu:
  / r  regexp   t  TODO entries     T  specific keyword
  m  match      M  match, TODO only p  property value
  d  deadlines due or overdue       b  before date
  a  after date D  between dates    c  clear

<C-c>\         Tags / property match sparse tree (org-match-sparse-tree).
                With a count, only TODO entries match.

The buffer is folded so only matching entries are visible, the matches are
highlighted, and the location list is filled (|:lnext|). The highlights go
away with the next change or the next <C-c><C-c>.

14. CAPTURE                                                      *org-capture*

<prefix>c opens the template menu. `:Org capture KEY` selects a template
directly. A count works like Emacs's prefix argument: `4<prefix>c` (C-u)
jumps to a template's target, `16<prefix>c` (C-u C-u) to the last stored
entry and `1<prefix>c` (C-1) asks for the date of a date tree entry.
`:Org capture_here` (C-0 C-c c) inserts the template at the cursor: an
entry becomes a sibling of the headline there, other types go on the
cursor line (before it at column 0, else after it).

The target is resolved when the capture starts, like Emacs: missing
file+headline headlines and date tree nodes are created then, and the
location is remembered even if the file changes (or the clock moves to
another task) while you type. When the target is gone at the end (its
headline was deleted), nothing is lost: the capture buffer stays open.

                                                    *org-capture-templates*
>lua
    capture = {
      templates = {
        t = { description = "Task", template = "* TODO %?\n  %u", target = "~/org/refile.org" },
        w = "Work",   -- group label for keys starting with w
        wt = { description = "Work task", template = "* TODO %?", target = "~/org/work.org", headline = "Inbox" },
        j = { description = "Journal", template = "* %<%H:%M> %?", target = "~/org/journal.org", datetree = true },
      },
      window = "split",
    }
<
When `templates` is empty (the default), Emacs's fallback is used:
`t = { description = "Task", target = "", headline = "Tasks", template =
"* TODO %?\n  %u\n  %a" }`, which files under "Tasks" in
`default_notes_file`.

Template fields:
  description        menu label
  template           string, list of lines, `{ file = "path" }` (read from
                     that file, relative to `org_directory`) or a function
                     returning a string. When empty: "* %?\n  %a" for
                     entries, "- %?" for items, "- [ ] %?" for checkitems,
                     "| %? |" for table lines
  type               "entry" (default), "item", "checkitem", "table-line",
                     "plain"
  target             file (relative to `org_directory`, "" =
                     `default_notes_file`), "clock", or a function
                     returning either; defaults to `default_notes_file`
  headline           file+headline: under the first headline with this
                     title (TODO keyword, priority and tags ignored),
                     created at the end of the file when missing
  olp                file+olp: outline path, e.g. { "Projects", "Neovim" }
                     or "Projects/Neovim"; every node must exist
  datetree           file+olp+datetree: true or { tree_type = ... }, under
                     `olp`/`headline` when given. The date is the capture
                     date (agenda day, `time_prompt`, C-1) or today.
                     Existing nodes are recognized by their date
                     ("2026-09 Sept" is the September node)
  tree_type          "day" (default), "week", "month", a list of "year",
                     "quarter", "month", "week", "day", or a function(date)
                     returning { { title, compare } ... } (:tree-type)
  regexp             file+regexp: Vim regexp; the text goes where the
                     first match ends (starts, with `prepend`); an entry
                     becomes a child when the match is on a headline
  func / function    file+function: function(bufnr) returning the line
                     (and column) of the location, or moving the cursor
                     there; a headline line means "under this headline"
  location           the (function f) target: function() returning the
                     buffer, line and column, or nothing for the cursor
                     position in the current buffer
  id                 insert under the entry with this ID (file+id)
  target = "clock"   insert under the currently clocked task (clock)
  prepend            insert as the first child instead of the last
  empty_lines        blank lines around the text, replacing the blank
                     lines already there (also empty_lines_before /
                     empty_lines_after; items in an existing list get at
                     most one)
  table_line_pos     where a table line goes, e.g. "II-3" (3 lines before
                     the 2nd hline) or "I+1" (right after the 1st). A table
                     is created when there is none
  properties         table of properties added to the entry
  immediate_finish   finish without opening the capture window
  jump_to_captured   jump to the entry after finishing
  kill_buffer        unload the target file afterwards when the capture
                     loaded it
  refile_targets     `refile.targets` used when refiling from the capture
                     buffer
  clock_in           clock the entry while capturing (stops the running
                     clock); the time is logged when the capture ends
  clock_keep         with clock_in, keep the clock running afterwards
  clock_resume       with clock_in, clock the interrupted task in again
                     when the capture ends or is aborted
  time_prompt        ask for the date used by %t/%T/%u/%U and the datetree
  no_save            don't save the target file after capturing
  prepare_finalize   function(capture_bufnr), before the text is read
  before_finalize    function(bufnr, lnum) in the target, before saving
  after_finalize     function(bufnr, lnum) when the capture is done
  unnarrowed         not supported: see |org-differences|

An entry template without stars gets "* ", item templates get "- " (and
continuation lines are indented under the bullet); in an existing list the
item takes the list's indentation and bullet style. Items and table lines
go into the first list / table of the target entry (of the file for a
plain file target); "plain" text goes at the end of the entry's text,
before its children (after its planning, properties and drawers with
`prepend`), or at the end (top) of a file.

                                                    *org-capture-contexts*
`capture.templates_contexts` (org-capture-templates-contexts) makes
templates available only in some buffers. Each rule is `{ key, rules }`, or
`{ key, other_key, rules }` to use `other_key`'s template for `key` there
(the other key is then hidden). A template is shown when any of its rules
holds; rules are tables with one of `in_file`, `not_in_file`, `in_mode`
(filetype), `not_in_mode`, `in_buffer`, `not_in_buffer` (Vim regexps) or
functions:
>lua
    capture = { templates_contexts = {
      { "m", { { in_mode = "^mail$" } } },
      { "t", "p", { { in_file = "project" } } },
    } }
<
Template expansions:                               *org-capture-expansions*
  %?           cursor position
  %t %T        active date / date and time
  %u %U        inactive date / date and time
  %^t %^T %^u %^U  the same, asking with the calendar
  %<fmt>       strftime format, e.g. %<%Y-%m-%d>
  %a           annotation: a link to the location capture was started from
  %A           the same, asking for a description
  %l           the link without a description
  %L           the bare link target
  %i           initial content (the visual selection); the text before
               %i on its line is repeated on every line
  %x           clipboard (the `*` register, else `+`)
  %c           last yank
  %f %F        origin file name / full path
  %n           your full name (like Emacs's `user-full-name`)
  %k %K        the clocked task's title / a link to it
  %^{Prompt}   ask; `%^{Prompt|default|opt1|opt2}` offers opt1 and opt2
               and uses the default for an empty answer
  %^C %^L      ask for a clipboard value (%^L makes it a link)
  %\1 ...      the answer to the Nth %^{...} prompt
  %\*1 ...     the answer to the Nth prompt of any kind (%^t, %^g, ...)
  %^g %^G      tags prompt, completing the target file's / all agenda
               files' tags; tags on a headline are aligned
  %^{PROP}p    property prompt (offers the PROP_ALL values of the target)
  %:keyword    link information: %:link, %:description, %:annotation,
               %:initial, %:type
  %[file]      the contents of a file
  %(expr)      the value of a Lua expression, e.g. %(os.getenv("HOST"))
               (Emacs: an elisp sexp)
Like Emacs, `%%` is not an escape: write `\%` for a literal "%" before an
expansion character (`\%t`). Leading blank lines and trailing whitespace of
the expanded text are removed.

Capture window: `<C-c><C-c>` or `:w` finalizes (with a count, C-u C-c C-c,
it then jumps to the entry), `<C-c><C-k>` aborts (the headlines created for
an unmodified target are dropped again) and `<C-c><C-w>` finalizes and
refiles the entry (entry templates only; also `<prefix>w`, `<prefix>k`,
`<prefix>r`). The window splits the screen like Emacs (`capture.window`:
"split", "float", "vsplit", "tab" or "current").

:Org capture_goto_target  choose a template and jump to its target
                          (C-u C-c c in Emacs)
:Org capture_goto_last    jump to the last captured (or refiled) entry
                          (C-u C-u C-c c)
From the agenda, `c` captures with the date at point as the default date.

org-protocol                                                  *org-protocol*
`org-protocol://` URLs from a browser or another program capture, store
links and open files in a running Neovim, like Emacs `org-protocol.el`:
  org-protocol://capture?template=KEY&url=URL&title=TITLE&body=TEXT
      capture with template KEY (`protocol.default_template_key`, else
      choose); `%:link`, `%:description`, `%a`, `%i` (body) and
      `%:<param>` come from the URL
  org-protocol://store-link?url=URL&title=TITLE
      store the link for |org-insert-link| and yank the URL
  org-protocol://open-source?url=URL
      open the local file behind a published URL (`protocol.projects`,
      like org-protocol-project-alist: base_url, working_directory,
      online_suffix, working_suffix, rewrites)
Old-style URLs (`capture://KEY/URL/TITLE/BODY`) work too, and
`protocol.handlers` adds sub-protocols. Call it from Lua with
`require("org.protocol").handle(url)` or `:Org protocol <url>`.

Neovim must listen on a socket (`nvim --listen ~/.cache/nvim/org.sock`, or
|v:servername|) and the OS must send `org-protocol:` URLs to a handler
that forwards them, e.g. on Linux a desktop file with
`MimeType=x-scheme-handler/org-protocol;` and: >sh
    Exec=nvim --server ~/.cache/nvim/org.sock --remote-expr "v:lua.require'org.protocol'.handle('%u')"
<
then `xdg-mime default org-protocol.desktop x-scheme-handler/org-protocol`.
On macOS register the scheme with a small app bundle (an AppleScript
`on open location` handler running the same command). A bookmarklet: >js
    javascript:location.href='org-protocol://capture?'+new URLSearchParams({
      template:'p', url:location.href, title:document.title,
      body:window.getSelection()});void(0)
<
Emacs's emacsclient integration (`server-visit-files` advice, `:kill-client`)
has no counterpart: the handler command above plays that role.

15. REFILE AND ARCHIVE                                *org-refile* *org-archive*

<prefix>r       Refile the subtree as the last child of another headline
                (org-refile, <C-c><C-w>). In Visual mode, refile the
                selected lines; they must start with a headline and form a
                sequence of subtrees. The subtree keeps its blank lines and
                goes after the target's own blank lines, like Emacs. A
                count works like Emacs's prefix argument: 4 (C-u) jumps to
                a target, 16 (C-u C-u) to the last refiled entry, 2 refiles
                under the running clock and 3 copies (org-refile-keep).
<prefix>R       Copy the subtree to a refile target, keeping the original
                (org-refile-copy, <C-c><M-w>).
:Org refile_goto       Jump to a refile target (C-u C-c C-w).
:Org refile_goto_last  Jump to where the last refile or capture went
                       (C-u C-u C-c C-w).

By default the targets are the level-1 headlines of the current buffer,
shown by their heading (Emacs's org-refile-targets nil). Refile options:
  targets             like org-refile-targets. A list of specs, each with
                      `files` ("agenda", "current" (the default), a path or
                      glob, a list, or a function) and any of `max_level`,
                      `level`, `tag`, `todo`, `regexp` (Vim regexp on the
                      headline):
>lua
    refile = { targets = {
      { files = "current", max_level = 2 },
      { files = "agenda", tag = "project" },
      { files = "~/org/someday.org", level = 1 },
    } }
<
  max_level           shortcut when `targets` is empty: the agenda files
                      plus the current file (unless `include_current_file
                      = false`) up to this level
  use_outline_path    how targets are shown (org-refile-use-outline-path):
                      false (default) the heading, followed by
                      " (file.org)" for other files; true "Parent/Child/";
                      "file" "file.org/Parent/Child/"; "full-file-path",
                      "title" (#+TITLE) and "buffer-name" likewise. The
                      last four also offer the files themselves (top
                      level). A "/" in a heading is shown as "\/"
  outline_path_complete_in_steps
                      with an outline path, choose one level at a time
                      (default true)
  allow_creating_parent_nodes
                      true or "confirm" (ask first): type "Target/New" to
                      create missing headlines under an existing target
  active_region_within_subtree
                      refile a Visual selection that does not start at a
                      headline by making its first line one
  verify              function(headline) -> boolean to drop targets
                      (org-refile-target-verify-function)
  log                 false | "time" | "note": add "Refiled on [date]"
                      to the entry's logbook (org-log-refile); a region
                      only gets time stamps
  reverse_note_order  refile as the first child (org-reverse-note-order)

<prefix>$       Archive the subtree. The location comes from the ARCHIVE
                property, then `#+ARCHIVE:`, then `archive_location`
                (default `%s_archive::`). Forms:
                  "%s_archive::"             another file, top level
                  "archive.org::* Archived"  another file, under a headline
                  "::* Archive"              same file, under a headline
                  "archive.org::datetree/"   another file, in a date tree
                                             for the CLOSED date (or today)
                  "archive.org::datetree/* Sub"  under "Sub" in the day
                A new archive file starts with
                `archive_file_header_format` ("\nArchived entries from
                file %s\n\n", false for none; a file not named *.org also
                gets an Org mode line). Entries are separated by one blank
                line (none in a date tree); `archive_reversed_order` makes
                them the first child. `archive_mark_done` (true or a done
                keyword) marks them done.
                Adds ARCHIVE_TIME, ARCHIVE_FILE, ARCHIVE_OLPATH,
                ARCHIVE_CATEGORY, ARCHIVE_TODO and ARCHIVE_ITAGS (also
                "ltags" and "olid") according to
                `archive_save_context_info`. Inherited tags become local
                tags when archiving within the same file
                (`archive_subtree_add_inherited_tags`: "infile", true or
                false). IDs of archived entries keep resolving
                (|org-id|). With a count, 4 (C-u) runs `archive_all_done`
                and 16 (C-u C-u) `archive_all_old`.
                User autocmds `OrgArchive` (source buffer, before the
                subtree is removed; org-archive-hook) and
                `OrgArchiveFinalize` (archive buffer;
                org-archive-finalize-hook) get `data = { bufnr, lnum,
                title, archive_file }`.
<prefix>hA      Toggle the ARCHIVE tag. Archived subtrees stay folded and are
                excluded from the agenda. With a count (C-u C-c C-x a),
                offer to tag every child without open TODO entries.
<C-c><C-x>A     Move the subtree under its "Archive" sibling
                (`archive_sibling_heading`), which is created with the
                ARCHIVE tag when missing (org-archive-to-archive-sibling).
:Org archive_all_done
                Offer to archive each child of the headline at the cursor
                (each top-level tree when not on a headline) that has no
                open TODO entries (C-u C-c C-x C-s in Emacs).
:Org archive_all_old
                The same for children whose first active time stamp lies
                before today (C-u C-u C-c C-x C-s).

16. LINKS, IDS AND ATTACHMENTS                  *org-links* *org-id* *org-attach*

Syntax: `[[target][description]]`, `[[target]]`, plain links
(`https://en.wikipedia.org/wiki/Foo_(bar)`: balanced parentheses are part
of the link, trailing punctuation is not) and <angle> links. Bracket links
may span lines. With `ui.conceal_links` (org-link-descriptive), only the
description is shown.

Targets:
  https://… http://… ftp:… mailto:…   opened with |vim.ui.open()|
  doi:10.1000/x                       `links.doi_server_url` + path
  file:path  ./rel  ~/p  /abs          open a file; add a search option:
      ::42  ::*Heading  ::#custom-id  ::(coderef)  ::/regexp/  ::some text
  file+sys:path  file+emacs:path      system application / always Neovim
  id:UUID  id:UUID::search            headline with that ID (the search
                                      runs inside its subtree)
  #custom-id                          headline with that CUSTOM_ID
  *Heading                            headline in the current file
  (label)                             coderef in a src/example block
  <<target>>  text                    dedicated target, `#+NAME`, headline
  shell:cmd                           run in a terminal in the file's
                                      directory (asks first)
  help:topic                          Vim :help
  man:printf(3)  man:ls::-l           |:Man|, with an optional search
  info:emacs#Top                      the `info` program in a terminal
  attachment:name                     file in the entry's attachment dir
  abbrev:tag  abbrev::tag  abbrev     `#+LINK:` or `links.abbreviations`
                                      (`%s` = tag, `%h` = url-encoded)
  custom:path                         `links.types` (see below)

Searches (org-link-search) ignore case and runs of whitespace (a text
search also matches across line breaks), and headline searches ignore the
TODO keyword, priority, COMMENT, tags and statistics cookies. A fuzzy
link tries `<<target>>`, `#+NAME:` and headlines. When nothing matches in
an Org file, `links.search_must_match_exact_headline` decides: with
"query-to-create" (default) you are asked "No match - create this as a new
heading?" (the heading is added at the end of the file, or as the last
child of the entry for `id:ID::*Heading`); with true the failure is
reported; with false a plain text search follows, which never lands on the
link itself. `*Heading` searches never fall back to text. `::/regexp/`
takes an Emacs regexp: in Org files it shows a sparse tree
(|org-sparse-tree|), elsewhere a location list (like `occur`); common
Emacs syntax is translated to Vim regexps, see |org-differences|.

<CR>, gx, <prefix>o  Open the link, footnote or date at the cursor.
<C-c><C-o>      The same. On the tags of a headline, show a tags agenda for
                the tag under the cursor (a count: TODO entries only).
                Elsewhere on a headline, pick one of the entry's links, or
                "Open all links"; without links, open the attachment
                directory when there is one.
                With a count (C-u), files open in Neovim even when an
                external app applies, and internal links are shown in
                another window; with 16 (C-u C-u), files open with the
                system application.
                `file:` and `id:` links open in another window, splitting
                when there is none, like Emacs (`links.frame_setup`).
<prefix>ls      Store a link to the current location (works in any
                buffer, org-store-link). In org buffers this is, in order:
                the `store` function of a custom link type, an `id:` link
                (see `links.use_id`), the `<<target>>` under the cursor
                (`file:…::target`), the `#+NAME:` of the element at the
                cursor, the current line before the first heading, or the
                heading: `file:…::#custom-id` or `file:…::*Heading`. When
                the entry has a CUSTOM_ID, a `file:…::#custom-id` link is
                stored too. In Visual mode the selection is the search
                string (`links.context_for_files` may limit its lines).
                In other files, the current line is the search string (an
                empty line gives a plain `file:` link). Search strings
                collapse whitespace and drop statistics cookies. In the
                agenda, the link points to the item's entry; in a src
                block edit buffer (|org-babel|), it stores a coderef link
                `file:…::(label)` and adds a `(ref:label)` to the line when
                it has none. Help buffers give `help:tag`, man pages
                `man:page`, netrw/oil listings a link to the file under the
                cursor.
                A count of 4 (C-u) toggles `links.context_for_files`, 16
                (C-u C-u) skips custom `store` functions, 64 stores one link
                per selected line.
<prefix>li      Insert a link (org-insert-link). Stored links, their
                descriptions, link types and file paths (relative to the
                file's directory) are completed; an empty answer inserts
                the last stored link. Entering a type alone (`file`,
                `id:`, a custom type) completes it. On a link, edit it (a
                plain or angle link becomes a bracket link). In Visual
                mode, the selection becomes the description. Links to the
                current file become their search option, and file paths
                follow `links.file_path_type`. An inserted stored link is
                removed from the list (`links.keep_stored_after_insertion`).
                With a count of 4 (C-u), pick a file; 16 (C-u C-u) uses an
                absolute path; 64 inverts `keep_stored_after_insertion`.
<prefix>lL      Insert the last stored link and a newline, and forget it
                (C-c M-l). A count inserts that many. Links without a
                description get `<no description>`, like Emacs.
<prefix>lA      Insert every stored link as a `- ` line and forget them
                (C-c C-M-l); a count of 4 keeps them.
<prefix>lt      Toggle concealed link display (org-toggle-link-display):
                only links change, not emphasis markers.
<prefix>ln/lp   Next / previous link (takes a count). Links in src and
                example blocks, comments and verbatim are skipped;
                repeating a failed search wraps around the buffer.
<C-c>&          Jump back to where you followed a link from (<C-o> works
                too).
<C-c>'          On `#+INCLUDE:`, `#+SETUPFILE:` or `#+BIBLIOGRAPHY:`, visit
                the file.

Radio targets `<<<text>>>` make every occurrence of "text" a link to them
(also in export): case is ignored, the words must stand alone and may be
split over lines. Radio links are highlighted; after adding a radio
target, <C-c><C-c> on it refreshes the highlighting. Coderefs: a
`(ref:name)` label at the end of a src or example block line (or the
block's `-l "fmt"` format) can be reached with `[[(name)]]`.

Custom link types (org-link-set-parameters) go in `links.types`, either a
function (follow) or a table: >lua
    links = { types = { jira = {
      follow = function(path, link, count) vim.ui.open("https://jira/" .. path) end,
      complete = function() return "jira:" .. vim.fn.input("Issue: ") end,

IDs are stored in `id.locations_file`. `:Org id_update_locations` rebuilds

18. TABLES AND FORMULAS                                *org-tables* *org-tblfm*

Start a row with `|`. `|-` becomes a separator line (hline) when the table is
aligned.

Insert mode:  <Tab>/<S-Tab>  next / previous field (realigns; creates rows)
              <CR>           same column in the next row
              <S-CR>         copy the field down (see below)
Normal mode:
  <C-c><C-c>      realign; in a row marked `#` recalculate that row; with a
                  count recalculate the table (4) or iterate it (16); on
                  a `#+TBLFM` line apply that line (see below); on
                  `#+PLOT:` plot; on `#+ORGTBL:` recalculate and send
  <C-c>*          recalculate the current row (column formulas of the row
                  and every field formula); count 4: the whole table;
                  count 16: until it no longer changes (org-table-iterate)
  <M-h/l>         move column left / right (also <M-Left/Right>)
  <M-k/j>         move row up / down (also <M-Up/Down>)

  <M-K>/<M-J>     delete row / insert row above
  <M-CR>          insert row below
  <S-Up/Down/Left/Right>  swap the field with its neighbour
  <S-CR>          copy the field one row down and move there; in an empty

                  are on: `set -s extended-keys on` and
                  `set -as terminal-features 'xterm*:extkeys'`
  <C-c>+          sum the column (or the Visual selection) into the

  <C-c><Tab>      shrink / expand the column (see |org-table-shrink|)
  <C-c>`          edit the field in a prompt; count 4: show a shrunk
                  column in full; count 16: follow-field mode
  <C-c>{          toggle the formula debugger (|org-table-debugger|)
  <C-c>"a <C-c>"g ASCII bar plot / gnuplot plot (|org-plot|)
  <prefix>Tc      create a table ("5x3"), or convert CSV/TSV/whitespace
                  (Visual mode; count 4: comma, 16: tab, N: N+ spaces)
  <prefix>T-      insert a hline (<C-c>- with a count: above)
  <prefix>Tf      recalculate the whole table
  <prefix>Ts      sort rows (<C-c>^, see below)
  <prefix>Tr/TR   insert / delete row
  <prefix>Ti/TI   insert / delete column
  <prefix>Tt      transpose the table (hlines are dropped)
  <prefix>T#      rotate the recalculation mark ` # * ! $ _ ^` of the row
                  (Visual mode: set a mark on every selected row); a
                  marker column is added when needed
  <prefix>'       the formula editor (|org-table-formula-editor|)
  :Org table_import   insert a CSV/TSV/whitespace file as a table
  :Org table_export   write the table with a translator: the file and
                      format come from the TABLE_EXPORT_FILE and
                      TABLE_EXPORT_FORMAT (`orgtbl-to-latex :splice t`)
                      properties when set, else from prompts (the format
                      offered matches the file extension, else
                      `table_export_default_format`)
  :Org table_iterate  :Org table_recalc_buffer (all tables, iterated)

Inserting, deleting and moving rows and columns rewrites the references of
every `#+TBLFM` line below the table like Emacs org-table-fix-formulas:
`$3=$1+$2` becomes `$2=$INVALID+$1` when column 1 is deleted, formulas that
assign to a deleted row or column are removed, references inside remote()
are left alone. Set `table_fix_formulas_confirm` to be asked first. A new
row copies a `#`, `*` or `$` mark of the current row.

Sorting (<C-c>^, org-table-sort-lines) sorts the rows between the hlines
around the cursor, or the rows of the Visual selection: `a` text (emphasis
markers and link brackets ignored; case-insensitive, case-sensitive with a
count), `n` numbers, `t` timestamps, durations and H:MM, `f` a key function
typed as Lua (`function(s) return #s end`) with an optional comparison
function; the uppercase letters sort in reverse.

Alignment: a column is right-aligned when at least `table_number_fraction`
(0.5) of its fields are numbers. `<l>`, `<r>` and `<c>` cookies (`<r10>`
with a width) fix the alignment; cookie cells are aligned like the column.

Type `=formula` in a field and press <Tab>, <CR> or <C-c><C-c>: it becomes
the column formula of that column (`:=formula` a field formula for that
field), is stored in `#+TBLFM` and the field is computed (<C-c>* updates
the rest). `table_formula_evaluate_inline` turns this off.

<C-c>= reads the formula of the current column (count: of the current field,
or its `^`/`_` name; count 16: put the active formula into the field as
`=...` for editing), stores it and computes the field. An empty formula
removes it. A1-style references (`B3`, `C&`) are accepted when typed
(`table_use_standard_references`).

                                                        *org-table-formulas*
Formulas go in `#+TBLFM:` lines below the table: >org
    | Item  | Qty | Price | Total |
    |-------+-----+-------+-------|
    | Apple |   3 |  0.50 |  1.50 |
    | Pear  |   2 |  0.75 |  1.50 |
    |-------+-----+-------+-------|
    | Sum   |     |       |  3.00 |
    #+TBLFM: $4=$2*$3;%.2f::@>$4=vsum(@I..@II);%.2f
<
Only the first `#+TBLFM:` line is used. Keep alternatives in more lines
below it and press <C-c><C-c> on one of them to apply it once
(org-table-calc-current-TBLFM). Storing formulas (<C-c>=, inline formulas,
the formula editor) rewrites only the first line (or the edited one), with
the formulas sorted like Emacs.
References:
  $2  $>  $<  $>> $+1 $-1    columns
  @3  @>  @<  @<< @-1 @I @II rows / hlines
  @2$3                       a single field
  @2$1..@4$3  $1..$3         ranges
  @# $#                      the current row / column number
  remote(name, @2$1)         a field of a named table (#+NAME:)
  $name                      a named column, field, parameter or constant
Names, looked up in this order:
  `!` row           `| ! | | qty | price |` names the columns below it
  `^` / `_` rows    name the field in the row above / below (a formula
                    sees the value it had before the recalculation, like
                    Emacs, so iterate to use a fresh one)
  `$` row           `| $ | max=50 |` defines a parameter
  constants         `#+CONSTANTS: tax=0.16 rate=18.5`, then the
                    `table_formula_constants` option
  $PROP_Name        the Name property of the entry (inherited)
  header row        (extension) `$Total=$Qty*$Price` uses the header above
                    the first hline when there is no `!` row
Column formulas run on the rows below the first hline (all rows without
one); when the first column holds marks (`! $ ^ _ # *`), only on rows
marked `#` or `*`. Rows marked `! ^ _ $ /` are never changed. Formulas run
row by row in the order of their sorted left sides, column formulas first,
then field formulas. A column formula beyond the last column adds the
column; a field formula does so only with `table_formula_create_columns`
(true, "warn" or "prompt"; false: an error).

                                                           *org-table-calc*
Formulas are GNU Calc expressions, evaluated by a Lua reimplementation of
the parts Org tables use. As in Emacs, each reference is replaced by the
field text (`(3)`; ranges `[1,2,3]`, empty fields dropped) before the
formula is evaluated, so:
- Calc precedence: `/` binds looser than `*`, `a/b*c` is `a/(b*c)`; `^`
  binds tighter than unary minus (`-2^2` is -4); `2 3` and `2(3+1)`
  multiply; `a ? b : c`; `!` factorial, `%` percent (`10%`) or modulo.
- Numbers: exact integers of any size (`2^100`), floats with 12 digits and
  Calc's display with 8 (`3.`, `0.33333333`, `1e-3`, `1.2345679e12`),
  fractions `3:4` (`F` flag), vectors `[1, 2]` (`|` concatenates, `*` of
  two vectors is the dot product).
- Dates: `<2024-01-10 Wed>` (also `[...]` fields) is a date; subtracting
  two gives days (`$2-$1`), adding a number gives a date (written as an
  inactive timestamp), `date(<...>)` gives the day number.
- Text stays symbolic: `$1*2` on `x` gives `2 x`, `sqrt(x)` stays,
  `if($1>3, big, small)` returns `big`/`small`; `pi` and `e` stay
  symbols. With `N` a non-numeric result is #ERROR.
- Functions: vsum vmean vmin vmax vcount vprod vmedian vsdev vpsdev vvar
  vpvar vlen rev sort, abs sqrt exp ln log log10 exp10 floor ceil round
  trunc frac idiv mod `\` gcd lcm fact choose perm sign min max hypot, sin
  cos tan arcsin arccos arctan arctan2 sinh cosh tanh deg rad (degrees
  unless `R`), if lnot, date year month day hour minute second weekday
  now. Unknown functions stay symbolic, e.g. `foo(x)`.
Flags after `;` (org-table-eval-formula): Calc modes `p20` (precision),
`n3` (significant digits), `f2` (fixed), `s3` / `e3` (scientific /
engineering), `N` (fields as numbers), `E` (keep empty fields, as `nan` in
Calc), `R` / `D` (radians / degrees), `F` (fractions), `T` / `t` / `U`
(fields and results as durations: H:MM:SS, hours (see
`table_duration_custom_format`) and H:MM; `table_duration_hour_zero_padding`),
`L` (Lisp literal). Like Emacs, these letters are removed from the rest,
which is a printf format applied to the result: `%.2f`, `%.1f%%`, `%d`.
Lisp formulas: `'(+ $1 $2);N`, `'(concat $1 "-" $2)`: fields become Lisp
strings, numbers with `N`, verbatim text with `L`; ranges become several
arguments; a list result is #ERROR. See |org-differences| for the Lisp
subset. Lua formulas (extension): `$3='(string.upper($1))` (a `'(...)`
that is not Lisp).
Errors show as #ERROR.

                                                         *org-table-shrink*
<C-c><Tab> in a table shrinks the current column, or shows it again
(org-table-toggle-column-width): a shrunk column shows the first W

                                                  *org-table-follow-field*

19. SOURCE BLOCKS (BABEL)                                          *org-babel*
>org
    #+NAME: hello
    #+begin_src python :results output :var n=3
    for i in range(n): print("hi", i)
    #+end_src
<
Babel follows Emacs Org 9.8: the same header arguments, the same way values
are read from programs and written back (tables, lists, `: ` lines), the same
`#+RESULTS` placement, `:cache` hashes and tangled files, so a file gives the
same results in both editors.

<C-c><C-c> or <prefix>be   Execute the block, #+CALL line, inline src block
                           or inline call at the cursor (asynchronously).
                           With a count (C-u) a `:cache yes` block runs even
                           when its hash is unchanged.
<prefix>bb / bs    Execute every src block, #+CALL line, inline src block
                   and inline call of the buffer / subtree, in order.
<prefix>bk         Remove the result. With a count (C-u), remove every
                   result in the buffer.
<prefix>bn / bp    Next / previous block.
<prefix>'          Edit the block in a buffer with the language's filetype.
                   With a count (C-u) on a block with a `:session`, show
                   the session instead. See |org-babel-edit-special|.
<prefix>bt         Tangle the file (`:Org tangle`). With a count of 1
                   (C-u) only the block at the cursor; with 2 or more
                   (C-u C-u) the blocks with the same `:tangle` value.
<prefix>bf         Tangle another file.
<prefix>bv         Show the expanded block (noweb, :prologue, variables,
                   :epilogue) in a split.
<prefix>bI / bc    Show the block's merged header args / report a header
                   arg of the #+begin_src line that looks like a misspelt
                   one (within 2 edits of a known name, like Emacs).
<prefix>bj         Insert a header argument (names and values completed).
<prefix>bg / br    Go to a named block / a named result.
<prefix>bu         Go to the head of the block.
<prefix>bo         Open the result (follows a file link, or shows it).
<prefix>bd         Split the block at the cursor into two; in Visual mode
                   wrap the selection in a new block (or, inside a block,
                   make it a block of its own); elsewhere insert a block.
<prefix>bi         Add the named blocks of a file to the Library of Babel,
                   so #+CALL, :var and noweb can use them everywhere
                   (also <C-c><C-v><Tab>).
<prefix>bz / bZ    Show the block's session (with a count, first assign
                   its :var values there); bZ also opens the edit buffer.
<prefix>bl         Send the block to its session and show the session.
<prefix>bK         Kill the block's session.
<prefix>ba         Show the block's hash (the one `:cache yes` stores).
<prefix>bh         List the Babel key bindings.
<prefix>bm         Select the block body (Visual line mode).
<prefix>bx         Run Normal-mode keys in the block's edit buffer and
                   write the result back (e.g. `gg=G` to reindent).
<Tab> on #+RESULTS Fold / unfold the result (org-babel-hide-result-toggle);
                   `:Org babel_hide_all_results` folds every result.
#+CALL: name(n=5)  Execute a named block with arguments (C-c C-c on it).
                   `#+NAME:` above a call names its results. Arguments
                   without `name=` fill the block's variables in order:
                   `#+CALL: add(10, 20)`.
src_lua{return 1}  Inline block: C-c C-c on it inserts or replaces
                   ` {{{results(=1=)}}}` after it. `:results raw` inserts
                   the bare value; tables, lists and multi-line results
                   are an error ("Inline error: ... cannot be used").
call_name(n=5)     Inline call, same as above.

Evaluation ~
Before a block runs you are asked "Evaluate this LANG code block on your
system?" unless `babel.confirm_evaluate` is false. It can also be a
function `function(lang, body) return true end` that decides (like Emacs'
`org-confirm-babel-evaluate`). `:eval query` always asks, `:eval no` and
`:eval never` (or `:noeval`) never run, `:eval never-export`/`no-export`
only skip export, `:eval query-export` asks when exporting. Executing the
buffer or a subtree asks for every block, like Emacs. With
`babel.no_eval_on_ctrl_c_ctrl_c` C-c C-c does not evaluate blocks.

Errors: whatever a program writes to stderr, and its exit code when it
fails, go to the `*Org-Babel Error Output*` buffer (shown in a split); the
result keeps the standard output only, like `org-babel-eval`. A missing
reference or an inline result that cannot be inserted stops the execution
of the buffer.

Hooks are `User` autocommands: `OrgBabelAfterExecute` (after a result is
inserted; `data` has bufnr, lang, name, result), `OrgBabelTanglePre`,
`OrgBabelTangleBody` (the body being tangled is in
`require("org.babel.tangle").body`, which the callback may change),
`OrgBabelTanglePost` (per written file, `data.file`) and
`OrgBabelTangleFinished`.

Results ~
A block's result is its value (`:results value`, the default) or what it
prints (`:results output`). Like Emacs:
  - Python, Ruby and JavaScript values are read from their printed form:
    `[[1,2],None,[3,4]]` is a table with a hline, `1.0`, big integers,
    `True`, `None` keep their spelling, a dict stays text (a table with
    `:results table`, a `key :: value` list with `:results list`),
    `:results verbatim` / `pp` / `scalar` keep the text (pprint for pp).
  - Shell blocks default to their output (`:results value` is the exit
    status). Unless `output`, `verbatim`, `raw`, `org`, `html`, `code`,
    `pp` or `file` is given, the text is read like
    `org-babel-import-elisp-from-file`: several lines become a table split
    at tabs, commas or runs of spaces, numbers are read, one line stays
    text (`echo a b` gives `: a b`, `printf 'a\nb\n'` a two-row table).
  - sqlite runs `sqlite3 -csv` (`-header` with `:colnames yes`) and passes
    `:header :echo :bail :csv :column :html :line :list :separator
    :nullvalue` (and `:readonly yes`) to it.
  - Lua blocks run inside Neovim (not an external `lua` like Emacs): a
    returned table becomes a table or list, `return "a", "b"` gives `a, b`,
    `nil` gives `nil`. Code runs in the editor process: it can use the
    `vim` API, but `os.exit()` or a blocking loop affects Neovim, and
    `babel.timeout` cannot stop it. `print` goes to the result.
Results are inserted after `#+RESULTS:` like `org-babel-insert-result`:
text as `: ` lines (an example block from `babel.min_lines_for_block_output`
lines), lists as tables (with `:results list` as a plain list), `raw`,
`drawer` (`:results:` ... `:end:`), `org`, `html`, `latex`, `code` and
`:wrap` as in Emacs. A paragraph below `#+RESULTS:` is not part of the
result and stays when the result is replaced.

Sessions ~
`:session [name]` runs the block in a long-lived interpreter shared by every
block with the same language and name (no name = `default`), so variables,
imports, functions and the working directory persist between blocks.
Supported: shells (sh, bash, zsh, fish), python, js/node, ruby and lua (lua
sessions keep their globals inside Neovim). Other languages ignore
`:session` with a warning.
  - `:results value` is the value of the last expression (python, ruby,
    js), formatted like Emacs, or the returned value (lua); shells use their
    output unless `:results value` is explicit, which gives the exit status.
  - stderr is merged into the output, like an Emacs REPL buffer.
  - Each session has a transcript buffer (`org-babel-session://lang/name`)
    showing what ran; type at its prompt to evaluate a line in the session.
    Wiping that buffer kills the session.
  - The session starts in the block's `:dir`. A top-level `let`/`const` in
    a js session becomes `var`, so blocks can be evaluated again.

Languages ~
`babel.languages` maps a language name to `{ cmd = "...", ext = "...",
default_header_args = {...} }`. `default_header_args` are that language's
defaults (Emacs `org-babel-default-header-args:LANG`). Emacs enables only
emacs-lisp (`org-babel-load-languages`); the plugin enables shells, python,
lua, js/ts, ruby, perl, php, R, go, rust, sqlite, sql, C, C++/cpp, D and awk
because emacs-lisp cannot run in Neovim (see below). `:python`, `:ruby` and
`:cmd` (js) choose the interpreter of one block, like Emacs.
  - python: `:return expr` (the value of `expr`), `:preamble`, and
    `:results graphics file :file x.png` (the matplotlib figure is saved).
  - C, C++ (cpp) and D (ob-C): compiled with gcc / g++ (rdmd for D) and
    run; `:includes <stdio.h>`, `:defines N 5`, `:namespaces std`,
    `:flags -O2`, `:libs -lm`, `:main no`, `:cmdline args`; table
    variables become arrays with `NAME_rows` / `NAME_cols` (and
    `NAME_h(row, "col")` with `:colnames yes`).
  - sql (ob-sql): `:engine postgresql|mysql|mssql|sqsh|vertica|monetdb|dbi`
    runs that client with `:dbhost :dbport :dbuser :dbpassword :database`
    (`:out-file`); without `:engine` the plugin runs sqlite3 with `:db`.
    `$name` in the body is replaced by `:var name` (a table becomes a CSV
    file name).

Header arguments ~
Header arguments merge like Emacs: `babel.default_header_args` (inline
blocks: `default_inline_header_args`, #+CALL: the called block's, then
`default_lob_header_args`), the language's `default_header_args`, the
`header-args` and `header-args:LANG` properties (the nearest headline that
sets one wins; `header-args+:` adds to the inherited value; `#+PROPERTY:`
applies when no headline sets it), the `#+begin_src` line, then `#+HEADER:`
lines (the last wins).
  :results   output|value; replace|append|prepend|silent|none|discard;
             verbatim|scalar|table|vector|list|file; raw|org|drawer|html|
             latex|code|pp|link|graphics
  :var       name=value, name="string", name=named-table, name=list,
             name=table[1,2], name=table[1:3,-1] (0-based ranges and
             negative indices count every row, the header and hlines
             included; `[,1]` = a column). A reference to a src block or
             `#+CALL` evaluates it: name=block, name=block(x=1),
             name=block(1, 2), name=block[:results output](x=1),
             name=block(x=1)[0]; `name=block[]` is its body text. Other
             forms: file.org:name, an ID or CUSTOM_ID (the headline's
             text), Emacs Lisp literals `'(1 2 3)` and simple forms
             `(+ 1 2)`. Bash gets tables as associative arrays and lists
             as arrays; sqlite/sql replace `$name`.
  :hlines    yes: keep the hlines of table variables (None / nil / hline)
  :separator cell separator of tables given to shells (default: tab)
  :stdin     ref: feed a value to the stdin of a shell block
  :session   [name]: see Sessions above
  :colnames  a table variable whose 2nd row is the only hline loses its
             header row; `yes` always takes the first row as names and
             puts them back on a table result of the same width (the
             default, like Emacs 9.8, does not put them back); `no` keeps
             the header as data; `'(a b)` names the result's columns
  :rownames  yes: the same for the first column
  :wrap      [type [params]] wrap the result in #+begin_type (default
             `results`), e.g. `:wrap src python`, `:wrap export html`;
             `:wrap no` inserts the result as it is
  :cache     yes: store a hash in `#+RESULTS[hash]:` and reuse the result
             while the parameters and body are unchanged. The hash is
             computed like `org-babel-sha1-hash`, so it matches Emacs
             (`babel.hash_show_time` adds the date). Works on #+CALL too.
  :file      with `:results file` the result is written to the file
             (relative to `:dir`; the directory must exist) and a link is
             inserted (relative to the Org file); `:results file link` /
             `graphics` only links. :output-dir (created), :file-ext (with
             #+NAME), :file-mode `(identity #o755)`, :sep (for tables),
             :file-desc (no value = the file name, `[]` = none)
  :dir :cmdline :prologue :epilogue :noweb-ref :mkdirp yes (for :dir)
  :noweb     yes|no|tangle|eval|no-export|strip-export|strip-tangle|
             tangle-eval. Every <<ref>> of a line is expanded (references
             may contain spaces: `<<add(a=3, b=4)>>`); blocks sharing a
             :noweb-ref are joined with :noweb-sep (default a newline);
             :noweb-prefix no stops repeating the text before the
             reference. `<<name(x=1)>>` inserts the result of evaluating
             the block; `<<id>>` of a headline with that CUSTOM_ID or ID
             inserts its text. Blocks in COMMENT subtrees are skipped.
  :exports   code|results|both|none (for export)
  :post      name(arg=*this*): run the named block on the result; its
             result is inserted instead
  :tangle :comments :padline :shebang :tangle-mode :no-expand  see below
Switches: `-i` keeps the indentation of the lines (like
`src_preserve_indentation`, Emacs `org-src-preserve-indentation`),
otherwise the common indentation of a block is removed before it runs;
`-n` / `+n` number lines and `-r` / `-l "fmt"` handle coderefs (always
removed before a block runs).

Tangling ~
`:tangle yes|FILE` writes a block to a file (`yes`: the Org file's name with
the extension of `babel.tangle_lang_exts` or the language name, as Emacs:
`python` → `.py`, `sh` → `.sh`, `bash` → `.bash`). Like `org-babel-tangle`:
  - the Org buffer is saved first; blocks in COMMENT and :ARCHIVE:
    subtrees are skipped; `:var` assignments, `:prologue`/`:epilogue` and
    noweb references (`:noweb yes|tangle`) are written; `-r` removes
    coderef labels; unchanged files are not rewritten.
  - `:comments link` (and `yes`) wraps each block in
    `[[file:x.org::*Heading][Heading:N]]` ... `Heading:N ends here`
    comments (N counts the blocks of the entry; a named block uses its
    name; the link is relative to the tangled file,
    `babel.tangle_use_relative_file_links`), `:comments org` writes the
    Org text before the block as comments, `both` does both, `noweb` also
    wraps every noweb expansion. The formats are
    `babel.tangle_comment_format_beg` / `_end`.
  - `:padline no` removes the blank line between blocks; `:shebang` goes
    on the first line and makes the file executable; `:mkdirp yes` creates
    the directory; `:tangle-mode o755`, `(identity #o755)`, `rwxr-xr-x` or
    `u+x` (added to `babel.tangle_default_file_mode`) set the mode.
From a tangled file:
  :Org tangle_jump      jump to the Org block the cursor is in
                        (org-babel-tangle-jump-to-org)
  :Org detangle [file]  copy the edited bodies back into the Org blocks
                        (org-babel-detangle; needs link comments)
  :Org tangle_clean     remove the link comments and noweb references
                        (Emacs 9.8's org-babel-tangle-clean removes
                        nothing because of a bug; this does what its
                        documentation says)
`:Org babel_load_file [file]` tangles the `lua` blocks of an Org file to
FILE.lua (again only when the Org file is newer) and runs it with `dofile`,
the Lua counterpart of `org-babel-load-file` (e.g. an init.org).

Library of Babel and tables ~
`org-sbe` works in Emacs Lisp table formulas: >org
    | 2 | 4 |
    #+TBLFM: $2='(org-sbe "square" (x $1))
<
evaluates the block `square` with `x` set to the first column (`$$1` passes
the field as a string, a first string argument holds header arguments).

Export ~
With `babel.evaluate_on_export = true` (the default, Emacs
`org-export-use-babel`) exporting first evaluates, in a copy of the buffer,
the blocks and #+CALL lines with `:exports results|both`, inline src blocks
and calls, and `:exports code|none` blocks that use a session; each one is
confirmed like any evaluation. `:eval never-export|no-export` blocks keep
their existing results. With `false`, export uses the `#+RESULTS` already in
the buffer.

                                                        *org-babel-edit-special*
<prefix>' (C-c ') also edits, like `org-edit-special`: example, export and
comment blocks, LaTeX environments, `: ` fixed-width areas, the body of an
inline src block (kept on one line), the definition of the footnote at the
cursor (inline definitions cannot contain blank lines), a LaTeX fragment
(`$x$`, `\(x\)`, `\[x\]`); it visits the file of an INCLUDE, SETUPFILE or
BIBLIOGRAPHY keyword, runs deadline / schedule on a planning line and the
date prompt on a timestamp, and follows a link. Elsewhere: "No special
environment to edit here".

Not supported ~
  - emacs-lisp (elisp) blocks cannot be evaluated: Neovim has no Emacs Lisp
    interpreter (the small evaluator used by table formulas only knows
    arithmetic, strings and lists). They can still be tangled and exported.
  - Header values that are arbitrary Emacs Lisp (`:dir (concat ...)`,
    `:var x=(some-function)`, `:results (if ...)`): only the forms the
    table formula evaluator knows are evaluated.
  - `org-babel-load-file` for Emacs Lisp, and Emacs hook functions (hooks
    are `User` autocommands instead).
  - Asynchronous sessions (`:async`), `:results xmp` (Ruby rcodetools),
    Indium js sessions, and SQL sessions and `:dbconnection` (Emacs'
    `sql-connection-alist`).
  - Attachment links for `:file` results inside the attachment directory
    (`attachment:` links) and `:dir 'attach`.

20. DYNAMIC BLOCKS                                               *org-dblocks*
>org
    #+BEGIN: clocktable :scope file :maxlevel 2 :block thisweek
    #+END:
<
<prefix>xu / xU  Update the block at the cursor / all blocks. <C-c><C-c> on
                 the `#+BEGIN:` line also updates it.

clocktable parameters (the output matches Emacs 9.8):
  :scope     file|subtree|tree|treeN|agenda|agenda-with-archives|
             file-with-archives|("a.org" "b.org")
  :maxlevel  N (default 2)
  :block     today, yesterday, thisweek, lastweek, thismonth, lastmonth,
             thisq, lastq, thisyear, lastyear (the this* forms and today
             take -N / +N), untilnow, 2026-09-23, 2026-W39, 2026-Q3,
             2026-09, 2026. It wins over :tstart / :tend.
  :tstart / :tend   timestamps or <now>, <today>, <yesterday>,
             <tomorrow>, <-2d>, <+1w>, <-3h> (h from now, d w m y from
             today)
  :wstart / :mstart  first day of the week (1 = Monday) / of the month
  :step      day|week|semimonth|month|quarter|year: one table per period
             of the :block or :tstart/:tend range (`:stepskip0 t` skips
             empty ones)
  :match     a match string (|org-match-syntax|)
  :formula % add a percentage column; :formula "$3=$2;t" adds a
             #+TBLFM line. A #+TBLFM below the table survives updates.
  :sort (2 . ?T)  sort the rows by a column (a/A n/N t/T)
  :lang de   headers in de, es, fr, nl, nn, pl, pt-BR or sk
  :filetitle t  #+TITLE instead of the file name in the file column
  :properties ("Effort" "OWNER")   property columns (`:inherit-props t`)
  :level t   a level column        :timestamp t  a timestamp column
  :tags t    a tags column         :emphasize t  bold level 1, italic 2
  :link t    link headlines        :fileskip0 t  skip files without time
  :hidefiles t  no file column     :tcolumns N   at most N time columns
  :compact t    one time column, indented headlines
  :indent nil   no `\_` indentation
  :narrow 40!   cut headlines at 40 characters (the default); :narrow 40
                adds a <40> width row instead
  :header "text"  replace the `#+CAPTION:` line

columnview parameters: `:id local|global|file:path|ID` (default local),
`:maxlevel`, `:skip-empty-rows`, `:indent`, `:format`, `:match` (tags /
property match), `:exclude-tags (a b)` (inherited tags count), `:hlines t|N`
(a hline before each entry, or each entry of level N or less), `:vlines t`
(column groups), `:link t` (link items to their headings), `:formatter`
(the name of a global Lua function `function(rows, params)` returning the
lines; `columns_dblock_formatter` sets one for every block; rows are the
titles, "hline", then `{ level = n, hl = headline, cells... }`). Like Emacs
(org-columns-dblock-write-default), a first row of width cookies (`<25>`)
is written when the format has widths, and the columns are shrunk; ITEM
loses statistics cookies, footnote references, targets and inline src
blocks / calls; archived and commented subtrees are skipped. Keywords like
`#+NAME:` above the table and the first `#+TBLFM:` line below it are kept,
and the formulas re-applied. A `|` in a value is written as `\vert{}` (Emacs
writes it raw, which breaks the table).

Custom blocks: >lua
    require("org.dblock").register("myblock", function(params, ctx)
      return { "| generated | table |" }
    end)

21. EXPORT                                                        *org-export*

The exporter is a port of Emacs Org 9.8.10 `ox.el` and its back-ends: the
buffer is parsed into the same element tree as org-element, and each
back-end turns it into text with the same transcoders, so the output of
HTML, LaTeX, Beamer, Markdown, ASCII, Org and iCalendar matches Emacs.

<prefix>e (Emacs `C-c C-e`) opens the export dispatcher:
  b / s / v / a  toggle body only / subtree only / visible only / async
  c f  iCalendar: current file   c a  every agenda file   c c  combined
  h H  HTML buffer      h h  HTML file          h o  HTML file and open
  l L  LaTeX buffer     l l  LaTeX file         l p  PDF   l o  PDF, open
  l B  Beamer buffer    l b  Beamer file        l P  PDF   l O  PDF, open
  m M  Markdown buffer  m m  Markdown file      m o  Markdown file, open
  m G  GFM buffer       m g  GFM file
  O O  Org buffer       O o  Org file           O v  Org file and open
  o o  ODT (pandoc)     o O  ODT and open       d d  DOCX (pandoc)
  t A/a  ASCII buffer/file   t L/l  Latin-1   t U/u  UTF-8
  P f  publish file     P p  current project    P x  a project  P a  all
  p    other format via pandoc
  #    insert the default export template

`:Org export {format} [subtree] [body] [visible] [buffer] [open]` where
format is html, md, gfm, ascii (or txt), latin1, utf8, latex, pdf, beamer,
beamer-pdf, org, ics or a pandoc format (docx, odt, rst, epub, ...).
`:Org publish [project|file|current|all] [force]` publishes projects
(|org-publish|). Lua: `require("org.export").export(format, opts)` returns
the output path, `.to_string(format, opts)` the text.

Output goes next to the source file (named after it or #+EXPORT_FILE_NAME),
or to `export.output_dir`. PDF compiles the LaTeX file with
`export.latex.pdf_process` (latexmk when available, else three runs of
`export.latex.compiler`); it runs in the background with |vim.system()|
unless `export.latex.async_compile` is false. DOCX, ODT and other pandoc
formats run pandoc on the output of the Org back-end.

Export settings ~                                        *org-export-settings*
`#+TITLE`, `#+SUBTITLE`, `#+AUTHOR`, `#+EMAIL`, `#+DATE`, `#+CREATOR`,
`#+LANGUAGE`, `#+SELECT_TAGS`, `#+EXCLUDE_TAGS`, `#+EXPORT_FILE_NAME`,
`#+KEYWORDS`, `#+DESCRIPTION` and back-end keywords (`#+HTML_HEAD`,
`#+HTML_LINK_HOME`, `#+HTML_DOCTYPE`, `#+HTML_CONTAINER`, `#+LATEX_CLASS`,
`#+LATEX_CLASS_OPTIONS`, `#+LATEX_HEADER`, `#+LATEX_HEADER_EXTRA`,
`#+LATEX_COMPILER`, `#+BEAMER_THEME`, ...) as in Emacs. `#+OPTIONS:` takes
every Emacs key: `':` `*:` `-:` `::` `<:` `\n:` `^:` `arch:` `author:`
`broken-links:` `c:` `creator:` `d:` `date:` `e:` `email:` `f:` `H:`
`inline:` `num:` `p:` `pri:` `prop:` `stat:` `tags:` `tasks:` `tex:`
`timestamp:` `title:` `toc:` `todo:` `|:` and the back-end ones
(`html-postamble:`, `html-preamble:`, `html-style:`, `html5-fancy:`,
`html-link-use-abs-url:`, ...). Values are read like Emacs, so lists work:
`tasks:("TODO" "NEXT")`, `d:(not "LOGBOOK")`. Every key has a default in
`export` (|org-config-export|), named after the Emacs variable.
When exporting a subtree, its EXPORT_TITLE, EXPORT_FILE_NAME,
EXPORT_OPTIONS, EXPORT_AUTHOR, EXPORT_DATE, EXPORT_LATEX_CLASS, ...
properties override the keywords. `#` in the dispatcher inserts the default
template (`#+options:`, `#+title:` ... lines, or EXPORT_* properties in
subtree mode).

`#+LANGUAGE:` translates the generated strings ("Table of Contents",
"Footnotes", "Figure", ...) with the Emacs dictionary, and smart quotes
(`':t`) use that language's quotes.

Select tags (`export`) export only the tagged subtrees; exclude tags
(`noexport`) and COMMENT subtrees are removed; archived subtrees keep only
their headline (`arch:`). Headlines deeper than `H:` become lists. Visible
only (`v`) exports what is not folded.

Links: internal links (`[[*Heading]]`, `[[#custom-id]]`, `[[name]]`,
`[[target]]`, radio targets, `id:` links, coderefs) resolve to generated
labels; a link that resolves to nothing stops the export with an error
unless `broken-links:t` (drop it) or `broken-links:mark`. Links whose type
has an `export` function in `links.types` use it, like
`org-link-parameters :export`. `#+TOC: headlines 2 [local]`, `#+TOC:
tables` and `#+TOC: listings` insert lists anywhere.

`#+INCLUDE: "file.org"` includes a file; its headlines become children of
the current one (or start at `:minlevel N`). Add `::*Heading`, `::#id` or
`::name` to include one subtree or named element, `:only-contents t` to
drop the subtree's headline, `:lines "5-10"`, or `src LANG` / `example` /
`export BACKEND` to include it as a block. `#+SETUPFILE:` reads the
keywords of another file.

Macros: `#+MACRO: name text $1 $2` (`$0` = all arguments, `\,` a literal
comma, macros may use other macros), `export.global_macros` (strings or Lua
functions) and the built-ins `{{{title}}}`, `{{{author}}}`, `{{{email}}}`,
`{{{date(FMT)}}}`, `{{{time(FMT)}}}`, `{{{modification-time(FMT)}}}`,
`{{{input-file}}}`, `{{{keyword(NAME)}}}`, `{{{property(NAME[,search])}}}`,
`{{{n(name[,-|N])}}}` and `{{{results(...)}}}`.

Code blocks follow `:exports` when `babel.evaluate_on_export` is true (the
default, Emacs `org-export-use-babel`): results are computed in a copy of
the buffer, with the usual `babel.confirm_evaluate` question. When it is
false the buffer is exported as it is.

Hooks and filters (Emacs `org-export-before-processing-functions`,
`org-export-before-parsing-functions` and `org-export-filter-*-functions`)
are Lua functions: >lua
    export = {
      hooks = { before_parsing = function(backend, lines) return lines end },
      filters = {
        ["final-output"] = function(text, backend, info) return text end,
        headline = { function(text) return text end },
      },
    }
<
Back-ends ~                                              *org-export-backends*
HTML          ox-html: XHTML strict by default (`#+HTML_DOCTYPE: html5`,
              `html5-fancy:t`), default CSS, MathJax, postamble "auto"
              (author, date, creator, validation link), `#+ATTR_HTML`,
              `#+HTML_HEAD`, info.js (`#+INFOJS_OPT`), inline images.
              Source code is not fontified unless `export.html.fontify`
              is a function(code, lang).
LaTeX / PDF   ox-latex: classes (`export.latex.classes`, #+LATEX_CLASS),
              packages, labels, figures and tables with `#+ATTR_LATEX`
              (:width :float :placement :environment :mode :align
              :booktabs :caption ...), math environments, special blocks
              as environments, babel/polyglossia from #+LANGUAGE,
              `src_block_backend` verbatim, listings or minted.
Markdown      ox-md (headline_style "atx", "setext" or "mixed"); tables
              and other constructs without Markdown syntax become HTML.
GFM           GitHub flavoured Markdown (pipe tables, fenced code,
              `- [ ]` task lists), format "gfm".
ASCII         ox-ascii: `:Org export ascii`, latin1 or utf8;
              `export.ascii.charset` sets the default ("ascii").
Org           ox-org: the buffer after macro expansion, #+INCLUDE and
              removal of non-exported subtrees.
iCalendar     |org-export-icalendar|
Beamer        |org-export-beamer|

ASCII ~                                                     *org-export-ascii*
`ascii` exports plain text like Emacs ox-ascii. Text is filled to
`export.ascii.text_width` columns (default 72; the older
`export.text_width` is still read) with two spaces after sentences.
`center`, `justifyright` and `justifyleft` blocks align their text, and
link targets are listed as notes after each section unless
`export.ascii.links_to_notes` is false. `export.ascii.charset` ("ascii",
"latin1" or "utf-8") picks the characters used for entities, bullets,
checkboxes, rules and table borders; the Latin-1 and UTF-8 dispatcher
entries override it. The other layout options (margins, spacing, bullets,
underlines, caption position, verbatim format, drawer and inlinetask
formatters) mirror the Emacs `org-ascii-*` variables of the same name.
`table_use_ascii_art` (ascii-art-to-unicode) is not supported.

Beamer ~                                                   *org-export-beamer*
`:Org export beamer` (dispatcher: l B buffer, l b file, l P PDF, l O PDF and
open) writes a Beamer presentation, derived from the LaTeX exporter like
Emacs ox-beamer. Headlines at the frame level (`H:`, default
`export.beamer.frame_level` = 1) become frames, shallower ones sections
and deeper ones blocks. A headline with `BEAMER_env: frame` sets the
frame level of its subtree. Properties:
  BEAMER_env   block alertblock theorem definition example exampleblock
               proof quote quotation verse structureenv onlyenv
               beamercolorbox, frame fullframe note noteNH appendix
               ignoreheading againframe columns column (plus
               `export.beamer.environments_extra`)
  BEAMER_act   overlay (`<2->`), or a default overlay in brackets `[<+->]`
  BEAMER_opt   frame/block options (`allowframebreaks`, `label=x`, ...)
  BEAMER_col   column width (fraction of \columnwidth)
  BEAMER_ref   frame resumed by `againframe`
  BEAMER_subtitle  frame subtitle
Frames with code or verbatim text get the `fragile` option. An
`@@beamer:<2->@@` snippet at the start of an item, bold text, link or
radio target is its overlay; `#+ATTR_BEAMER: :overlay <+-> :options ...`
applies to lists and images. Keywords: #+BEAMER_THEME,
#+BEAMER_COLOR_THEME, #+BEAMER_FONT_THEME, #+BEAMER_INNER_THEME,
#+BEAMER_OUTER_THEME (all accept `[options]name`), #+BEAMER_HEADER,
#+BEAMER: (raw line), #+SUBTITLE, `#+TOC: headlines N [options]`. With
`toc:` an outline frame titled `export.beamer.outline_frame_title` is
added.

iCalendar ~                                             *org-export-icalendar*
Dispatcher keys (Emacs `C-c C-e c`): `c f` current file, `c a` every agenda
file (one .ics each), `c c` all agenda files combined into
`export.icalendar.combined_agenda_file` ("~/org.ics"). Lua:
`require("org.export.icalendar").export_file()`, `.export_agenda_files()`,
`.combine_agenda_files()`, `.to_string(lines)`.
Entries become VEVENTs from active timestamps (`with_timestamps`, `<:`),
DEADLINE ("DL: " prefix, `use_deadline`) and SCHEDULED ("S: ",
`use_scheduled`); with `include_todo` TODO entries also become VTODOs
(DTSTART/DUE, RRULE with UNTIL, PRIORITY from the priority cookie, STATUS).
Repeaters (`+1w`) give RRULE; APPT_WARNTIME or `alarm_time` adds a VALARM;
SUMMARY, LOCATION, DESCRIPTION, CLASS and TIMEZONE properties are honoured;
the body is the DESCRIPTION (`include_body`). Tags and the category go to
CATEGORIES (`categories`). #+ICALENDAR_EXCLUDE_TAGS and #+ICAL-TTL are read.
Files use CRLF line endings and 75-character folded lines (RFC 5545).
Differences: entries without an ID get a UID derived from the file and the
entry (stable across exports) instead of a random one; diary sexps
(`%%(...)` lines and `<%%(...)>` timestamps) are skipped because Emacs
converts them with its calendar library; `++`/`.+` repeaters give no RRULE
(like Emacs); BBDB anniversaries are not supported.

Citations ~                                                  *org-export-cite*
Citations written as `[cite/STYLE:prefix @key suffix]` are rendered on
export by a citation processor, chosen with `#+CITE_EXPORT: NAME [BIBSTYLE
[CITESTYLE]]` or by `export.cite.export_processors` (default: "basic" for
every back-end). Bibliography files come from `#+BIBLIOGRAPHY:` keywords
(BibTeX .bib/.bibtex or CSL-JSON .json, relative to the exported file) and
`export.cite.global_bibliography`. `#+PRINT_BIBLIOGRAPHY:` inserts the
bibliography at that point. Processors:
  basic     any back-end; styles author (a), noauthor (na), nocite (n),
            text (t), note (ft), numeric (nb) and the default; variants
            bare (b), caps (c), bare-caps (bc); bibliography styles
            "plain", "numeric" or author-year (default).
  natbib    LaTeX; \citep, \citet, ... and \bibliography.
  biblatex  LaTeX; \autocite, \textcite, ..., multi-cite commands,
            \printbibliography[OPTIONS] from ":key value" properties;
            loads biblatex and adds \addbibresource lines.
  bibtex    LaTeX; \cite, \nocite and \bibliography.
Note styles turn a citation into a footnote, moving punctuation according
to `export.cite.note_rules` and the document LANGUAGE. The CSL processor
(citeproc) is not available (it needs the Emacs citeproc-el library); to
use CSL styles, export to Org or Markdown and run `pandoc --citeproc`.

Publishing ~                                                   *org-publish*
Projects are set in `export.publish.projects` (org-publish-project-alist):
>lua
    export = { publish = { projects = {
      site = { base_directory = "~/org/site", publishing_directory = "~/www",
               recursive = true, publishing_function = "html",
               auto_sitemap = true, sitemap_title = "My site",
               makeindex = true },
      static = { base_directory = "~/org/site", base_extension = "png\\|css",
                 publishing_directory = "~/www", recursive = true,
                 publishing_function = "attachment" },
      all = { components = { "site", "static" } },
    } } }
<
Keys are the Emacs plist properties with `_` for `-`. `publishing_function`
is "html", "latex", "pdf", "beamer", "md", "gfm", "ascii", "latin1",
"utf8", "org", "attachment", a Lua function(plist, file, pub_dir) or a list.
`exclude` and `base_extension` are Vim regular expressions matched against
file names relative to `base_directory`. Other keys (with_toc,
html_postamble, ...) are export options for the project's files.
Only files changed since they were last published (or whose #+INCLUDE
files changed) are published; the timestamps live in
`export.publish.timestamp_directory` (default stdpath("data")/org-timestamps/,
Emacs uses ~/.org-timestamps/). With a site map (auto_sitemap) a
"sitemap.org" listing the files ("tree" or "list" style, sorted with
sitemap_sort_files / sitemap_sort_folders) is written and published;
`makeindex` collects #+INDEX: entries into theindex.inc / theindex.org.
Links to headlines of other project files point to the right anchor.
Functions: `require("org.export.publish").publish_all(force)`,
`publish_project(name, force)`, `publish_current_file(force)`,
`publish_current_project(force)`.

Not supported ~                                        *org-export-unsupported*
These need Emacs Lisp or Emacs itself:
- `#+BIND:` (sets Elisp variables) is ignored.
- `(eval ...)` macros are left unexpanded; use `export.global_macros` with
  a Lua function instead.
- ODT has no native back-end (ox-odt writes with Emacs' nXML/zip
  tooling); `o` exports through pandoc.
- Source fontification (htmlize, engrave-faces): HTML code is plain unless
  `export.html.fontify` is set; `src_block_backend = "engraved"` falls
  back to verbatim.
- LaTeX fragments as images (`tex:dvipng`, `dvisvgm`, `imagemagick`) are
  exported as MathJax/verbatim; there is no image conversion.
- table.el tables are exported verbatim.
- Asynchronous export (`a`) only makes PDF compilation asynchronous;
  publishing runs on the editor's event loop.
- Remote (TRAMP) files and directories; `#+INCLUDE` of URLs.
- Generated labels (`orgXXXXXXX`) and iCalendar UIDs are derived from the
  content instead of random, so repeated exports give the same output.
- The default creator string names Neovim and org.nvim instead of Emacs.

23. ENCRYPTION (ORG CRYPT)                                         *org-crypt*

Encrypt the text of an entry with GnuPG, like Emacs' org-crypt. The `gpg`
command (`crypt.gpg_program`) must be installed and set up. The headline,
planning line, property drawer, clock lines, LOGBOOK drawer and the blank
lines after them stay in clear; the rest of the entry, subtree included, is
replaced by an ASCII-armored message (trailing blank lines stay outside):
>
    * Totally secret                                              :crypt:
    :PROPERTIES:
    :CRYPTKEY: 0x0123456789012345678901234567890123456789
    :END:
    -----BEGIN PGP MESSAGE-----

    jA0ECQMIkNjbrRrbvfn80mABVGV15nu5Iag/HgOzdDr3dtq1HTkNqHu2MN2nc6ow
    ...
    -----END PGP MESSAGE-----
<
The format is the one Emacs writes: files encrypted in either editor
decrypt in the other.

:Org crypt_encrypt_entry     Encrypt the entry at the cursor
                             (org-encrypt-entry). Encrypted entries are
                             left alone.
:Org crypt_decrypt_entry     Decrypt the entry at the cursor
                             (org-decrypt-entry).
:Org crypt_encrypt_entries   Encrypt every entry matching
                             `crypt.tag_matcher` (org-encrypt-entries).
:Org crypt_decrypt_entries   Decrypt every matching entry
                             (org-decrypt-entries).
There are no default keys, as in Emacs; bind the actions in `mappings.org`.
`:Org reveal` (<C-c><C-r>) decrypts the entry at the cursor first, as
org-crypt does through `org-fold-reveal-start-hook`. `*_entries` skip
archived and commented trees, like org-scan-tags.

Keys: `crypt.key = false` encrypts symmetrically, always (Emacs
`org-crypt-key` nil). Otherwise the `CRYPTKEY` property (inherited only
through `use_property_inheritance`; the value `nil` means no key), or else
`crypt.key`, is looked up in the public keyring and every key it matches
becomes a recipient. When nothing matches (`""`, the default, never does)
the entry is encrypted symmetrically. Unchanged decrypted text gets its old
message back when encrypted again, so saving doesn't rewrite it.

Passphrases are read with |inputsecret()| (twice when encrypting) and
passed to gpg on stdin with `--pinentry-mode loopback`; for secret keys
they are asked only when gpg-agent has none cached. During one
`*_entries` run or save the symmetric passphrase is asked once.

Encrypting on save: with `crypt.encrypt_on_save = true`, matching entries
are encrypted before the buffer is written (Emacs
`(org-crypt-use-before-save-magic)`). As in Emacs the buffer stays
encrypted after writing; decrypt again to keep working. When an entry
can't be encrypted the write is aborted.

                                                           *org-crypt-leaks*
Emacs' auto-save files leak decrypted text to disk; in Neovim the swap
file ('swapfile') and a persistent undo file ('undofile') do. Before
decrypting in a buffer that has either, `crypt.disable_auto_save` decides
(org-crypt-disable-auto-save): `"ask"` (default) asks whether to turn both
off for the buffer, `true` turns them off, `false` keeps them with a
warning. `"encrypt"` (re-encrypt before auto-saving) is not possible, as
Neovim has no hook before writing the swap file: it acts like `true`.
Text you yank goes to registers, which 'shada' may save; for files you
always keep encrypted consider an autocmd such as: >lua

    vim.api.nvim_create_autocmd("BufReadPre", {
      pattern = "*/secret/*.org",
      command = "setlocal noswapfile noundofile shada=",
    })
<
Tag inheritance: children inherit `crypt`, so `crypt_encrypt_entries` and
`crypt_decrypt_entries` also visit them (harmless: they are encrypted with
their parent). Emacs recommends `tags_exclude_from_inheritance = { "crypt"
}` to keep the tag on the entries that carry it; like Emacs it is not the
default.

Config (`crypt`): `tag_matcher` "crypt" (a |org-match-syntax| expression),
`key` "" (string or false), `encrypt_on_save` false, `disable_auto_save`
"ask", `gpg_program` "gpg".

31. LINTING                                                         *org-lint*

                        `org-lint`) and list the problems in the location
                        list (title "org-lint", entries "checker: message",

                        No default key, as in Emacs.

`{ lnum, col, checker, message, trust }` sorted by position, and
`require("org.lint").show(checkers?)` fills the location list. The buffer is
parsed like Org's element parser, so messages and lines match Emacs.

32. DIFFERENCES FROM EMACS                                   *org-differences*

- Agenda notes (`z`), clock-out and refile notes are single-line prompts;
  state change and schedule notes use a `*Org Note*` split like Emacs
  (`note_buffer`).
- Table formulas: GNU Calc is reimplemented in Lua for what tables use
  (|org-table-calc|); its symbolic algebra (simplification, solving,
  derivatives), units, complex numbers (`sqrt(-4)` stays `sqrt(-4)`
  instead of `(0, 2)`), HMS forms, intervals, error forms and its ~1000
  other functions are not: Calc is a large Emacs package, and results
  here are exact integers, fractions, 12-digit floats, dates or symbolic
  text with only a few simplifications (`x + x` is `2 x`; Emacs's
  `vmean` of symbols is left as `(1 + x + 3) / 3`). Quoted strings
  (`"big"`) are kept as text; Calc makes them vectors of character codes.
  Emacs Lisp formulas `'(...)` run on a small Lisp interpreter (the
  functions listed in `lua/org/table/elisp.lua`): arbitrary Emacs Lisp
  cannot run without Emacs. Any other `'(...)` is a Lua expression.
- Table formula errors: Emacs stops the whole recalculation on some errors
  (a reference outside the table, `$2=` defined twice, unknown remote
  tables); here the field shows #ERROR (the last definition wins) and the
  other fields are still computed. Left sides Emacs rejects are accepted:
  `$name=` for a named column, `$2..$3=` and `@I$2..@>$2=` ranges.
- Tables in the table.el format (`+---+` grids, C-c ~, C-c ' on them) are
  not supported: table.el is a separate large Emacs package; such tables
  are left alone. <M-CR> inserts a row instead of splitting the field.
  Shrunk columns use conceal and virtual text (|org-table-shrink|), the
  header line is drawn in the 'winbar', <C-c>` edits a field in a prompt
  (follow-field mode uses a window) and plots use gnuplot directly (Emacs
  needs gnuplot.el; the radar plot type is missing). The orgtbl-to-unicode
  and orgtbl-to-table.el translators are missing, and translators convert
  Org markup in cells with a simplified exporter.
- Clocking (|org-clock|): the idle time comes from the system on macOS
  (ioreg) and X11 (xprintidle), elsewhere (Wayland, Windows) from Neovim's
  own input, so time spent in other applications counts as idle there.
  The mode line entry is the |org-api| statusline component; clicking it
  has no menu. Timers use counts, so a countdown's C-u (default timer)
  has no count form: a count is always minutes.
- Capture `%(...)`, bulk action `f` and agenda skip functions take Lua
  instead of Elisp.
- Capture edits the text in a separate buffer that is stored at the target
  (resolved when the capture starts) on finalize, instead of an indirect
  buffer narrowed to the text already inserted in the target. So
  `:unnarrowed` (showing the rest of the target file while capturing) is
  not supported, and the target file does not show the new text until the
  capture is finished. Mail and news `%:keyword` values (`%:from`,
  `%:subject`, ...) come from Emacs link sources (Gnus, mu4e, ...) that
  have no Neovim counterpart; only `%:link`, `%:description`,
  `%:annotation`, `%:initial` and `%:type` exist. The last stored location
  (`org-capture-bookmark`, obsolete in Emacs) lasts for the session only.
  `org-extend-today-until` is not applied to capture dates. With C-0
  (`:Org capture_here`) Emacs splits the line at point; the Neovim cursor
  sits on a character, so the text goes before the cursor line at column
  0 and after it otherwise.
- The ID database is JSON, not Emacs's `org-id-locations-file` format, so
  it can't be shared with Emacs. The org-attach git/annex extensions and
  the refile cache (not needed) are not implemented; archiving does not
  loop over a Visual selection (Emacs does only with
  `org-loop-over-headlines-in-active-region`, off by default). Agenda archives-mode and view toggles (`va`, `v[`, ...)
  stay on until toggled off.
- Babel sessions exist for shells, python, js, ruby and lua only, and
  are not full REPLs: each block runs as one request. Lua blocks run
  inside Neovim instead of an external `lua`. `elisp:` links and
  emacs-lisp blocks are not supported; `:var` and header Lisp forms are
  limited to what the table formula Lisp evaluator implements (see
  |org-babel|).
- Export: see |org-export-unsupported|.
- Links (|org-links|):
  - `elisp:` links are not supported: they need an Emacs Lisp interpreter.
    Abbreviations using `%(my-function)` cannot call Elisp either; give
    `links.abbreviations` a Lua function instead.
  - `help:` opens Vim's |:help|: Emacs `help:` links name Elisp functions
    and variables (describe-function), which do not exist here. `info:`
    runs the `info` program in a terminal, `man:` uses |:Man|.
  - Links to Emacs applications (gnus, rmail, mhe, bbdb, irc/erc, eww,
    w3m, bibtex, calendar) can't be followed or stored: there is no such
    application in Neovim. `docview:` opens the file.
  - `shell:` runs in a terminal window instead of collecting the output in
    an `*Org Shell Output*` buffer; `links.confirm_shell` asks with a y/n
    prompt.
  - `::/regexp/` searches translate the common Emacs regexp syntax to Vim
    regexps; Emacs-only constructs (syntax classes other than whitespace
    and words, categories, backward references to point) are approximated
    or unsupported.
  - Internal links followed with a count open in another window on the same
    buffer; there are no indirect buffers
    (org-link-use-indirect-buffer-for-internals), and Vim folds are per
    window anyway.
  - Files Neovim cannot display (images, media, office documents, PDF,
    HTML) open with the system application, where Emacs opens images and
    office documents itself (org-file-apps); `links.file_apps` overrides it.
  - Storing an `id:` link before the first heading stores a `file:` link:
    no file-level ID property drawer is created.
  - Emacs wildcard file links (`file:*.org`) do not open a directory
    listing of the matches.
- Diary sexps are emulated for the common calendar functions and
  `org-calendar-holiday` (|org-agenda-holidays|) only, and the Emacs
  diary is not available in the agenda (|org-agenda-unsupported|).
- Not implemented:
  - MobileOrg (org-mobile): the MobileOrg apps are unmaintained and the
    staging/sync protocol is tied to Emacs; sync the files with any file
    sync tool instead.
  - inline image and LaTeX previews: core Neovim has no image protocol
    (org-link-preview, org-toggle-inline-images, org-image-max-width,
    org-display-remote-inline-images); an image.nvim / snacks.image
    integration could provide them in kitty or sixel terminals.
- Column view is a separate table buffer rather than overlays on the
  headlines. Like Emacs, digits 1-9 select allowed values there, so counts
  are not available in the view (0 keeps its Vim meaning).
- Structure editing:                               *org-structure-differences*
  - Emacs acts at point, between two characters; Normal mode has a cursor
    on a character. Commands that insert at point (<M-CR>, C-c RET,
    drawers, templates, paste) act at the end of the line in Normal mode
    (at its start in column 0) and never split it; in Insert mode they act
    at the cursor like Emacs.
  - Emacs binds M-h to org-mark-element and C-x n b / C-x n e to narrowing;
    here <M-h> promotes and <C-x> decrements, so those are <prefix>v,
    <prefix>nb and <prefix>ne. Narrowing edits the region in a separate
    buffer instead of hiding the rest of the buffer.
  - A count repeats promote / demote (<M-h>, <<); Emacs ignores it.
  - Element commands work on whole lines.
  - Speed commands work in Insert mode at the start of a headline (where
    Emacs would insert the letter); Normal mode keeps Vim's letters.
  - Pretty sub/superscripts can't be raised: Unicode super/subscript
    characters are used when they exist, else a highlight.
  - The org-list-checkbox-radio-mode minor mode is not provided; use
    `#+attr_org: :radio t` or <C-c><C-x><C-r>.
- Visibility (see |org-hidden-lines|): hiding text between visible lines
  needs Neovim 0.11 (`conceal_lines`); hidden lines are shared by the
  windows of a buffer while folds are per window; Vim fold commands don't
  show hidden lines; linewise commands on a closed fold act on the whole
  fold; `catch_invisible_edits` only watches typing on hidden lines (in a
  closed fold the cursor is on its visible first line).
- TODO keywords, tags, properties and dates (see |org-todo|, |org-tags|,
  |org-properties|, |org-dates|):
  - C-c C-t prefix arguments are counts: `C-0` (no note) and `C-- 1`
    (cancel repeaters) have no count form and are the actions
    `todo_without_note` and `todo_cancel_repeaters`; a count of 4 always
    means C-u, so the 4th keyword cannot be picked by count.
  - `#+TYP_TODO:` keywords cycle like a sequence; Emacs jumps to the done
    keyword on the first C-c C-t of a series.
  - The Emacs hooks are User autocmds (`OrgTodoStateChange`,
    `OrgTodoRepeat`, `OrgPropertyChanged`) that cannot change the result;
    only `todo_blockers` (org-blocker-hook) can veto a change.
    org-todo-get-default-hook, org-todo-statistics-hook and
    org-after-todo-statistics-hook have no equivalent.
  - `org-loop-over-headlines-in-active-region` given as a match string is
    not supported (true, false and "start-level" are).
  - The fast tag selection menu is a floating window read one key at a
    time; it does not show the tags on the headline while it is open.
  - Regexps in `use_tag_inheritance` and `use_property_inheritance` are Vim
    regexps; `{...}` in match strings and tag groups are Emacs regexps
    translated to Vim (Emacs-only constructs are approximated).
  - The date prompt refuses text it cannot read at all instead of using the
    default date, and accepts today/tomorrow/yesterday/now; the calendar is
    the plugin's own (no Emacs calendar/diary commands such as holidays,
    sunrise or diary entries in it).
  - The custom timestamp display conceals the timestamp text: the cursor
    moves over the hidden characters, and the real text shows in Insert
    mode or with 'concealcursor' unset.
  - Habit graphs are only drawn in the agenda (as in Emacs); a habit's
    scheduled date must have a repeater of at least one day.
