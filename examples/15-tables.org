* How to use this file
Org tables are plain text: every line that starts with =|= is a table row,
and org.nvim keeps the columns lined up for you while you type. This file
covers everything you can do with a table *without* formulas: creating
tables (by typing, from CSV/TSV text, from a file), aligning, moving around,
adding, deleting and moving rows and columns, horizontal lines, copying a
series down, sorting, transposing, alignment and width cookies, shrinking
columns, column groups, links and markup in cells, names and captions,
exporting a table to a file and table.el tables.

Formulas (=#+TBLFM:=, ~$3=$1*$2~, ~vsum(@2..@-1)~ ...) have their own file:
[[file:16-spreadsheet.org][16-spreadsheet.org]].

- The file starts folded (=#+STARTUP: overview=). Put the cursor on a
  heading and press =<Tab>= to open it; =<S-Tab>= cycles the whole buffer.
- =<prefix>= means your org prefix, =<leader>o= by default (with the
  bundled init file the leader is =<Space>=, so =<prefix>Tc= is
  =<Space>oTc=). Emacs keys (=<C-c>|=, =<C-c>^= ...) work too.
- The exercises change the tables in place. =u= undoes an exercise, so you
  can press =u= and do the next one on the original table. =git checkout
  examples/15-tables.org= restores the whole file.
- =g?= lists every key of the buffer; type =/table= in that list to see the
  table keys.
- Lines starting with *Try:* are exercises. *Expect:* shows the exact result.
  Expected tables are shown inside =#+begin_example= blocks so that they are
  plain text (the table commands leave them alone).
- Lines starting with =# = are Org comments: they explain the example next
  to them and are never exported.

Start Neovim from the repository root with the bundled init file (it sets
the agenda files to =examples/*.org= and a scratch =org_directory=, so your
own notes are never touched):

#+begin_src sh :eval no
nvim -u examples/minimal_init.lua examples/15-tables.org
#+end_src

Two things about keys before you start:

- Every table key under the prefix starts with =T= (=<prefix>Tc=,
  =<prefix>Ts= ...); =<prefix>T= itself does nothing, so you can pause after
  it (which-key, if installed, then lists the table keys).
- The =<M-...>= keys need a terminal that sends Alt. If =<M-j>= does
  nothing, the arrow forms =<M-Down>= =<M-Up>= =<M-Left>= =<M-Right>= do the
  same thing. =<S-CR>= needs a terminal that can tell it from =<CR>= (see
  "Copy down" below for tmux).

* Anatomy of a table
A table is a block of consecutive lines that start with =|= (spaces before
the =|= are allowed). Inside a line, =|= separates the *fields*. A line
that starts with =|-= is a *horizontal line* (an "hline"); it has no fields.
The rows above the first hline are the *header*: they are exported as
column titles. The first line that does not start with =|= ends the table.

# A complete table: one header row, one hline, four data rows.
#+NAME: planets
| Planet  | Moons | Radius (km) | Ringed |
|---------+-------+-------------+--------|
| Mercury |     0 |        2440 | no     |
| Earth   |     1 |        6371 | no     |
| Jupiter |    95 |       69911 | yes    |
| Saturn  |   146 |       58232 | yes    |

What you see above:

- Every row has the same number of fields, padded with spaces so the =|=
  line up. You never type that padding yourself: org.nvim *aligns* the
  table.
- Columns where at least half the non-empty fields are numbers
  ("Moons", "Radius") are right-aligned; the others are left-aligned.
- The hline =|---------+-------+...|= has a =+= where a =|= would be.
- A table can have several hlines; they split it into sections (the sort
  command uses them, see "Sorting rows").

A table does not need a header or an hline. This is a table too:

| apples  | 3 |
| pears   | 5 |
| cherries | 12 |

# ↑ That little table is deliberately NOT aligned: see the next section.

* Aligning a table
Any table command aligns the table it works on. You can also align on
demand:

- =<C-c><C-c>= (or =<prefix><CR>=) with the cursor anywhere in the table.
- Leaving Insert mode (=<Esc>=) inside a table aligns it.
- Aligning adds the missing fields of short rows, turns =|-= into a full
  hline, and trims extra spaces in fields.

*Try:* put the cursor on "cherries" in the little table at the end of the
previous section and press =<C-c><C-c>=.

*Expect:* the fields line up and 12 is right-aligned:
#+begin_example
| apples   |  3 |
| pears    |  5 |
| cherries | 12 |
#+end_example

row with a missing field, a row with an extra field, a bare =|-= line and a
row without a closing =|=.

* Creating tables
** By typing
Start a line with =|= and type the fields separated by =|=. The first
=<Tab>= (or =<Esc>=, or =<C-c><C-c>=) aligns it. A row made of just =|-=
becomes an hline when you press =<Tab>= on it, and =<Tab>= moves to (and
creates) the row below.

# Practice area: put the cursor on the empty line between the two comments.

# End of the practice area.

*Try:* on the empty line of the practice area above, type exactly:
=i|Name|Age= =<Esc>= =o|-= =<Tab>= =Ada= =<Tab>= =36= =<Tab>= =Bob=
=<Tab>= =41= =<Esc>=

(that is: Insert, the header row, leave Insert, open a line below, type
=|-=, then =<Tab>= converts it into an hline and jumps to a new row where you
type "Ada", =<Tab>=, "36", =<Tab>= makes another row ...)

*Expect:*
#+begin_example
| Name | Age |
|------+-----|
| Ada  |  36 |
| Bob  |  41 |
#+end_example

Note: inside a table, =<CR>= in Insert mode always goes to the next row
(creating one when needed), even at the end of the line. To type something
under a table, leave Insert mode and open a line with =o= on the last row;
text that does not start with =|= is no longer part of the table.

** An empty table: =<prefix>Tc=
On a line outside any table, =<prefix>Tc= (Emacs =C-c |=) asks
=Table size Columns x Rows [e.g. 5x2]:= with =5x2= already filled in.
=<CR>= accepts it; to type another size, clear the prompt with =<C-u>= first.
The first row is a header and an hline follows it. On a blank line the
table replaces the line; on a line with text it goes below that line. The
cursor lands in the first field.

** Converting CSV, TSV and whitespace text
Select lines of text in Visual mode (=V=) and press =<prefix>Tc=: each line
becomes a row. The separator is guessed from the selection:

1. a Tab anywhere → split on Tabs (TSV);
2. else a comma anywhere → split as CSV (with ="quoted, fields"= and =""=
   for a literal quote);
3. else → split on runs of spaces.

A count before =<prefix>Tc= (typed in Visual mode, after selecting) forces
the separator: =4= comma, =16= Tab, any other N "N or more spaces" (so
single spaces stay inside fields). A =|= in the data becomes =\vert{}=.
There is no hline in a converted table; add one with =<prefix>T-=
(see "Horizontal lines").

*** CSV
# The next three lines are plain text, not a table (yet).
name,role,city
Ada Lovelace,engineer,London
"Doe, Jane",cook,"New ""Old"" York"

*Try:* put the cursor on "name,role,city", press =V2j= to select the three
lines, then =<prefix>Tc=.

*Expect:* the quotes are gone and "Doe, Jane" stays one field:
#+begin_example
| name         | role     | city           |
| Ada Lovelace | engineer | London         |
| Doe, Jane    | cook     | New "Old" York |
#+end_example

*** TSV
# The two lines below are separated by real Tab characters.
city	country	population
São Paulo	Brazil	12.33

*Try:* =V= on "city", =j=, =<prefix>Tc=.

*Expect:* (the space in "São Paulo" is kept, the Tabs split)
#+begin_example
| city      | country | population |
| São Paulo | Brazil  |      12.33 |
#+end_example

*** Whitespace
# Plain words separated by spaces.
alpha beta   gamma
1 2       3

*Try:* =V= on "alpha", =j=, =<prefix>Tc=.

*Expect:*
#+begin_example
| alpha | beta | gamma |
|     1 |    2 |     3 |
#+end_example

*** Two or more spaces (a count)
Columns of text copied from a terminal often contain single spaces inside a
field. Split on "2 or more spaces" instead:

# "New York" must stay one field.
New York     8.3   USA
Los Angeles  3.9   USA
Mexico City  9.2   Mexico

*Try:* =V= on "New York", =2j=, then =2<prefix>Tc= (the =2= is the count).

*Expect:*
#+begin_example
| New York    | 8.3 | USA    |
| Los Angeles | 3.9 | USA    |
| Mexico City | 9.2 | Mexico |
#+end_example

*Try:* =u= and do it again without the count (=V2j<prefix>Tc=).

*Expect:* every single space splits too, so the city names are cut in two:
#+begin_example
| New    | York    | 8.3 | USA    |
| Los    | Angeles | 3.9 | USA    |
| Mexico | City    | 9.2 | Mexico |
#+end_example

Press =u= to get the text back.

*** Forcing CSV with a count
# The spaces here must not split: force comma with a count of 4.
first name,last name
Grace Brewster,Hopper

*Try:* =V= on "first name", =j=, =4<prefix>Tc=.

*Expect:*
#+begin_example
| first name     | last name |
| Grace Brewster | Hopper    |
#+end_example

(Without the count this would also work, because the comma is found; the
count matters when the text has both Tabs and commas.)

* Moving around in Insert mode
While you are in Insert mode inside a table:

| Key       | Moves to                                                      |
|-----------+---------------------------------------------------------------|
| =<Tab>=   | the next field; after the last field, the next row's first    |
| =<S-Tab>= | the previous field; before the first, the previous row's last |
| =<CR>=    | the same column in the next row                               |

- Every move aligns the table first, so the columns grow as you type.
- Hlines are skipped.
- =<Tab>= in the last field of the last row *adds a row*.
- =<CR>= on the last row, or on a row followed by an hline, *inserts an
  empty row* below it.
- The cursor lands at the start of the field. What you type is inserted
  before the text already there; to replace a field, empty it first with
  =<C-c><Space>= in Normal mode (see "Field helpers").

#+NAME: nav
| Day | Task        | Hours |
|-----+-------------+-------|
| Mon | Write specs |     2 |
| Tue | Review      |     1 |

*Expect:* =<Tab>= after the last field created the "Wed" row:

* Horizontal lines (hlines)
Ways to make an hline:

- Type =|-= on a new line and press =<Tab>= (Insert mode) or =<C-c><C-c>=.
- =<prefix>T-= or =<C-c>-=: insert an hline *below* the current row.
- =1<C-c>-= (any count): insert it *above* the current row.
- =<C-c><CR>=: insert an hline below the current row and move to the row
  under it, creating an empty row when there is none.

An hline is a row like any other for =<M-k>= / =<M-j>= (move) and =<M-K>=
(delete).

* Copy down and series: =<S-CR>=
=<S-CR>= (Normal or Insert mode) copies the current field into the row
below and moves there, adding a row when the table ends (or an hline
follows). While copying it *increments*:

- a number: +1, or +the difference to the field above when that field is a
  number too (so 5, 10 continues 15, 20);
- text that starts or ends with a number (=Item 1=, =Room 101=,
  =3 apples=): that number, same rule;
- a timestamp: +1 day, or +the difference in days to a timestamp above
  (so a weekly series stays weekly);
- anything else is copied unchanged.

In an *empty* field, =<S-CR>= fills it from the nearest non-empty field
above (with a count N: the Nth one above) and stays in that row.

Set =table_copy_increment = false= to copy without incrementing, or to a
number to use that step.

(=set -s extended-keys on= and =set -as terminal-features 'xterm*:extkeys'=).

* Column widths and shrinking
A *width cookie* =<N>= (or =<lN>=, =<cN>=, =<rN>= with an alignment)
limits how much of a column is *shown*. It never cuts your text: the table
is aligned to the full text, and the column is only narrowed on screen when
you *shrink* it:

- =<C-c><Tab>= in a column: shrink it, or show it again. A column with a
  width cookie shows its first N characters followed by =…=; a column
  without a cookie collapses to just =…=.
- =4<C-c><Tab>=: shrink every column that has a width cookie, expand the
  others (Emacs =org-table-shrink=).
- =16<C-c><Tab>=: expand every column.
- =<C-c><Tab>= with the cursor before the first =|= (press =0= first):
  asks =Column ranges (e.g. 2-4 6-):= and toggles those columns.
- =#+STARTUP: shrink= in a file (or =startup_shrink_all_tables = true=)
  shrinks the cookie columns of every table when the file opens.

Shrinking uses conceal and virtual text, so it sets ='conceallevel'= to 2.
The text in the file never changes (=:set conceallevel=0= shows it). In
Insert mode the table is shown in full, and it shrinks again when you leave
Insert mode. =4<C-c>`= shows the column of the cursor in full; =<C-c>`= on
a shrunk field lets you read and edit the whole text.

* Column groups
A row whose first field is =/= defines *column groups* for export: in the
other fields of that row, =<= starts a group, =>= ends one, and =<>= makes a
column a group of its own. Exporters draw vertical lines between groups
(HTML uses =<colgroup>= elements, LaTeX =|= in the column spec, ASCII =|=).
Inside the editor the row is an ordinary row; like a cookie row, it is not
exported as data.

#+NAME: groups
| N | N^2 | N^3 | N^4 | sqrt(n) | sqrt[4](N) |
| / |   < |     |   > |       < |          > |
|---+-----+-----+-----+---------+------------|
| 1 |   1 |   1 |   1 |       1 |          1 |
| 2 |   4 |   8 |  16 |  1.4142 |     1.1892 |
| 3 |   9 |  27 |  81 |  1.7321 |     1.3161 |

This makes three groups: N alone (the first column always starts a group),
the powers N^2 to N^4, and the two roots.

*Try:* with the cursor in this section, press =<prefix>e= (the export
menu), =s= (scope: this subtree), =t= (plain text), =A= (as an ASCII
buffer). Find the table in the new buffer; =:q= closes it.

*Expect:* vertical bars only between the groups:
#+begin_example
 N | N^2  N^3  N^4 | sqrt(n)  sqrt[4](N) |
---+---------------+---------------------+
 1 |   1    1    1 |       1           1 |
 2 |   4    8   16 |  1.4142      1.1892 |
 3 |   9   27   81 |  1.7321      1.3161 |
#+end_example

* Rich content in fields
Fields can hold links, emphasis, code, timestamps, entities and non-ASCII
text:

- Links are aligned by what you *see*: while link brackets are concealed
  (=ui.conceal_links=, the default), =[[https://orgmode.org][Org]]= counts
  as 3 characters wide. That is why the raw text of a row with links looks
  misaligned with =:set conceallevel=0=, and fine with the default.
- Emphasis markers (=*bold*=, =/italic/=, ~=code=~) count as characters.
- Wide characters (CJK, emoji) count as two columns, accented letters as
  one.
- A literal =|= cannot be typed into a field (it would split it); write
  =\vert{}= instead, which exports as =|=.

#+NAME: rich
| What      | Example                              |
|-----------+--------------------------------------|
| link      | [[https://orgmode.org][Org]]                                  |
| bare link | [[https://neovim.io]]                    |
| markup    | *bold*, /italic/, =verbatim=, ~code~ |
| date      | <2026-12-24 Thu>                     |
| entity    | \alpha + \beta, 30\deg               |
| unicode   | José, Zürich, 東京                   |
| pipe      | a \vert{} b                          |

*Try:* =<C-c><C-c>= in the table.

*Expect:* no change: the table is already aligned as org.nvim aligns it
(the "link" rows look short in the file text, but line up on screen).

*Try:* cursor on "24" in the date, =<S-Up>=.

*Expect:* the date becomes =<2026-12-25 Fri>= (on a timestamp the
=<S-arrows>= change the date; they do not swap fields). =u= to undo.

* Exporting a table to a file: =:Org table_export=
=:Org table_export= writes the table under the cursor to a file with a
*translator*: =orgtbl-to-tsv=, =orgtbl-to-csv=, =orgtbl-to-latex=,
=orgtbl-to-html=, =orgtbl-to-texinfo=, =orgtbl-to-orgtbl=,
=orgtbl-to-generic= (plus parameters, e.g. =orgtbl-to-latex :splice t=).
It asks for the file name, then for the format, suggesting the one matching
the file extension (=.csv= → =orgtbl-to-csv=), else
=table_export_default_format= (=orgtbl-to-tsv=). Hlines are dropped in
CSV/TSV.

The file name and the format can instead come from the properties
=TABLE_EXPORT_FILE= and =TABLE_EXPORT_FORMAT= of the entry (inherited from
parents): then there is no question at all.

* table.el tables
Emacs has a second table package, table.el, whose tables are grids of =+=,
=-= and =|= in which a cell can span several rows or columns and hold
several lines. Org files may contain them. org.nvim recognises them, leaves
them alone for the normal table commands, and offers:

- =<C-c>~= on an Org table: convert it to a table.el table (after a
  confirmation). Hlines are dropped and every row gets a border.
- =<C-c>~= on a table.el table: convert it back to an Org table (the border
  lines are removed; spanned and multi-line cells are split, as in Emacs).
- =<C-c>~= elsewhere: insert a new table.el table after asking for the
  number of columns and rows and the cell widths and heights.
- =<C-c>'= on a table.el table: edit it in a separate buffer where the grid
  is realigned when you leave Insert mode; =<C-c><C-c>= writes it back,
  =<C-c><C-k>= aborts.
- =<Tab>= and =<C-c><C-c>= on a table.el table only print a hint.
