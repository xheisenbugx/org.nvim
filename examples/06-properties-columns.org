* How to use this file
Properties are key/value pairs attached to an entry, stored in a
=:PROPERTIES:= drawer right below the headline. Column view shows the
entries of a subtree as a table of their properties, with totals and other
summaries computed over the children. This file walks through both, with
exercises you can check.

Start Neovim from the root of the repository with the bundled init file:

#+begin_src sh :eval no
nvim -u examples/minimal_init.lua examples/06-properties-columns.org
#+end_src

=examples/minimal_init.lua= makes =<leader>= the =<Space>= key, so
=<prefix>= (the default =<leader>o=) is =<Space>o=, and lists all
=examples/*.org= files as agenda files. It keeps the default
=use_property_inheritance = false=.

- The file opens folded. =<Tab>= on a heading opens it, =<S-Tab>= cycles
  the whole buffer. =<Tab>= on a =:PROPERTIES:= line folds the drawer.
- =u= undoes anything; =git checkout examples/06-properties-columns.org=
  restores the original file. Opening column view can write computed
  totals into the file (see [[*Summaries are written back]]): that is
  expected, =u= undoes it too.
- =g?= lists every key of the buffer; the usual Emacs keys work as well.
- *Try:* marks an exercise, *Expect:* says exactly what you should see.
- Lines starting with =#= and a space are Org comments: notes for you.

Options that only exist in Lua are shown as small =lua= source blocks:
put the cursor in the block, press =<C-c><C-c>= and answer =y=. They run
inside Neovim and last until you quit.

** The settings of this file
#+begin_example
#+PROPERTY: Effort_ALL 0:15 0:30 1:00 2:00 4:00
#+PROPERTY: Owner_ALL Alice Bob Carol
#+PROPERTY: Status_ALL "Not started" "In progress" Done
#+PROPERTY: Team platform
#+COLUMNS: %30ITEM %TODO %3PRIORITY %Owner %Effort{:} %TAGS
#+end_example

- The =_ALL= lines list the allowed values of =Effort=, =Owner= and
  =Status=; values with spaces are quoted.
- =#+PROPERTY: Team platform= gives every entry of the file the property
  =Team= (as a default that entries inherit).
- =#+COLUMNS:= is the default layout of column view in this file.

* Property drawers
** Syntax
The drawer comes right after the headline (and after its =SCHEDULED:= /
=DEADLINE:= line, if any), starts with =:PROPERTIES:= and ends with
=:END:=. Each line is =:NAME: value=. Names are case insensitive
(=:owner:= and =:Owner:= are the same property) and can't contain spaces;
a value may be empty.

*** A task with properties
:PROPERTIES:
:Owner:    Alice
:Status:   In progress
:Effort:   1:00
:Room:     4.12
:END:
# Four properties. Press <Tab> on the :PROPERTIES: line to fold them.

*** A task with a date and properties
SCHEDULED: <2026-10-05 Mon>
:PROPERTIES:
:Owner:    Bob
:END:
# The drawer follows the SCHEDULED line; that is still "right below".

*** Not a property drawer
Some text first.
:PROPERTIES:
:Owner:    Nobody
:END:
# Text before it: this is an ordinary drawer, not the entry's properties.
# :Org lint reports it ("obsolete-properties-drawer").

** Properties of the whole file
Properties for every entry of the file come from =#+PROPERTY: NAME value=
lines (this file has =Team=, and the =_ALL= lists), from a property
drawer at the very top of the file (before any other line except
comments), or from =global_properties= in your config. They act as
defaults: an entry gets them when it looks them up with inheritance.

#+begin_example
:PROPERTIES:
:Client:   Initech
:END:
#+TITLE: A file whose first lines are a property drawer
#+end_example

* Setting and deleting properties
** <prefix>p: set a property
=<prefix>p= (Emacs =<C-c><C-x>p=) asks for the property name, with
completion of the names used in this buffer and the agenda files, then
for the value. When the property has allowed values (=Owner_ALL=,
=Status_ALL=, ...) you pick one from a list; otherwise you type it, with
completion of the values already used. The drawer is created when needed
and every line is written as =:NAME:= padded to 10 characters, then the
value (=property_format= ="%-10s %s"=).

* Allowed values
** _ALL lists and S-Right / S-Left
A property =NAME_ALL= lists the values allowed for =NAME=. It can be set
for the file (=#+PROPERTY: Owner_ALL Alice Bob Carol=) or in a drawer, in
which case it applies to that subtree (=_ALL= is always inherited). Values
with spaces are written in double quotes.

With the cursor on a property line, =<S-Right>= / =<S-Left>= switch to the
next / previous allowed value, wrapping around at the end. =<prefix>p=,
=<prefix>xe= and the =s= of =<C-c><C-c>= offer these values as a list.

* Inheritance
** Most properties are not inherited by default

only to the entry that has it: a search for =Client="ACME"= finds the
entry with the drawer, not its children. Some properties are always
looked up in the parents: =CATEGORY=, =COLUMNS=, =LOGGING=,
=LOG_INTO_DRAWER=, =ARCHIVE=, the =_ALL= lists and a few others that
Org itself uses.

** Overriding and appending (NAME+)
A child's own value replaces the inherited one. =:NAME+: value= appends to
the inherited value (or to an earlier line of the same drawer) with a
space in between; =#+PROPERTY: NAME+ value= appends at file level.

* Special properties
Some property names are computed from the entry instead of read from the
drawer. They can be used in searches and in column view:

| Name           | Value                                             |
|----------------+---------------------------------------------------|
| =ITEM=         | the headline text (no keyword, priority or tags)  |
| =TODO=         | the TODO keyword                                  |
| =PRIORITY=     | the priority letter (=B= when there is no cookie) |
| =TAGS=         | the entry's own tags, like =:work:urgent:=        |
| =ALLTAGS=      | own and inherited tags                            |
| =CATEGORY=     | the category (property, =#+CATEGORY=, file name)  |
| =LEVEL=        | the number of stars (in searches)                 |
| =FILE=         | the file name                                     |
| =SCHEDULED=    | the =SCHEDULED:= timestamp                        |
| =DEADLINE=     | the =DEADLINE:= timestamp                         |
| =CLOSED=       | the =CLOSED:= timestamp                           |
| =TIMESTAMP=    | the first active timestamp in the entry           |
| =TIMESTAMP_IA= | the first inactive timestamp in the entry         |
| =CLOCKSUM=     | the time clocked in the subtree                   |
| =CLOCKSUM_T=   | the time clocked today                            |
| =BLOCKED=      | =t= when the entry can't be marked DONE yet       |

Don't put special names in a drawer: they are ignored there and
=:Org lint= reports them.

* Searching by property
Properties can be used in match strings: in sparse trees
(=<prefix>/ m=, =<C-c>\=), in the agenda (=<prefix>a m=) and in custom
agenda commands. =<prefix>/ p= is a shortcut that asks for =NAME=value=
and adds the quotes.

| Match               | Finds entries whose ...                          |
|---------------------+--------------------------------------------------|
| =Owner="Alice"=     | Owner is exactly Alice                           |
| =Owner<>"Alice"=    | Owner is not Alice (missing counts as different) |
| =Effort>1=          | Effort is more than 1 (see below)                |
| =Effort<*2=         | Effort exists and is less than 2 hours           |
| =Status={progress}= | Status matches the regexp =progress=             |
| =PRIORITY="A"=      | priority is A                                    |
| =LEVEL=4=           | are at level 4                                   |
| =TODO="DONE"=       | keyword is DONE                                  |
| =+Owner="Bob"/TODO= | Owner is Bob and keyword TODO                    |
| =DEADLINE<"<+1w>"=  | deadline is less than one week away              |

Numbers compare as numbers, a missing property is =0= for numbers and
=""= for strings. The starred operators (=<*=, =>*=, ...) only match
entries that have the property. Like Emacs, a value is read as a number
up to the first character that isn't part of one: =1:30= is =1=, =90min=
is =90=, =1d= is =1=. So =Effort>1= works for =H:MM= values but not for
mixed units.

* Column view
** Opening and leaving column view
=<prefix>C= (Emacs =<C-c><C-x><C-c>=) turns the headlines of the current
subtree into rows of a table: each column shows a property, the column
titles go into the window bar at the top. The text of the file does not
change; body lines stay visible between the rows. =q= leaves the view.

Which entries and which columns:
- the format comes from the nearest =COLUMNS= property of the entry or
  its parents, else from =#+COLUMNS:= (here
  =%30ITEM %TODO %3PRIORITY %Owner %Effort{:} %TAGS=), else from
  =columns_default_format=;
- with a =COLUMNS= property, the view covers the subtree that has it;
  otherwise the subtree at the cursor (the whole file when the cursor is
  before the first heading);
- =1<prefix>C= always shows the whole file with the file format.

** The format: %[width]PROPERTY[(title)][{summary}]
Each column is =%= followed by an optional width, the property name, an
optional title in parentheses and an optional summary operator in
braces: =%25ITEM= is the headline, 25 characters wide;
=%Effort(Time){:}= shows =Effort= under the title =Time= and sums it as
durations. A format after =;= in the braces (=%Cost{+;%.2f}=) is applied
to every value of the column.

** Keys in column view
| Key                    | Action                                     |
|------------------------+--------------------------------------------|
| =e=                    | edit the value (also TODO, tags, dates)    |
| =n= =p=                | next / previous allowed value              |
| =<S-Right>= =<S-Left>= | same as =n= / =p=                          |
| =1= .. =9=             | pick the N-th allowed value                |
| =a=                    | edit the allowed values (=NAME_ALL=)       |
| =v=                    | show the full value                        |
| =<C-c><C-c>=           | toggle a checkbox value (else quit)        |
| =<C-c><C-t>=           | change the TODO state                      |
| =<C-c><C-o>=           | open the link in the field                 |
| =h= =l=                | previous / next column (also arrow keys)   |
| =<= =>=                | narrow / widen the column                  |
| =<M-h>= =<M-l>=        | move the column left / right               |
| =<M-L>= =<M-H>=        | add a column / delete the column           |
| =s=                    | edit the column (property, title, summary) |
| =<M-k>= =<M-j>=        | move the entry up / down                   |
| =c= =o=                | contents / overview visibility             |
| =r= =g=                | recompute                                  |
| =q=                    | quit                                       |

Changes to the layout (width, order, new columns) are saved back to the
=COLUMNS= property or the =#+COLUMNS:= line the view comes from.

* Summary operators
A summary operator in braces computes a value for every entry with
children, from the values of its children (and their children, bottom
up). The entry's own value is not added: a parent shows the summary of
its children. Each subtree below has its own =COLUMNS= property; press
=<prefix>C= on its first heading to see the numbers of the *Expect:*
lines.

** Numbers: {+} {$} {min} {max} {mean}
| Operator   | Result                                        |
|------------+-----------------------------------------------|
| ={+}=      | sum (=6=, =19.5=: printed like Emacs)         |
| ={+;%.1f}= | sum, every value with one decimal             |
| ={$}=      | sum with two decimals (money)                 |
| ={min}=    | smallest value                                |
| ={max}=    | largest value                                 |
| ={mean}=   | arithmetic mean (always shown with a decimal) |

*** Books to buy
:PROPERTIES:
:COLUMNS:  %20ITEM %Pages{+} %Price{$} %Rating(Low){min} %Rating(Avg){mean} %Rating(High){max}
:END:
*Try:* on "Books to buy" press =<prefix>C=.
*Expect:*
#+begin_example
ITEM            | Pages | Price | Low | Avg | High
Books to buy    | 1363  | 29.49 | 3   | 4.0 | 5
  Dune          | 612   | 9.99  | 5   | 5   | 5
  Neuromancer   | 271   | 7.5   | 4   | 4   | 4
  Snow Crash    | 480   | 12    | 3   | 3   | 3
#+end_example
- =Pages{+}=: 612 + 271 + 480 = 1363;
- =Price{$}=: 9.99 + 7.5 + 12 = =29.49=, always with two decimals;
- the same property =Rating= appears three times with different
  operators and titles: min =3=, mean =4.0= (a mean always has a
  decimal), max =5=. Leaves show their own value.

** Summaries are written back
Like Emacs, opening column view (or updating a =columnview= block) writes
each computed summary into the entry's own property *when the entry
already has that property*, even an empty one, and its value differs.
This keeps totals in the file up to date.

** Your own summary operator

  count = function(values) return tostring(#values) end,
}

* Column view as a table (columnview dynamic block)
A =columnview= dynamic block writes the column view into the file as an
Org table that you can export or use in formulas. =<C-c><C-x>i= inserts
one; =<C-c><C-c>= on the =#+BEGIN:= line (or =<prefix>xu=) updates it.
Parameters: =:id local= (this subtree), =global= (the whole file), =file:path=
or an =ID=; =:maxlevel N=; =:hlines N=; =:indent t=; =:skip-empty-rows t=;
=:match "tags"=; =:exclude-tags (a b)=; =:format "..."=. See
=18-dynamic-blocks.org= for everything about dynamic blocks.

*** Offsite budget
:PROPERTIES:
:COLUMNS:  %20ITEM %Owner %Cost{+}
:END:
#+BEGIN: columnview :id local :indent t
#+END:
*Try:* put the cursor on the =#+BEGIN:= line and press =<C-c><C-c>=.
*Expect:* the block is filled with:
#+begin_example
| <20>           |       |      |
| ITEM           | Owner | Cost |
|----------------+-------+------|
| Offsite budget |       | 1150 |
| \_  Catering   | Alice |  800 |
| \_  Bus        | Bob   |  350 |
#+end_example
The first row holds the width =<20>= from =%20ITEM=, and that column is
shrunk to 20 characters on screen. =\_= marks the indentation of
sub-entries (=:indent t=). Change a =Cost= and update the block again.

**** Catering
:PROPERTIES:
:Owner:    Alice
:Cost:     800
:END:
**** Bus
:PROPERTIES:
:Owner:    Bob
:Cost:     350
:END:
