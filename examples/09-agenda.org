* How to use this file
The agenda collects the dated entries and the TODO items of all your
=agenda_files= into one read-only buffer: a calendar of days, a TODO list, the
result of a tag or text search. From that buffer you can act on the entries
(change their state, reschedule them, clock in, refile ...) without visiting
the files. This file teaches every agenda view and key, with a data set whose
agenda output is written out below, line by line, so you can compare.

- The file starts folded (=#+STARTUP: overview=). Put the cursor on a heading
  and press =<Tab>= to open it; =<S-Tab>= cycles the whole buffer.
- Keys assume the default prefix: =<prefix>= means =<leader>o= (Space o with
  the bundled init file). Emacs keys such as =C-c a= work too
  (=:h org-emacs-keys=).
- =g?= lists the keys of the current buffer: in an org buffer the org keys,
  in the agenda the agenda keys.
- Nothing breaks if you make a mess: =u= in this buffer undoes, and
  =git checkout examples/09-agenda.org= restores the file. Edits made from the
  agenda change this buffer but do not save it; quit with =:qa!= to throw
  them away.
- Lines starting with *Try:* are exercises. *Expect:* says what you should
  see, for the file as it is in git: after changing entries, the agenda
  changes too. =git checkout examples/09-agenda.org= (then =:e!=) resets it.
- Lines starting with =# = are Org comments that annotate the examples.

Start Neovim from the repository root with the bundled init file:

#+begin_src sh :eval no
nvim -u examples/minimal_init.lua examples/09-agenda.org
#+end_src

=examples/minimal_init.lua= sets =agenda_files= to *every* =.org= file of
=examples/= (plus the capture scratch directory), defines the custom agenda
commands =w= and =u=, turns on =enforce_todo_dependencies=, and says that a
project is a heading tagged =:project:= (=agenda.stuck_projects=).

Because all the example files are agenda files, a plain agenda mixes the
entries of every file. *Restrict the agenda to this file* (next section):
press =<prefix>a=, then =<=, then the view key. The expected output in this
file assumes you did.

Today, in this file, is *Monday 2026-09-28*. On another day the "In N d."
counts and the "today" lines differ: the time grid, the =Sched.= and =In N
d.= lines and the habit graph are always drawn for the real today.

* Opening the agenda
** The dispatcher
=<prefix>a= (Emacs =C-c a=) opens a menu, the dispatcher. Press one key to
pick a view:

| Key     | View                                                    |
|---------+---------------------------------------------------------|
| =a=     | the agenda: a week of days (=agenda.span=)              |
| =t=     | every open TODO entry                                   |
| =T=     | TODO entries with the keywords you type (=WAITING=)     |
| =m=     | a tags / property match                                 |
| =M=     | a match, TODO entries only                              |
| =s=     | search for words or a regexp                            |
| =S=     | search, TODO entries only                               |
| =n=     | the agenda and all TODOs, one after the other           |
| =#=     | stuck projects                                          |
| =/=     | a regexp in all agenda files, into the quickfix list    |
| =<=     | restrict to the current file; again: current subtree    |
| =>=     | remove the restriction (and the restriction lock)       |
| =e=     | write the views of custom commands with =export_files=  |
| =*=     | toggle sticky agenda buffers                            |
| =?=     | the =:FLAGGED:= entries of MobileOrg                    |
| =w= =u= | custom commands (here from =examples/minimal_init.lua=) |

=<Esc>= closes the menu without doing anything. In the agenda =q=
quits and =g?= lists every agenda key.

** Restricting to this file
=<= in the dispatcher restricts the next view to the current buffer. The
label next to =<= shows the state: =[buffer]=. Press =<= a second time to
restrict to the subtree at the cursor (=[subtree]=), a third time to remove
the restriction. The restriction applies to every view, custom commands
included, and stays while you move around in the agenda (=f=, =b=, =r=).

*Expect:* a week agenda with lines from many files: the category column on
the left shows =agenda:=, =tutorial:= and the categories of the other example
files. Press =q=.

*Expect:* only the categories =agenda:= and =holiday:= (the holidays of this
file, see below). Compare with [[*The week at a glance][The week at a glance]].

*Try:* put the cursor on the heading "Tasks without dates" below, press
=<prefix>a=, =<=, =<= (the label says =[subtree]=) and =t=.
*Expect:* a TODO list with only the six open tasks of that subtree, from
"Fix the production outage" to "Clean the garage".

Another way to see only this file's entries is a category filter: in any
agenda, put the cursor on a line starting with =agenda:= and press =<= (in
the agenda buffer, =<= keeps only the category at point). This file's
category is =agenda= (=#+CATEGORY:= at the top); the Holidays subtree has its
own category =holiday= and disappears with that filter.

* What shows up in the agenda
Everything below this heading is the data set of the date agenda. Each

|   Mon |   Tue |   Wed |   Thu |   Fri |   Sat |   Sun |

** Scheduled entries
=SCHEDULED:= says when you plan to *start* working on an entry. It shows on
its day with the leader =Scheduled:=, and, while it is not done, every later
day in *today's* agenda as =Sched. Nx:= (scheduled N days ago). A time in the
timestamp puts it in the time grid. A delay (=-2d= after the date) hides the
entry until the delay is over.

# Scheduled today, no time: "Scheduled:" in Monday's list.
*** TODO Call the plumber                                              :home:
SCHEDULED: <2026-09-28 Mon>
The kitchen tap drips.
Ask about the boiler as well.
# Scheduled today at 09:30: in the time grid (and a clock line for log mode).
*** TODO Team standup                                                  :work:
SCHEDULED: <2026-09-28 Mon 09:30>
:LOGBOOK:
CLOCK: [2026-09-28 Mon 09:30]--[2026-09-28 Mon 09:45] =>  0:15
:END:
# Scheduled last Friday: today it says "Sched. 3x:".
*** TODO Return the library books                                    :errand:
SCHEDULED: <2026-09-25 Fri>
# Scheduled Thursday with a 2-day delay: shown since Saturday, "Sched. 4x:".
*** TODO Clean the gutters                                             :home:
SCHEDULED: <2026-09-24 Thu -2d>
# Scheduled Sunday with a 3-day delay: hidden until Wednesday.
*** TODO Draft the newsletter                                          :work:
SCHEDULED: <2026-09-27 Sun -3d>
# Done entries still show on their day, but never as "Sched. Nx:".
*** DONE Pay the electricity bill                                      :home:
CLOSED: [2026-09-28 Mon 08:05] SCHEDULED: <2026-09-28 Mon>

** Deadlines
=DEADLINE:= says when an entry is *due*. It shows on its day as =Deadline:=,
and in today's agenda from =deadline_warning_days= (14) days before as =In
N d.:=, and after the date as =N d. ago:= until it is done. A warning period
in the timestamp (=-30d=) replaces the 14 days for that entry.

# Due Friday: "In 4 d.:" today, "Deadline:" on Friday.
*** TODO Renew the passport                                            :home:
DEADLINE: <2026-10-02 Fri>
Photos are in the top drawer. Bring the old passport.
# Due in 22 days but warns 30 days ahead: "In 22 d.:" today.
*** TODO Submit the grant report                                       :work:
DEADLINE: <2026-10-20 Tue -30d>
# Due in 32 days, beyond the 14-day warning: only on its own day, Oct 30.
*** TODO File the insurance claim                                      :home:
DEADLINE: <2026-10-30 Fri>
# Missed last Thursday: "4 d. ago:" today.
*** TODO Send the birthday card                                      :errand:
DEADLINE: <2026-09-24 Thu>
# Both: "In 7 d.:" today, "Scheduled:" Wednesday, "Deadline:" next Monday.
*** TODO Book the venue                                                :work:
DEADLINE: <2026-10-05 Mon> SCHEDULED: <2026-09-30 Wed>

** Timestamps and ranges
A plain active timestamp (angle brackets) anywhere in an entry makes it an
appointment on that day. A time goes to the time column, a time range too. A
date range (two timestamps joined by =--=) shows on every day of the range
with =(i/n):=. A time of day written in the headline is used when the
timestamp has none, and is removed from the text. Inactive timestamps
(square brackets) never show, unless you press =v[= in the agenda.

# Tuesday 12:30-13:30 in the time column.
*** Lunch with Sam
<2026-09-29 Tue 12:30-13:30>
At the noodle bar on Main Street.
# The time comes from the headline: Wednesday "14:00 ... Dentist".
*** 14:00 Dentist
<2026-09-30 Wed>
# Three days: (1/3) Thursday, (2/3) Friday, (3/3) Saturday.
*** Conference                                                         :work:
<2026-10-01 Thu>--<2026-10-03 Sat>
The slides are on the laptop. Remember the power adapter.
# Across midnight: (1/2) Sunday at 22:00, (2/2) Monday at 6:30.
*** Night train
<2026-10-04 Sun 22:00>--<2026-10-05 Mon 06:30>
# Two timestamps: one line on Tuesday and one on Thursday.
*** Piano lessons
<2026-09-29 Tue 17:00> <2026-10-01 Thu 17:00>
# Inactive: hidden, except with v[ (Tuesday, leader "[").
*** Idea about the garden
[2026-09-29 Tue]

** Repeaters
A repeater (=+2d=, =+1w=, =+1m=, =++1w=, =.+1d=) makes a timestamp recur.
The agenda shows every occurrence, also in the future
(=agenda.show_future_repeats=). Marking a repeating TODO done moves its date
to the next occurrence instead of closing it.

# Every other day: Mon, Wed, Fri, Sun, ...
*** Water the plants                                                   :home:
<2026-09-28 Mon +2d>
# Every Friday at 16:00.
*** TODO Weekly review                                                 :work:
SCHEDULED: <2026-10-02 Fri 16:00 +1w>
# Due on the 1st of every month: "In 3 d.:" today, "Deadline:" Thursday.
*** TODO Pay the rent                                                  :home:
DEADLINE: <2026-10-01 Thu +1m>

** Habits
A TODO with =:STYLE: habit= and a repeating =SCHEDULED:= is a habit. It shows
in today's agenda only, with a consistency graph from column 40 of the line:
one character per day, the 21 days before today, today, and 7 days after.
=*= is a day it was done (from the state changes in its log), =!= is today,
and the colours show whether it was on time (blue: too early, green: on
time, yellow: last chance, red: overdue).

# Graph today: "* ** **!" -- done Mon 21, Wed 23, Thu 24, Sat 26, Sun 27.
*** TODO Stretch                                                      :habit:
SCHEDULED: <2026-09-28 Mon .+1d>
:PROPERTIES:
:STYLE:    habit
:LAST_REPEAT: [2026-09-27 Sun 07:10]
:END:
:LOGBOOK:
- State "DONE"       from "TODO"       [2026-09-27 Sun 07:10]
- State "DONE"       from "TODO"       [2026-09-26 Sat 07:30]
- State "DONE"       from "TODO"       [2026-09-24 Thu 07:05]
- State "DONE"       from "TODO"       [2026-09-23 Wed 07:00]
- State "DONE"       from "TODO"       [2026-09-21 Mon 07:15]
:END:

** Diary sexps
Emacs diary s-expressions compute dates: a timestamp whose date is =%%=
followed by a sexp, or a line of its own starting with =%%= and the sexp at
column 0 (the rest of the line is the text). org.nvim evaluates the common
calendar functions without Emacs (=:h org-agenda-diary-sexp=).

# diary-float t 4 1 = the first Thursday of every month: Thu 2026-10-01.
*** Book club
<%%(diary-float t 4 1)>
# Born 1990-10-02: Friday shows "Ana turns 36".
*** Birthdays
%%(org-anniversary 1990 10 2) Ana turns %d
# Every Tuesday (2) from 2026-09-01 to 2026-12-18.
*** Evening class
<%%(org-class 2026 9 1 2026 12 18 2)>
# Mon, Wed and Fri at 18:00: the string result becomes the line.
*** Gym
%%(when (memq (calendar-day-of-week date) '(1 3 5)) "18:00 Gym")

* Tasks without dates
TODO entries without a date never show in the date agenda, only in the TODO
list and in matches. Their priorities, efforts and the =CLIENT= property are
used by the sorting, filter and match examples.

* The week at a glance

an 80-column window. A line starts with the category (=agenda:=), then the
time or the leader (=Scheduled:=, =In 4 d.:= ...), then the headline and its
tags. The tags are aligned to the right edge of the window, so they move
with your window width. The =┄┄┄┄┄= lines are the time grid, drawn in
today's agenda only; the =← now= line sits at the current time (written
=HH:MM= here). Within a day, timed entries come first, then the others by
urgency.

| Key          | Does                                                     |
|--------------+----------------------------------------------------------|
| =<CR>=       | open the entry in this window                            |
| =<Tab>=      | open the entry in another window                         |
| =<Space>=    | show the entry in the other window, keep the cursor here |

* Filters
Filters hide lines without rebuilding the view. They show in the window bar
(the top line of the window). =|= removes all of them.

| Key     | Filter                                                     |
|---------+------------------------------------------------------------|
| =/=     | combined: =+work-urgent=, =<0:30=, =/regexp/=, a category  |
| =\=     | one tag, by its key from =#+TAGS=                          |
| =<=     | the category of the line at point (again: off)             |
| ~=~     | an Emacs regexp on the text (again: off)                   |
| =_=     | effort: =<=, =>= or ~=~, then a digit                      |
| =^=     | the entries under the same top-level heading               |
| =<Bar>= | remove all filters (=<Bar>= is Vim's name for the bar key) |

A count changes a filter: =1\= (Emacs =C-u \=) *excludes* the tag, =2/= adds
to the current filters. In =/=, =+tag= and =-tag= keep or hide a tag (or a
category), =<1:00= keeps efforts of at most one hour, =>1:00= at least, and
=/text/= is a regexp. After =\=, =<Space>= means "any tag", =?= "no tag"
and =.= "the tags of this line".

The =_= digits pick a value of the global =Effort_ALL= list
=0 0:10 0:30 1:00 2:00 3:00 4:00 5:00 6:00 7:00= (1 is =0=, 2 is =0:10=, 3
is =0:30=, ...), not the =#+PROPERTY:= of this file. Entries without an
effort count as infinitely long.

* More dispatcher entries
- =n=: the agenda and the TODO list in one buffer (two blocks).
- =/=: a regexp searched in every line of every agenda file, into the
  quickfix list (=:copen=, =:cnext=). Not restricted by =<=.
- =*=: sticky agenda buffers: each view keeps its own buffer
  (=org://agenda(KEY)=) and is shown as it was when you open it again (=r=
  refreshes it).
- =A= inside an agenda appends another view to the current buffer.

*Try:* =<prefix>a /= and type =kumquat= =<CR>=.
*Expect:* the quickfix window with the lines that contain "kumquat": in this
file the headline, the search examples ..., and lines of any other example
file that mentions it.

*Try:* =<prefix>a <= n=.
*Expect:* the week agenda, a separator line of =─=, then the TODO list of this
file. =<C-Down>= / =<C-Up>= jump between the two blocks.

* Custom commands
Custom commands combine views and options under a key of the dispatcher.
=examples/minimal_init.lua= defines two:

#+begin_src lua :eval no
agenda = {
  custom_commands = {
    -- a block agenda: three views in one buffer
    w = {
      description = "Work overview",
      types = {
        { type = "agenda", span = "day", header = "Today" },
        { type = "tags_todo", match = "+work/!", header = "Open work tasks" },
        { type = "todo", match = "WAITING", header = "Waiting for" },
      },
    },
    -- a single tags view
    u = { description = "Urgent", type = "tags", match = 'PRIORITY="A"|+urgent' },
  },
}
#+end_src

*Try:* =<prefix>a <= u=.

More options for your own config (=:h org-agenda-custom-commands=):

#+begin_src lua :eval no
agenda = {
  custom_commands = {
    p = "Personal",                     -- a group: press p, then a key
    pa = {
      description = "Three days, home only",
      type = "agenda",
      span = 3,
      start_day = "-1",                 -- start yesterday
      tag_filter_preset = { "+home" },  -- a filter that stays on
    },
    pn = { description = "NEXT actions", type = "todo", match = "NEXT" },
    ps = { description = "Garden notes", type = "search", match = "garden" },
    pt = { description = "Work tree", type = "tags-tree", match = "+work" },
    r = {
      description = "Review",
      types = {
        { type = "agenda", span = "week", header = "This week" },
        { type = "stuck", header = "Stuck" },
        {
          type = "todo",
          header = "Unscheduled",
          skip = require("org.agenda").skip_entry_if("scheduled", "deadline"),
        },
      },
      settings = { prefix_format = " %-10:c %s" },
      export_files = { "~/review.html", "~/review.txt" },
    },
  },
}
#+end_src

- =types= (or =blocks=) makes a block agenda; =type= a single view. Types:
  =agenda=, =todo=, =tags=, =tags_todo=, =search=, =stuck=, and the sparse
  trees =tags-tree=, =todo-tree=, =occur-tree= of the current buffer.
- =skip= hides entries; =require("org.agenda").skip_entry_if= and
  =skip_subtree_if= take conditions like Emacs's org-agenda-skip-entry-if:
  =scheduled=, =notscheduled=, =deadline=, =timestamp=, =regexp=, =todo= ...
- =settings= apply to every block; =export_files= are written by =e= in the
  dispatcher.

* The restriction lock
The dispatcher's =<= restricts one view. The restriction lock restricts
*every* agenda command until you remove it, =:Org agenda= commands included.

| Key           | Where      | Does                                      |
|---------------+------------+-------------------------------------------|
| =<C-c><C-x><= | org buffer | lock the agenda to the subtree at point   |
| =<C-c><C-x>>= | org buffer | remove the lock                           |
| =<C-c><C-x><= | agenda     | lock to the subtree of the entry at point |
| =>=           | dispatcher | remove the restriction and the lock       |

On a line before the first heading, or with a count, the lock takes the
whole file.

*Try:* put the cursor on the heading "Tasks without dates" and press
=<C-c><C-x><=.
*Expect:* the message =Agenda restricted to subtree "Tasks without dates"=.
Now =<prefix>a t= (no =<= needed) lists only the six open tasks of that
subtree, and =<prefix>a a= shows an empty week (those tasks have no dates),
only the time grid of today. Press =<C-c><C-x>>= to remove the lock.

* Exporting the agenda
=<C-x><C-w>= in the agenda writes the current view to a file; the extension
picks the format: =.txt= (the text), =.html= (with colours), =.org= (the
subtrees of the entries), =.ics= (iCalendar), =.ps= / =.pdf= (printed like
Emacs, without external programs). =:Org agenda export FILE= does the same.

*Try:* in the day agenda of this file (=<prefix>a <= a= then =vd=), press
=<C-x><C-w>= and type =/tmp/today.txt=.
*Expect:* "Plain text written to /tmp/today.txt"; the file holds the agenda
text, starting with =Day-agenda (W40):=. Try =/tmp/today.html= and
=/tmp/today.ics= as well ("iCalendar written to ...").

Custom commands with =export_files= are all written at once by =e= in the
dispatcher, or from the shell:

#+begin_src sh :eval no
nvim --headless -u examples/minimal_init.lua \
  -c "lua require('org.agenda.export').batch('a', { span = 'day' })" -c q
#+end_src
