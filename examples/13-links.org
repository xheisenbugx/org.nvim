* How to use this file
Links turn an Org file into a web of notes: a link can point to a heading of
this file, to a line of another file, to a web page, to a heading with an
=ID= wherever it lives, or to a file attached to an entry. This file shows
every link type org.nvim supports, how to follow, store and insert links,
and how IDs and attachments work. Almost every example is a real, clickable
link: press =<CR>= on it and see where you land.

- The file starts folded (=#+STARTUP: overview=). Put the cursor on a
  heading and press =<Tab>= to open it; =<S-Tab>= cycles the whole buffer.
- =<prefix>= means your org prefix, =<leader>o= by default (so =<prefix>li=
  is =<Space>oli= with the bundled init file).
- =u= undoes any edit; =git checkout examples/13-links.org= restores the
  file. The attachment exercises create files under =examples/data/=:
  remove them with =rm -rf examples/data= when you are done.
- =g?= lists every key of the buffer; =/link= in that list finds the link
  keys.
- =:Org lint= checks the file. It reports a few links here *on purpose*:
  deliberately broken ones, =id:...::search= links, a wildcard and a
  URL-encoded abbreviation. Comments next to them say so.
- Lines starting with *Try:* are exercises, *Expect:* says what you should
  see. Lines starting with =# = are Org comments: they explain the example
  next to them and are never exported.

Start Neovim from the repository root with the bundled init file, which
sets the agenda files to =examples/*.org= (the ID links below search those
files), keeps the ID database in a scratch directory and never touches your
own notes:

#+begin_src sh :eval no
nvim -u examples/minimal_init.lua examples/13-links.org
#+end_src

After following a link to another place, =<C-o>= (or =<C-c>&=) brings you
back here, so you can wander freely.

* Anatomy of a link
:PROPERTIES:
:CUSTOM_ID: anatomy
:END:
An Org link has one of three shapes:

1. A *bracket link* with a description: =[[target][description]]=. Only the
   description is shown; the target is hidden (concealed).
2. A *bracket link* without a description: =[[target]]=. The target is
   shown.
3. A *plain link*: a URL written as it is, such as =https://orgmode.org=,
   or an *angle link* like =<https://orgmode.org>=.

Examples, one per line:

# A bracket link with a description: only "the Org manual" is visible.
- [[https://orgmode.org/manual/][the Org manual]]
# A bracket link without a description: the target itself is visible.
- [[https://neovim.io]]
# A plain link: recognised on its own.
- https://neovim.io/doc/
# Balanced parentheses are part of a plain link, the final dot is not.
- https://en.wikipedia.org/wiki/Org-mode_(disambiguation).
# An angle link: the < > delimit it, so it may be followed by text.
- <https://github.com/xheisenbugx/org.nvim>and more text

A bracket link may even span two lines, like this one: [[*Following
links][the section about following links]].

** Seeing the raw text
By default org.nvim conceals the brackets and the target of described links
(the =ui.conceal_links= option, Emacs' =org-link-descriptive=). The cursor
line still shows the full text in Insert mode, and =<prefix>lt= toggles the
concealment for the whole buffer (links only: emphasis markers stay as they
are).

*Try:* press =<prefix>lt= now.

*Expect:* the first example above now reads
=[[https://orgmode.org/manual/][the Org manual]]= in full. Press
=<prefix>lt= again and it shrinks back to "the Org manual".

** What is not a link
Link syntax inside verbatim or code markup, comment lines and blocks is
not a link for Org: it is not exported as a link and =<prefix>ln= (next
link) skips it.

# Links inside verbatim or code markup are just text.
- In =verbatim [[*Anatomy of a link]]= or ~code https://x.org~ a link is text.
# Comment lines are not scanned for links either:
# [[*Anatomy of a link]] <- not a link, this line is a comment

#+begin_example
[[*Anatomy of a link]]  <- inside an example block: not a link either
#+end_example

The real link: [[*Anatomy of a link]].

*Try:* put the cursor on the heading "What is not a link" and press
=<prefix>ln=.

*Expect:* the cursor skips the three fake links and lands on the =[[= of
the real link in the line "The real link: ...". (In org.nvim, =<CR>= on
the text of a fake link still follows it.)

* Following links
:PROPERTIES:
:CUSTOM_ID: following
:END:
=<CR>=, =gx= and =<prefix>o= all run the same action, =open_at_point=
(Emacs =C-c C-o=). It opens whatever is under the cursor: a link, a
footnote reference or a timestamp (which opens the agenda for that day).

- *Web and mail* links open in the system browser / mail client
  (=vim.ui.open()=).
- *File* and *ID* links open the file in another window, splitting the
  screen when there is only one (=links.frame_setup=).
- *Internal* links (headings, targets, custom IDs) move the cursor inside
  the current buffer.

After an internal jump, =<C-o>= goes back (org.nvim records the jump in the
jumplist), and =<C-c>&= does the same like Emacs' mark ring.

* Moving between links
=<prefix>ln= and =<prefix>lp= (Emacs =C-c C-x C-n= / =C-c C-x C-p=) jump to
the next and previous link. They skip links in source and example blocks,
comments and verbatim text. A count jumps over several links, and when no
link is left, pressing the key again wraps around the buffer.

- Link three: [[#following][Following links]]
- Link four: <https://orgmode.org>

*Expect:* the cursor lands on the start of each link in turn: the =[[= of

=<= of link four. Then press =<prefix>lp= to walk back. =2<prefix>ln=
skips a link.

* Internal links
Internal links point into the current file. Their target decides what they
search for:

| Target          | Finds                                              |
|-----------------+----------------------------------------------------|
| =*Heading text= | a headline with exactly that text                  |
| =#custom-id=    | the headline whose =CUSTOM_ID= property matches    |
| =(label)=       | a coderef =(ref:label)= in a source/example block  |
| =some words=    | a =<<some words>>= target, a =#+NAME:=, a headline |

Searches ignore case and extra whitespace, and headline searches ignore the
TODO keyword, the priority, =COMMENT=, tags and statistics cookies.

- Exact title: [[*Target practice]]
- Different case and spacing: [[*target    PRACTICE]]
- With a description: [[*Target practice][jump to the practice area]]
- The heading has a TODO keyword, priority, cookie and tags, which are
  ignored: [[*Target practice][still the same heading]]

- Jump to the block named [[hello-block][the hello block]].

| Item   | Price |
|--------+-------|

*Expect:* the cursor lands on the =#+NAME: prices= line above the table.

** Coderefs =(label)=
Inside a source or example block, a line can end with =(ref:label)=. The
link =[[(label)]]= jumps to that line.

#+begin_src lua :eval no
local total = 0
for i = 1, 10 do          (ref:loop)
  total = total + i       (ref:add)
end
print(total)
#+end_src

In line [[(loop)]] we start the loop, and line [[(add)][the addition]] adds
each number.

*Try:* press =<CR>= on =(loop)= in the sentence above.

*Expect:* the cursor jumps to the line =for i = 1, 10 do (ref:loop)= in
the block.

** Links whose target is missing
When a =[[words]]= link finds no target, name or headline, org.nvim asks
"No match - create this as a new heading?" (the default of
=links.search_must_match_exact_headline=, ="query-to-create"=). Answer =y=
and the heading is added at the end of this file; answer =n= and you get
"No match for fuzzy expression: ...".

# This link has no target in this file:
# (:Org lint reports it as an unknown fuzzy location, on purpose.)
- [[A heading that does not exist yet]]

*Try:* press =<CR>= on the link above and answer =n=.

*Expect:* the message "No match for fuzzy expression: A heading that does
not exist yet". Do it again and answer =y=: a new heading
"A heading that does not exist yet" appears at the very end of the file
and the cursor is on it. Press =u= to remove it again.

* Radio targets
A radio target has *three* angle brackets: =<<<radio word>>>=. Every other
occurrence of those words in the file becomes a link to the target
automatically, with no brackets at all (and also in export). Case does not
matter, but the words must stand alone.

This paragraph defines the radio target <<<Org mode>>>. From now on, any
"org mode" in this file is a link to it.

# Each of these is a radio link, underlined like a normal link:
- Org mode is a plain-text format.
- Many people use ORG MODE for notes.
- The words may even be split over lines: Emacs Org
  mode is where the format comes from.
# Not a radio link: "org modes" is not the same word.
- "Org modes" is not a match, because "modes" is a different word.

*Try:* put the cursor on "Org mode" in the first item and press =<CR>=.

*Expect:* the cursor jumps to =<<<Org mode>>>= in the paragraph above.

* Link abbreviations =#+LINK:=
The =#+LINK:= lines at the top of this file define short prefixes:

#+begin_example
,#+LINK: gh https://github.com/%s
,#+LINK: ddg https://duckduckgo.com/?q=%h
,#+LINK: wiki https://en.wikipedia.org/wiki/
,#+LINK: ex file:./%s
#+end_example

- =%s= is replaced by the text after the colon (the "tag").
- =%h= is the same, but URL-encoded (spaces become =%20=).
- Without =%s= or =%h=, the tag is appended at the end.

# gh:  https://github.com/xheisenbugx/org.nvim
- [[gh:xheisenbugx/org.nvim][org.nvim on GitHub]]
# ddg: https://duckduckgo.com/?q=org%20mode%20tables
# (:Org lint warns about the %20 in the expanded link, like Emacs; it works.)
- [[ddg:org mode tables][search the web for "org mode tables"]]
# wiki: https://en.wikipedia.org/wiki/Org-mode
- [[wiki:Org-mode][Org mode on Wikipedia]]
# ex:  file:./14-footnotes.org::*How to use this file  (a local file!)
- [[ex:14-footnotes.org::*How to use this file][footnotes, via "ex:"]]
# A double colon works too: gh::user/repo
- [[gh::neovim/neovim][Neovim on GitHub]]

Abbreviations for every file go in =links.abbreviations= in your config:
={ gh = "https://github.com/%s" }=, or a Lua function that receives the tag.

* Storing and inserting links
The usual way to make a link is in two steps: *store* a link to where you
are (=<prefix>ls=), then *insert* it where you want it (=<prefix>li=).

** =<prefix>ls=: store a link
=<prefix>ls= works in any buffer, not only Org files. What it stores
depends on where you are:

| Where                          | Stored link                        |
|--------------------------------+------------------------------------|
| on a =<<target>>=              | =file:13-links.org::target=        |
| on a =#+NAME:= element         | =file:...::name=                   |
| on a headline with =CUSTOM_ID= | =file:...::#id= (and =::*Heading=) |
| on any headline                | =file:...::*Heading=               |
| in a Visual selection          | the selection as search text       |
| in a non-Org file              | =file:path::current line text=     |
| in a =:help= buffer            | =help:tag=                         |
| in the agenda                  | a link to the item's entry         |

With =links.use_id = true= headings are stored as =id:= links instead (and
get an =ID= property).

** =<prefix>li=: insert a link
=<prefix>li= asks for the link. The prompt completes stored links, link
types (=https:=, =file:=, =id:=, =gh:= ...) and file names. An empty answer
inserts the last stored link. Then it asks for a description, pre-filled
with the stored one: edit it, or clear it with =<C-u>= for none.

- On an existing link, =<prefix>li= *edits* it: the prompt starts with its
  target, then its description.
- In Visual mode, the selected text becomes the description.
- Stored links are removed from the list once inserted
  (=links.keep_stored_after_insertion=).
- Links to places in the same file are shortened: =file:13-links.org::*X=
  is inserted as =[[*X]]=.

* IDs
An =ID= property is a globally unique name for an entry. Links of the form
=[[id:...]]= find the entry *wherever it is*: in this file, in another
agenda file, even after you refiled it to a different file. That makes
them the most robust links to headings.

| Key                        | Action                                        |
|----------------------------+-----------------------------------------------|
| =<prefix>lI=               | give the entry an =ID= (or show its ID);      |
|                            | =4<prefix>lI= replaces it with a new one      |
| =<prefix>ly=               | copy the entry's ID, creating it              |
| =<prefix>lg=               | go to an entry by ID (IDs are completed)      |
| =:Org id_update_locations= | rebuild the ID database from the agenda files |
| =:Org id_store_link=       | store an =id:= link even without =use_id=     |

The ID database (=id.locations_file=) remembers which file holds which ID;
with the bundled init file it lives in a scratch directory. When an ID is
not where the database says, org.nvim scans the agenda files for it.

** An entry with an ID
:PROPERTIES:
:ID:       7f3c9a52-1d2e-4c6b-9a0f-13a1b2c3d4e5
:END:
This entry has an =ID=. Links to it:

- [[id:7f3c9a52-1d2e-4c6b-9a0f-13a1b2c3d4e5][this entry, by ID]]
# id:ID::search runs the search inside that entry's subtree. (:Org lint
# calls these two "Unknown ID", like Emacs' org-lint does; they work.)
- [[id:7f3c9a52-1d2e-4c6b-9a0f-13a1b2c3d4e5::*A child without an ID][its child]]
- [[id:7f3c9a52-1d2e-4c6b-9a0f-13a1b2c3d4e5::hidden spot][a target inside]]

This line holds the <<hidden spot>> the third link goes to.

*Try:* follow the three links (from here, or after moving this entry
around with =<M-j>=: IDs don't care where the entry is).

*Expect:* the first lands on the heading "An entry with an ID", the
second on its child "A child without an ID", the third on the line "This
line holds the ...".

* Attachments
An entry can have files *attached*: they live in a directory that belongs
to the entry, and =[[attachment:name]]= links refer to them by name. The
directory is:

1. the entry's =DIR= property, when it has one (relative to this file), or
2. =attach.dir= (default =data/=) plus a folder made from the entry's
   =ID=: the ID =7f3c9a52-...= gives =data/7f/3c9a52-...=.

When an entry has neither, attaching gives it an =ID=. Attaching also adds
the =ATTACH= tag and stores an =attachment:= link (=<prefix>lL= inserts it).

** The attachment menu =<prefix>A=
=<prefix>A= (=C-c C-a=) on a headline opens this menu:

| Key             | Action                                            |
|-----------------+---------------------------------------------------|
| =a=             | attach a file (=attach.method=: =cp= by default)  |
| =c= =m= =l= =y= | attach by copy / move / hard link / symbolic link |
| =u=             | download a URL into the directory (=curl=)        |
| =b=             | attach the contents of another buffer             |
| =n=             | create a new file in the directory and edit it    |
| =z=             | synchronise the =ATTACH= tag with the directory   |
| =o= / =O=       | open an attachment (system app / Neovim)          |
| =f= / =F=       | open the directory (system app / Neovim)          |
| =d= / =D=       | delete one attachment / all of them               |
| =s= / =S=       | set / remove the =DIR= property                   |

:PROPERTIES:

* Custom link types
You can add your own link types in the config, under =links.types=
(Emacs' =org-link-set-parameters=). A type is a follow function, or a table
with =follow=, =complete=, =store=, =export=, =face=,
=insert_description= and =preview=:

#+begin_src lua :eval no
require("org").setup({
  links = {
    types = {
      -- [[issue:123]] opens the GitHub issue 123 of org.nvim
      issue = function(path)
        vim.ui.open("https://github.com/xheisenbugx/org.nvim/issues/" .. path)
      end,
    },
  },
})
#+end_src

After that, =[[issue:1]]= follows with =<CR>=, is completed after =[[=,
and exports as a link. Simpler cases are better served by a =#+LINK:=
abbreviation (see [[*Link abbreviations =#+LINK:=][Link abbreviations]]).

Other hooks: =links.make_description(link, desc)= gives inserted links a
default description, =links.search_functions= handle =::search= options
first, and =links.translation_function(type, path)= rewrites links before
they are followed.

* What is not supported
- =help:= opens Vim's =:help=, not Emacs' describe-function.
- Links to Emacs applications (=gnus:=, =rmail:=, =bbdb:=, =irc:=, =eww:=,
  =w3m:=, =calendar:= ...) cannot be followed or stored.
- =elisp:= links run in a separate Emacs process, never inside Neovim, so
  commands acting on the editor fail.
- Wildcard =file:= links list the matches in a scratch buffer instead of
  Emacs' Dired.
- =::/regexp/= searches translate Emacs regexps to Vim regexps; exotic
  Emacs syntax is approximated.
See =:h org-differences= for the full list.
